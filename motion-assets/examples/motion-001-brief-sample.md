## A. 制作意图

| 项目 | 填写内容 |
| --- | --- |
| Motion ID / 名称 | Motion001 / Execution Module × Execution Behavior |
| 所属视频 / 系列 | Odyssey HOW 002 — How Odyssey Starts |
| 用途 | YouTube 讲解视频中的概念解释素材 |
| 目标观众 | 对 Agent 系统有初步认识，但不了解 Odyssey 的配置组织方式 |
| 一句话 idea | 先用横排模块与连接展示状态推进，再增加贯穿区域，形成模块与行为两个维度 |
| 看完应理解的结论 | Module / Pattern 主动推进系统状态；Behavior 贯穿执行，但不主动推进状态 |
| 必须出现的内容 | Input Guardrail、Agent、Output Guardrail，以及两个维度的名称 |
| 不能误导的事实 | Behavior 不是第四个执行节点；纵向不是独立流程；三模块箭头不是正式多 Agent Pattern 拓扑 |
| 不在本次范围内 | 真实运行演示、完整多 Agent 拓扑、其他技术概念动画 |
| 产品事实来源 | 本表明确的概念说明与现有 MVP task 中的旁白语义 |

旁白文案：

> 所以，我最早的一个想法，是尝试用二维的矩形结构，把这些配置组织起来。
>
> 横向表示不同的 Execution Module，每个 Execution Module 中用 Pattern——实际上就是拓扑结构，将不同的 Agent 串起来；
>
> 纵向表示 Execution Behavior，表示贯穿系统执行的行为。
>
> Execution Module 和 Execution Behavior 的区别在于，Execution Module（Pattern）主动推进系统状态；而 Execution Behavior 不主动推进系统状态。

关键句：最后一句对“是否推进状态”的区分。无需现在提供逐词动作设计。
