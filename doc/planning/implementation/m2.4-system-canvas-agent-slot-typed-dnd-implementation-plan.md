# Odyssey M2.4 System Canvas、Agent Slot 与 Typed DnD Implementation Plan

> Status: Batch A / Step 1 implementation complete; pending independent acceptance  
> Milestone: M2.4  
> Scope: Journey Editor 的固定 System Canvas、Pattern/Agent library、Agent Slot、typed drag/drop、context menu 与 store orchestration  
> Prerequisite: M2.1、M2.2、M2.3 accepted  
> Figma references: [`OdyJourney — Pattern Templates` (`300:33`)](https://www.figma.com/design/P3EF9io2DhyhwkNYBVqB5Z/Odyssey-Design?node-id=300-33)、[`OdyJourney — Resource Library Open` (`59:2`)](https://www.figma.com/design/P3EF9io2DhyhwkNYBVqB5Z/Odyssey-Design?node-id=59-2)  
> Authoritative guideline: [`frontend-engineering-guidelines.md`](../../frontend-engineering-guidelines.md)

## 1. 目标与完成结果

M2.4 把 M2.3 已验收的 Pattern strategies 与 commands 接入 Journey Editor，但不在组件、drag handler 或 store 中复制领域规则：

```text
Browser / keyboard event
→ validated OdysseyDragPayload or typed click intent
→ InteractionState transition
→ evaluatePatternDrop(payload, target, snapshot)
→ PatternDropAction | PatternDropRejection
→ Journey store action
→ M2.3 command
→ new PatternConfig | PatternDomainError
→ deriveSystemCanvasViewModel(document)
→ presentational components
```

完成后，用户可以在固定 System Canvas 上完成：

- 查看四种 built-in Pattern template；
- 查看由当前 `PatternConfig` 派生的 Slot 与 Route；
- 点击空 Slot 创建具有最小 `Start → End` workflow 的 Agent；
- 把通过 `Save as Template` 产生的真实 Agent Template 实例化到空 Slot；
- 在 Slot 间 move 或 exchange Agent；
- 对 Linear Slot 执行明确的 reorder；
- 通过 context menu select、unassign、replace、duplicate 或 open-workflow intent；
- 在拖拽前、拖拽中和失败后获得稳定、可访问的反馈；
- 使用点击/键盘替代路径完成核心操作。

M2.4 不把 System Canvas 实现为 Vue Flow，不保存 Slot 坐标，也不实现 M2.5 的 Workflow Preview 内容。

## 2. 已确认的事实来源与边界

### 2.1 M2.3 handoff

M2.4 直接消费：

- `PATTERN_DEFINITIONS` 与 `PATTERN_STRATEGIES`；
- `instantiatePattern`；
- `derivePatternPresentation`；
- `assignAgent`、`moveAgent`、`exchangeAgents`、`unassignAgent`、`reorderSlot`；
- Slot add/remove commands 和 supported-operation capability；
- `duplicateAgentAggregate` 及其 typed failure；
- Journey store 中已经存在的薄 Pattern actions。

M2.4 不得：

- 在 UI 中重新推导 routes、topology roles 或 operation support；
- 直接写 `document.pattern.slots`；
- 以 DOM order、像素坐标或显示名作为 identity；
- 用 drag source/target 的 CSS class 猜测业务动作。

### 2.2 Figma 结论

Figma `300:33` 的 1440×900 desktop reference 提供以下 presentation intent：

- 204 px global navigation 与顶部 product tabs 继续复用 M2.2 App Shell；
- 页面主体包含约 300 px library 与约 860 px System Canvas；
- System Canvas 包含 Input Guardrail、Execution module、Output Guardrail、Execution Behavior；
- Agent Slots 位于 Execution module 内，configured 与 empty 有不同状态；
- Pattern library 包含 Hub & spoke、Diamond loop、Linear sequence、Solo component；
- context menu 提供 Open workflow、Replace agent、Duplicate、Remove agent；
- Workflow Preview 位于右下角，但其行为和内容属于 M2.5。

Figma 的绝对坐标、示例 Agent、card layer 和 React/Tailwind reference 不是领域 contract。实现使用 Vue、现有 CSS variables 和项目组件结构，不引入 Tailwind。

## 3. 开始编码前的 Decision Gate

> Decision status: Accepted by product owner on 2026-08-13. Agent Templates are created only through `Save as Template`; no mock Template records are permitted.

### 3.1 推荐默认决策

1. **DnD transport**：M2.4 desktop proof 使用 HTML Drag and Drop；所有 `dataTransfer` 输入必须经过 versioned runtime parser。核心操作同时提供 click/keyboard 路径。
2. **Payload namespaces**：至少区分 `pattern-template`、`agent-template`、`assigned-agent`、`pattern-slot`；未来的 `workflow-node-template` 与 `resource` 预留在同一顶层 union，但不在 M2.4 执行业务动作。
3. **Agent source（Accepted）**：Agent Template 只能由已创建 Agent 的显式 `Save as Template` 产生。M2.4 不提供 mock Agent Templates，也不把 Journey Agent summary 冒充 Template；没有已保存模板时，Agent Template library 显示真实 empty state。
4. **Create Agent（Accepted）**：点击空 Slot 打开最小创建表单。确认后必须以一个原子 application/repository operation 创建 Agent identity、最小 `Start → End` WorkflowGraph/Layout、Journey Agent summary 和 Slot assignment；取消或失败不得留下 orphan Agent。
5. **Save as Template（Accepted）**：从已有 Agent aggregate 创建新的独立 private Agent Template snapshot；完整复制 WorkflowGraph、CanvasLayout、Variables、Reusable Tools 和 owned Tool instances，保留 Knowledge Space 等 external references，不保存 runtime values/secrets，也不与源 Agent 建立 live link。
6. **Template instantiation（Accepted）**：`agent-template → empty Slot` 深拷贝 template snapshot，remap 全部 owned IDs，并原子创建/分配一个新 Agent instance；同一 Template 可重复实例化为彼此独立的 Agents。
7. **Occupied target**：`agent-template → occupied Slot` 返回 `TARGET_OCCUPIED`；`assigned-agent → occupied Slot` 预检为合法 `exchange-agent`。Replace 只通过显式 menu/click flow，不由 template drop 隐式触发。
8. **Linear reorder**：只有 `pattern-slot` payload 能触发 reorder；拖 Agent 永远只表示 move/exchange，避免 reorder 与 exchange 混淆。
9. **Pattern template drop**：只生成 replacement candidate 和 destructive confirmation intent，不直接修改当前 Journey。M2.4 不伪造跨 Journey/Agent 的原子 persistence。
10. **Duplicate**：context menu 可以收集名称并产生 typed duplication request/candidate；只有存在可信的 aggregate commit boundary 时才能提交。现阶段不得连续调用两个 save 并展示为成功。
11. **Preview**：M2.4 只维护 `selectedSlotId` 与 `previewAgentId` contract；不渲染 workflow topology，正式 preview 留给 M2.5。
12. **Context menu**：selection 与 menu anchor 使用 Slot UUID 和 UI position；menu 关闭、Esc、outside click 和 focus return 都是 session behavior。
13. **Responsive baseline**：1440×900 对齐 Figma；约 1024 px 宽度允许横向 canvas overflow，不把固定 topology 压缩到不可操作。

### 3.2 两个非 UI 阻塞边界

以下 transaction boundaries 必须显式处理。Create、Save as Template 和 Template instantiation 属于 M2.4 的前置实施范围；replacement/duplicate 的完整 destructive commit 仍可保持 staged：

| 边界 | 当前事实 | M2.4 处理 |
| --- | --- | --- |
| Create Agent | 同时创建 Agent aggregate、Journey summary 与 Slot assignment | 新增原子 repository/application operation；失败不写入任何部分 |
| Save as Template | 从 Agent aggregate 创建独立 reusable snapshot | 新增 typed Template contract/repository operation；成功后 library 从 repository 重载/更新 |
| Instantiate Agent Template | 创建完整 Agent aggregate 并分配 Slot | 新增原子 repository/application operation；统一 owned-ID remap 与 runtime validation |
| Pattern replacement | 可能删除/保留多个 Agent，规范要求 backend transaction | 只 stage candidate、展示影响和 emit confirm/cancel；不执行伪事务 |
| Agent duplicate | 同时产生 Journey document 与新 Agent document；repository 只有独立 save | 完成 typed request/candidate UI 与纯 domain 调用；commit 等待原子 repository/API boundary |

如果产品要求 M2.4 就完成这两项的持久化成功态，需要先扩展 repository contract 和后端事务 API；这属于显著 scope change，不能由组件绕过。

## 4. 类型与状态设计

### 4.1 Versioned drag payload

建议建立纯 TypeScript boundary：

```ts
type OdysseyDragPayloadV1 =
  | { version: 1; kind: 'pattern-template'; templateKey: PatternTemplateKey }
  | { version: 1; kind: 'agent-template'; templateId: UUID }
  | { version: 1; kind: 'assigned-agent'; agentId: UUID; sourceSlotId: UUID }
  | { version: 1; kind: 'pattern-slot'; slotId: UUID }
  | { version: 1; kind: 'workflow-node-template'; nodeType: WorkflowNodeType }
  | { version: 1; kind: 'resource'; resourceType: 'tool' | 'knowledge-space'; resourceId: UUID }
```

要求：

- 使用固定 MIME key，例如 `application/x-odyssey-drag+json`；
- serializer 只接受 typed value；
- parser 接受 `unknown/string`，完成 JSON、version、discriminator、UUID/runtime validation；
- parse failure 返回 stable boundary error，不抛出原始 JSON exception；
- M2.4 target 对 future kinds 必须显式拒绝，不能 fall through。

### 4.2 InteractionState

```ts
type PatternInteractionState =
  | { type: 'idle' }
  | { type: 'dragging'; payload: PatternDragPayload; over: PatternDropTarget | null; feedback: DropFeedback | null }
  | { type: 'menu-open'; slotId: UUID; anchor: MenuAnchor }
  | { type: 'choosing-agent'; slotId: UUID; mode: 'assign' | 'replace' }
  | { type: 'confirming-pattern-replacement'; templateKey: PatternTemplateKey; affectedAgentIds: readonly UUID[] }
  | { type: 'naming-duplicate'; sourceSlotId: UUID; draftName: string }
```

所有 transition 通过单一纯函数或 store session action；组件不得维护互相独立的 `isDragging/isMenuOpen/isReplacing` booleans。

### 4.3 Drop target、action 与反馈

```ts
type PatternDropTarget =
  | { kind: 'system-canvas' }
  | { kind: 'agent-slot'; slotId: UUID }
  | { kind: 'linear-order'; targetOrder: number }

type PatternDropEvaluation =
  | { status: 'valid'; action: PatternDropAction; feedback: DropFeedback }
  | { status: 'invalid' | 'occupied' | 'duplicate'; reason: PatternDropReason; feedback: DropFeedback }
```

`evaluatePatternDrop` 必须只读取 immutable snapshot，不修改 Pattern。它负责把 payload + target 解析成 command intent，但 M2.3 command 仍是最终领域权威。

建议稳定 reason catalog：

- `PAYLOAD_INVALID`；
- `TARGET_KIND_UNSUPPORTED`；
- `SLOT_NOT_FOUND`；
- `TARGET_OCCUPIED`；
- `AGENT_ALREADY_ASSIGNED`；
- `SOURCE_SLOT_EMPTY`；
- `SAME_SLOT`；
- `REORDER_UNSUPPORTED`；
- `REORDER_POSITION_INVALID`；
- `PATTERN_REPLACEMENT_REQUIRES_CONFIRMATION`。

反馈必须包含非颜色文本或 `aria-live` message；CSS state 不是 reason 的事实源。

## 6. 实施步骤（9 个子任务）

### Step 1 — Freeze Agent creation/template contracts and transaction ports

交付：

- 在 `@odyssey/schemas` 中落实 frozen canonical 1.0.0 Agent Template runtime schema；
- 定义 Create Agent、Save as Template、list/load Template、instantiate Template 的 typed request/result；
- 明确 minimum `Start → End` aggregate factory 与 owned/external ID 分类；
- repository port 提供原子 use-case boundary，不让 UI 编排多个 save；
- in-memory adapter 实现真实状态语义，初始 Agent Template library 为空，不预置 mock template。

测试/验收：

- Create 成功同时产生 valid Agent aggregate、Journey summary 和 Slot assignment；
- Create 取消/失败/invalid response 不写任何部分；
- Save as Template 生成独立 snapshot，源 Agent 不变；
- Template 不包含 runtime/secrets，owned IDs 与 external references 分类正确；
- Template instantiation 完整 remap owned IDs，可重复实例化且互相独立；
- repository load/list/save response 均 runtime validated、deep cloned、支持 AbortSignal 和 stable errors。

### Step 2 — Freeze interaction contracts and acceptance matrix

交付：

- 冻结 payload、target、action、reason、feedback 与 InteractionState unions；
- 建立 payload × target × Pattern capability matrix；
- 明确 mouse、keyboard、context-menu 三种入口最终映射到同一 action；
- 把本计划 Decision Gate 更新为 accepted。

测试/验收：

- TypeScript exhaustive checks；
- matrix 覆盖 future payload 的稳定拒绝；
- 不涉及 Vue component 或 store mutation。

### Step 3 — Implement typed serialization, state transitions and drop preflight

交付：

- versioned serializer/parser；
- pure `transitionPatternInteraction`；
- pure `evaluatePatternDrop`；
- domain error → UI feedback mapping boundary。

测试/验收：

- malformed JSON、wrong version、unknown kind、invalid UUID；
- 每种 drag kind 只被匹配 target 接受；
- assigned Agent 到 empty/occupied Slot 分别得到 move/exchange；
- Agent Template 到 empty Slot得到 instantiate intent，到 occupied Slot 拒绝；
- Slot reorder 与 Agent exchange 不混淆；
- cancel/invalid evaluation 不改变输入。

### Step 4 — Build System Canvas presentation adapter

交付：

- 从 Journey document、M2.3 presentation 和 Agent summaries 派生稳定 view model；
- Slot position、route endpoints、label、assignment、capability、selection 全部显式建模；
- 固定 System Canvas shell（Guardrails / Execution / Behavior）与 Pattern topology 分层；
- route geometry 仅为 presentation，支持 resize/scale 计算但不持久化。

测试/验收：

- 四种 Pattern adapter fixtures；
- route endpoints 只引用现有 Slot view model；
- Agent summary 缺失时返回诊断 view state，不以 non-null assertion 掩盖；
- adapter output 不包含 Vue Flow 类型；
- save input 与 adapter 调用前后完全一致。

### Step 5 — Implement presentational libraries, Slots, routes and context menu

交付：

- `PatternTemplateLibrary`、`AgentLibrary`；
- Agent Template library 从 repository result 渲染；零模板时展示 empty state 与创建指引；
- `SystemCanvas`、`AgentSlot`、route layer；
- context menu shell；
- valid/invalid/occupied/duplicate/selected/focus/disabled visual states；
- Figma desktop layout 与现有 design tokens/CSS variables 对齐。

测试/验收：

- props → visible state；
- DOM event → typed emit；
- component 不导入 store、repository 或 M2.3 mutation command；
- context menu 支持 keyboard open、Esc、outside close、focus return；
- feedback 不只依赖颜色。

### Step 6 — Extend Journey store orchestration

交付：

- session actions：select Slot、open/close menu、begin/cancel drag、stage replacement、stage duplicate；
- create Agent、Save as Template、instantiate Template 调用原子 repository/application operation，并处理 loading/success/failure；
- drop dispatcher 只接受 Step 2 的 valid action；
- assign/move/exchange/unassign/reorder 委托 M2.3 commands；
- 成功后只更新 canonical Pattern、清理相关 session、递增 `mutationSeq`；
- 失败后保留原 document，并记录 stable domain/drop error；
- duplicate/replacement 不越过现有 transaction boundary。

测试/验收：

- 每个 valid action 的 store orchestration；
- domain failure 原子性；
- dragover 不改变 document 或 mutationSeq；
- stale selected/menu Slot 在结构变化后被 reconciliation；
- `toSaveInput()` 不包含 interaction/menu/selection/coordinates。

### Step 7 — Connect Journey Editor end-to-end interactions

交付：

- 替换 M2.2 Journey Editor placeholder；
- Pattern/Agent tab 的 library content 与 System Canvas；
- HTML DnD event boundary 和 click/keyboard alternatives；
- empty Slot 创建 Agent 表单与 configured Agent 的 Save as Template action；
- Slot click selection；
- context menu 的 Open workflow navigation intent、Replace、Duplicate、Unassign；
- Pattern replacement/duplicate 的 staged UI contract。

测试/验收：

- 用户可通过 UI 创建 Agent、Save as Template、从真实 Template 实例化、move、exchange、linear reorder、unassign；
- context-menu Open workflow 使用 typed route helper；
- invalid/cancel drop 不产生 mutation；
- active tab 切换不丢 canonical document；
- Preview 不在本步骤伪实现。

### Step 8 — Accessibility, responsive behavior and real-browser interaction proof

交付：

- focus ring、ARIA roles、`aria-live` feedback；
- keyboard assign/move/exchange/reorder 替代路径；
- Esc cancel drag/menu/dialog；
- 1440×900 visual check 与约 1024 px narrow-desktop check；
- 真实浏览器验证 dragstart/dragover/drop、context menu、focus return。

测试/验收：

- component/integration tests 不只依赖 snapshot；
- browser proof 覆盖 valid drop、invalid drop、exchange、cancel；
- 页面 resize 后 Slot/route 对齐，document 未变化；
- reduced-motion 下不依赖动画表达状态。

### Step 9 — Regression gate, completion report and M2.5 handoff

交付：

- 运行 `pnpm check`；
- 架构扫描：无 Vue Flow 泄漏、无 direct Pattern mutation、无 weak typing；
- 写 M2.4 completion report；
- 记录 replacement/duplicate transaction boundary；
- 为 M2.5 handoff `selectedSlotId`、`previewAgentId` 与 Open canvas route intent。

测试/验收：

- lint、typecheck、schemas/web tests、production build 全部通过；
- completion report 的测试数量与实际命令一致；
- 独立验收 prompt 覆盖本计划的 P0/P1 gates。

## 7. 推荐批次

### Batch A — Step 1: Agent creation/template foundation

先完成 Agent Template runtime contract、原子 use-case ports、minimum Agent factory 与无 mock 的 repository semantics。此批没有页面/DnD 改动，必须先独立验收 aggregate 完整性与原子失败。

### Batch B — Steps 2–3: Interaction core

冻结类型、状态机、parser 与 drop preflight，覆盖 Agent Template payload 与 target matrix。

### Batch C — Steps 4–5: Presentation adapter and components

完成 System Canvas view model 与纯展示组件。此批可以验证四种 Pattern 的视觉结构和真实 Template empty/list states，但不连接 store mutation。

### Batch D — Steps 6–7: Store and Journey Editor integration

把 valid actions 接到 M2.3 commands 和 Agent Template use cases，完成真实页面交互和 context menu。此批是主要集成风险，应独立验收。

### Batch E — Steps 8–9: Browser proof and milestone closure

补齐 accessibility、真实浏览器验证、全量质量门、completion report 与 M2.5 handoff。

一次性生成全部 M2.4 的风险较高，不建议跨 Batch 合并实现。每个 Batch 独立完成 review/acceptance 后再继续。

## 8. 测试矩阵摘要

| Source | Target | Expected |
| --- | --- | --- |
| Pattern template | System Canvas | stage replacement confirmation；不直接 mutate |
| Pattern template | Agent Slot / reorder zone | invalid target |
| Agent Template | empty Agent Slot | instantiate independent Agent and assign atomically |
| Agent Template | occupied Agent Slot | occupied rejection / explicit replace path |
| Assigned Agent | empty Agent Slot | move |
| Assigned Agent | occupied Agent Slot | exchange |
| Assigned Agent | same Slot | duplicate/same-target rejection，不 clone |
| Pattern Slot | Linear reorder zone | reorder |
| Pattern Slot | non-Linear reorder zone | unsupported |
| Workflow node/resource | System Canvas/Agent Slot | explicit invalid in M2.4 |
| malformed/foreign payload | any target | parse rejection；no mutation |

每条至少断言：evaluation result、document immutability、mutationSeq、session cleanup 与可访问反馈。

- 不实现 Workflow Preview topology（M2.5）；
- 不实现 Workflow graph commands（M2.6）；
- 不实现 editable Workflow Canvas（M2.7）；
- 不实现 autosave、conflict 或 multi-document persistence scheduling（M2.8）；
- 不实现 Tool/Knowledge Space resource DnD 的业务提交（M2.9），但 payload namespace 必须兼容；

- 不提供 mock Agent Template；没有 Save as Template 结果时 library 必须真实为空；
- 不在 dragover 阶段调用 command；
- 不依赖拖拽作为唯一可访问操作路径。
