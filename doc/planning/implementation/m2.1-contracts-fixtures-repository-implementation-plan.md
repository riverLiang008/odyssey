# Odyssey M2.1 — Contracts、Fixtures 与 Repository Boundary Implementation Plan

> Status: Proposed implementation plan  
> Parent plan: [`M2 Interaction Proof — Frontend Implementation Plan`](./m2-interaction-proof-frontend-implementation.md)  
> Engineering rules: [`Odyssey 前端工程规范`](../../frontend-engineering-guidelines.md)  
> Scope: 仅实现 M2.1；不实现页面、Pinia store、Vue Flow Canvas 或真实业务 API

## 1. 结论

M2.1 可以开始。

数据库设计和 canonical JSON 已经足以确定 M2 前端所需的核心 contract，但前端 contract **不应直接根据数据库表结构生成**。正确的来源关系是：

```text
Accepted domain constraints
          ↓
Canonical JSON contracts ─────→ @odyssey/schemas
          ↓                             ↓
Approved DB aggregate boundary     Frontend domain/editor
          ↓                             ↓
Future Pydantic API DTO  ←────→ Repository transport adapter
```

各层职责：

| 来源 | 对 M2.1 的权威内容 | 不应决定的内容 |
| --- | --- | --- |
| Canonical JSON | Pattern、Workflow Node、Edge、Loop、Layout、Variable、Tool 的 JSON 形状和 identity | 数据库索引、FK、表拆分 |
| DB implementation baseline | aggregate 边界、revision、JSONB/关系表边界、唯一性和删除保护 | Vue component、Canvas view model、editor session |
| SQLAlchemy models | 当前关系字段、状态 closed set 和 storage mapping 的实现证据 | 前端 public API response 的最终 shape |
| Pydantic/API DTO | 未来线上 request/response transport | 前端内部 UI state 和 Vue Flow object |
| Figma | 可见内容、交互和视觉状态 | domain contract、DB schema、API DTO |

因此 M2.1 应以 canonical JSON 为主，使用已批准数据库 baseline 交叉校验 aggregate/revision；先提供 in-memory repository。真实 API 完成后再新增 HTTP repository adapter，而不是修改 domain/editor contract。

## 2. 调研结果

### 2.1 已经固定、可直接实现的内容

- 所有 persisted entity 和 JSONB 内嵌对象使用 UUID string。
- built-in template/definition key 使用稳定 lowercase `snake_case`。
- Journey status 为 `draft | archived`。
- Journey、AgentWorkflow、KnowledgeSpace 和用户 Template 分别维护 revision。
- `PatternConfig` 存在 `ody_journey.pattern_config` JSONB。
- `WorkflowGraph` 与 `CanvasLayout` 分别存在 `agent_workflow.workflow_graph` 和 `agent_workflow.canvas_layout` JSONB。
- built-in Pattern 为 `hub_and_spoke | diamond_loop | linear_sequence | solo_component`。
- Pattern slot 坐标不持久化；route 由 Pattern rule 维护。
- Workflow 恰好包含一个 Start 和一个 End；任意环禁止；重复通过 Loop 表达。
- Workflow node config 已定义 Agent Action、Task、Branch 和 Loop 的判别结构。
- Loop body 内嵌自己的 graph 和 layout；Loop Start/End 是显式节点。
- Agent Canvas 和 Loop Canvas viewport 持久化。
- Agent-level Variables 是关系记录；Task-local Variables 存在 Task node config。
- AgentReusableTools 是 AgentWorkflow-owned 关系记录；Task Tool Steps 存在 Task node config。
- Knowledge Space reference 的 portable source of truth 在 typed workflow/tool JSON 字段，关系表只是删除保护和反向查询索引。
- V1 没有 Workflow Version/Restore/Release；current configuration + revision 是唯一编辑模型。

### 2.2 当前仓库实现差距

| 区域 | 当前状态 | M2.1 影响 |
| --- | --- | --- |
| `packages/schemas` | 只有薄 `WorkflowNode`、`WorkflowEdge`、`WorkflowGraph`、`CanvasLayout`，node config 仍是 `Record<string, unknown>` | 必须扩展为 canonical discriminated schemas |
| Runtime validation | `@odyssey/schemas` 没有 runtime schema library | repository boundary 无法安全解析外部数据 |
| API | 只有 `/health`，没有 Journey/Agent DTO 或 endpoint | M2.1 必须使用 in-memory repository |
| SQLAlchemy models | 已接近 approved DB baseline，包含 revision、templates、KS reference indexes 等 | 可用于交叉校验字段和 closed sets，但不作为 TS 自动生成源 |
| Alembic migration | 唯一 foundation migration 仍包含旧结构，如 `current_version_id`，且缺少新 baseline 大量表/约束 | 不能将当前 migration 当作前端 contract 权威来源 |
| Canonical JSON 文档 | 内容中的主要 decisions 已全部勾选，只有 package size limit 未决；但标题/status 仍写 Review Draft/not accepted | 实现前应确认将当前内容作为 schema `1.0.0` baseline，并修正文档状态或记录 freeze note |

### 2.3 与 M2.1 无关的未决项

canonical checklist 中仅剩 package/single-file size limit。M2.1 不实现 import/export ZIP，因此该项不阻塞 Pattern、Workflow、Layout、fixtures 和 repository contract。

## 3. M2.1 目标

完成后，后续 M2.2–M2.9 应可以：

- 从 `@odyssey/schemas` 导入 compile-time types 和 runtime schemas；
- 加载结构稳定、引用完整的 Journey/Agent fixtures；
- 通过 repository port 进行异步 load/save；
- 模拟 revision increment、network failure、invalid response 和 conflict；
- 确认 repository payload 永远不包含 Vue Flow 或 UI-only state；
- 在真实 API 到来时只添加 transport adapter，不重写 frontend domain contract。

## 4. M2.1 非目标

- 不实现 Journey/Agent 页面。
- 不实现 Vue Router、Pinia editor store 或 autosave debounce。
- 不导入 `@vue-flow/*`。
- 不实现 Pattern mutation strategy 或 Workflow graph command。
- 不实现真实 HTTP repository。
- 不实现 Pydantic DTO、FastAPI route、service 或 DB migration。
- 不实现 package ZIP import/export 和 size limit。
- 不实现完整 Knowledge Space、Template Library 或 Tool configuration UI contract；只定义 M2 fixture 引用所需的最小稳定类型。

M2.1 不应把所有类型放进一个 `index.ts`。建议 `@odyssey/schemas` 使用以下结构：

```text
packages/schemas/src/
├── common/
│   ├── identifiers.ts
│   ├── timestamps.ts
│   ├── result.ts
│   └── index.ts
├── pattern/
│   ├── pattern.schema.ts
│   └── index.ts
├── workflow/
│   ├── values.schema.ts
│   ├── variables.schema.ts
│   ├── tools.schema.ts
│   ├── nodes.schema.ts
│   ├── graph.schema.ts
│   ├── layout.schema.ts
│   └── index.ts
├── editor/
│   ├── journey-editor.schema.ts
│   ├── agent-workflow-editor.schema.ts
│   └── index.ts
├── repository/
│   ├── persistence.schema.ts
│   └── index.ts
└── index.ts
```

分层规则：

```text
Persistence/domain schemas
  canonical JSON，可进入 repository payload

Editor document schemas
  页面加载所需的 aggregate + summaries 投影
  不等于数据库 row，也不等于 ZIP package

Repository contracts
  load/save port、expected revision、transport-normalized errors

UI-only types
  不放在 @odyssey/schemas；后续留在 apps/web session/store
```

## 6. Runtime schema 技术方案

### 6.1 推荐选择

推荐在 `@odyssey/schemas` 引入 `zod`，以 runtime schema 作为单一实现来源，并通过 `z.infer` 导出 TypeScript type。

原因：

- M2.1 明确要求 repository boundary runtime validation；
- 纯 TypeScript interface 无法验证 API/fixture/import JSON；
- schema 与 inferred type 同源，可减少手写 interface 与 validator 漂移；
- discriminated union 适合 Workflow node、ValueSource、Tool Step 和 repository result；
- 后续 HTTP repository 可以直接复用 parsing，而不依赖 Vue。

示意：

```ts
export const workflowNodeSchema = z.discriminatedUnion('type', [
  startNodeSchema,
  endNodeSchema,
  agentActionNodeSchema,
  taskNodeSchema,
  branchNodeSchema,
  loopNodeSchema,
])

export type WorkflowNode = z.infer<typeof workflowNodeSchema>
```

### 6.2 边界约束

- schema package 不导入 Vue、Pinia、Vue Router、Naive UI、DOM 或 Vue Flow。
- 不通过 `z.any()` 恢复弱类型；未知 JSON literal 使用受控 JSON value schema。
- `configuration` 只有在 canonical 明确允许任意 extension bag 时才使用 JSON object schema。
- UUID 必须 runtime validated，不只声明为 `string`。
- timestamp 必须验证 UTC ISO 8601 representation。
- closed set 必须与 approved DB CHECK values 一致。
- schema parse failure 由 repository 映射为 `RESPONSE_INVALID`，不能让 Zod error 泄漏成 UI error contract。

## 7. 必须实现的 Schema

### 7.1 Common

```text
UUID
SchemaVersion = '1.0.0'
UTC timestamp
JSON primitive/value/object
Revision integer >= 1
```

实现注意：

- 可以导出 `UUID` branded type，但不得导致 fixture/DTO 到处使用无依据类型断言。
- `schemaVersion` 表示 JSON contract 版本，不是 record revision。
- normal CRUD editor response 是否在每个 nested field 重复 `schemaVersion`，由 editor DTO mapper 决定；canonical persistence objects 的独立验证边界必须保留版本语义。

### 7.2 Pattern

```text
PatternTemplateKey
PatternKind
PatternSlot
PatternRouteTarget
PatternRoute
PatternConfig
PatternTemplateSummary
```

canonical field：

```text
PatternConfig
  schemaVersion
  id
  templateKey
  kind
  name
  slots[]
  routes[]
  configuration

PatternSlot
  id
  label
  topologyRole
  order
  agentId
  configuration
```

M2.1 只做结构验证；Agent uniqueness、topology cardinality、linear route derivation 属于 M2.3 domain validation。

### 7.3 Workflow values 与 variables

```text
ValueSource
TemplateSegment
VariableDataType
VariableOwnership
AgentVariable
TaskLocalVariable
```

必须使用 discriminated union 表达 literal、variable 和 template value。Variable reference 使用 UUID，不使用 `{{name}}` 字符串作为 identity。

### 7.4 Tool envelopes

M2.1 至少定义 canonical common envelope：

```text
ToolKind
ToolStep
ToolOutputMapping
ToolFailureBehavior
AgentReusableTool
```

五种 built-in tool configuration 应使用按 `kind` 的 discriminated union；不能继续用一个永久的 `Record<string, unknown>`。如果为了控制 M2.1 大小分批实现，至少要完整实现 fixtures 实际使用的 `knowledge_retrieval` 和 `script_execution`，并为其余 kinds 建立明确、会拒绝未知结构的 schema，不得静默接受任意 config。

### 7.5 Workflow nodes

```text
StartNode
EndNode
AgentActionNode
TaskNode
BranchNode
LoopNode
LoopStartNode
LoopEndNode
WorkflowNode
WorkflowEdge
WorkflowGraph
```

注意：

- top-level graph 的 node union 与 Loop body node union 不完全相同。
- `loop_start`/`loop_end` 只允许出现在 Loop body。
- nested Loop 的禁止属于 domain invariant，但 schema 可通过 separate union 提前禁止 Loop body 中出现 `loop`。
- Branch edge 使用 canonical `sourceHandleId`；现有 `sourceHandle`/`targetHandle` 命名必须迁移，不能把 Vue Flow handle naming 直接定为 contract。
- Edge 是否保留 `targetHandleId` 应以 canonical contract 为准；不要因 Vue Flow API 方便自行扩展 persistence schema。

### 7.6 CanvasLayout

```text
NodePlacement
CanvasViewport
CanvasLayout
```

canonical 字段使用 `nodePlacements`，现有 `packages/schemas` 的 `nodePositions` 必须迁移。

结构 schema 只验证数值和 UUID；placement 引用存在 node、唯一 placement、zoom 范围等跨字段 invariant 可放在 refinement 或后续 domain validator。M2.1 至少必须拒绝非有限数值。

### 7.7 Editor documents

建议定义：

```ts
interface JourneyEditorDocument {
  journey: {
    id: UUID
    workspaceId: UUID
    name: string
    description: string | null
    status: 'draft' | 'archived'
    tags: string[]
    revision: number
    createdAt: string
    updatedAt: string
  }
  pattern: PatternConfig
  agents: AgentSummary[]
}

interface AgentWorkflowEditorDocument {
  agent: {
    id: UUID
    journeyId: UUID
    name: string
    description: string | null
    revision: number
    createdAt: string
    updatedAt: string
  }
  workflow: WorkflowGraph
  layout: CanvasLayout
  variables: AgentVariable[]
  reusableTools: AgentReusableTool[]
}
```

这是 editor projection，不是 DB row：

- `normalized_name` 不暴露给 editor。
- relation index rows 不暴露给 editor。
- JSONB/column storage distinction 不暴露给 editor。
- `workspaceId`、`journeyId` 等 ownership ID 保留。
- `revision` 位于相应 mutable aggregate。

## 8. Repository Boundary

### 8.1 Port

建议 port 放在前端 application boundary，而 shared repository DTO/schema 可以留在 `@odyssey/schemas`：

```ts
interface EditorRepository {
  loadJourney(
    journeyId: UUID,
    options?: { signal?: AbortSignal },
  ): Promise<RepositoryResult<JourneyEditorDocument>>

  saveJourney(
    input: SaveJourneyInput,
    options?: { signal?: AbortSignal },
  ): Promise<RepositoryResult<SaveJourneySuccess>>

  loadAgentWorkflow(
    journeyId: UUID,
    agentId: UUID,
    options?: { signal?: AbortSignal },
  ): Promise<RepositoryResult<AgentWorkflowEditorDocument>>

  saveAgentWorkflow(
    input: SaveAgentWorkflowInput,
    options?: { signal?: AbortSignal },
  ): Promise<RepositoryResult<SaveAgentWorkflowSuccess>>
}
```

`AbortSignal` 是 application/transport 能力，不进入 persisted DTO。若希望 `@odyssey/schemas` 完全 platform-neutral，port interface 放在 `apps/web/src/repositories`，shared package 只保留 input/result schemas。

### 8.2 Save input

```text
SaveJourneyInput
  journeyId
  expectedRevision
  pattern

SaveAgentWorkflowInput
  journeyId
  agentId
  expectedRevision
  workflow
  layout
  variables
  reusableTools
```

M2.1 不应设计 patch protocol。先使用 aggregate replacement semantics，和 approved DB compare-and-swap 一致。M3 接 API 时如果选择 JSON Patch/command endpoint，应通过 HTTP adapter 转换，不改变 editor document。

### 8.3 Result/error model

不使用 throw 作为预期 repository 业务结果：

```ts
type RepositoryErrorCode =
  | 'NOT_FOUND'
  | 'RESPONSE_INVALID'
  | 'NETWORK_FAILED'
  | 'REVISION_CONFLICT'
  | 'ABORTED'

type RepositoryResult<T> =
  | { ok: true; value: T }
  | { ok: false; error: RepositoryError }
```

programming error 可以 throw；预期 transport/domain boundary error 必须结构化返回。

### 8.4 In-memory implementation

必须满足：

- 每个 repository instance 拥有隔离的数据副本。
- load/save 经过 runtime schema parse，不因 fixture 来源可信而跳过 boundary。
- load 返回 deep-cloned document，调用者不能通过引用修改 repository internal state。
- save 也 deep-clone input，repository 不保留 caller mutable reference。
- `expectedRevision` 不匹配时返回 conflict，且不写入。
- 成功 save 原子替换 aggregate、revision + 1、更新 `updatedAt`。
- 可注入 latency、next failure、next invalid response、next conflict。
- async test 使用 fake timers 或 deferred promise，不使用不稳定真实 sleep。
- 测试场景控制接口不能混入生产 repository port。

## 9. Fixture 设计

### 9.1 原则

- fixture 必须 deterministic。
- 所有 ID 使用合法且稳定的 UUID；不使用 `agent-1` 等伪 ID。
- fixture factory 默认生成新对象，测试之间不得共享 mutable singleton。
- fixture 应通过与 repository 相同的 runtime schemas。
- fixture 名称来自 Figma 示例，但 identity 和 contract 不来自 Figma node ID。

### 9.2 最小 fixture set

```text
Workspace
  Odyssey Demo Workspace

Journey
  Research System

Pattern templates
  hub_and_spoke
  diamond_loop
  linear_sequence
  solo_component

Agent templates
  Research Agent
  Planner Agent
  Reviewer Agent

Agent workflows
  Minimal: Start → End
  Research: Start → Agent Action → Branch → Task → End
  Loop proof: Start → Loop → End, with Loop Start/Task/Agent Action/Loop End

Resources
  one Tool fixture
  one Knowledge Space summary/reference
```

### 9.3 Fixture builders

建议 builders：

```text
createPatternConfigFixture(overrides?)
createAgentWorkflowFixture(overrides?)
createWorkflowGraphFixture(overrides?)
createCanvasLayoutFixture(overrides?)
createJourneyEditorDocumentFixture(overrides?)
createAgentWorkflowEditorDocumentFixture(overrides?)
createInMemoryEditorRepositoryScenario(overrides?)
```

`overrides` 不应使用无限递归 `DeepPartial` 绕过 invariant。复杂子结构通过专用 builder 参数表达。

## 10. 实施步骤

M2.1 建议拆成 6 个小步骤，每一步通过测试后再继续。

### Step 1 — Freeze note 与差异清单

Status: **Implemented on 2026-08-11** — see [`v1-contract-source-mapping.md`](../../architecture/data/contracts/v1-contract-source-mapping.md).

- 将 canonical JSON 当前内容标记为 M2 使用的 `1.0.0` baseline，或新增一份 freeze decision note。
- 明确 canonical 中 package size limit 不阻塞 editor contracts。
- 记录 current migration 不是前端 contract source。
- 建立 DB/canonical/TypeScript 字段 mapping 表。

输出：一份可 review 的 source-of-truth note，避免实现者自行选择旧文档或 migration。

### Step 2 — Runtime schema foundation

Status: **Implemented on 2026-08-11** — common Zod schemas, package-level tests/typecheck, and root quality-command coverage added.

- 给 `@odyssey/schemas` 添加 runtime schema dependency。
- 实现 UUID、schemaVersion、revision、timestamp、JSON value。
- 为 package 添加独立 test/typecheck scripts；root `check` 应覆盖 schema package，而不只覆盖 web app。
- 建立 schema parse test helpers。

输出：可独立运行的 schema package quality gate。

### Step 3 — Pattern schemas

Status: **Implemented on 2026-08-12** — strict Pattern runtime schemas, canonical parsing tests, identity/reference refinements, and template summary provenance contracts added.

- 实现 Pattern discriminated types、routes 和 templates summaries。
- 添加 canonical examples 的 parse tests。
- 添加 invalid UUID、duplicate structural field、非法 route target 等失败 tests。

输出：M2.3 可直接消费的 Pattern contract。

### Step 4 — Workflow、Layout、Variable 与 Tool schemas

Status: **Implemented on 2026-08-12** — strict value, variable, five-kind Tool, Workflow/Loop, edge, and CanvasLayout runtime contracts with canonical and failure-path tests added.

- 先实现 value/variable/tool leaf schemas。
- 再实现 node discriminated unions 和 recursive Loop schema。
- 实现 graph/layout schemas。
- 添加 canonical example、Loop body、Branch handle、Task tool sequence tests。

输出：M2.6/M2.7 可直接消费且不含 Vue Flow 类型的 Workflow contract。

### Step 5 — Editor documents 与 repository

Status: **Implemented on 2026-08-12** — editor/save schemas, Web repository port, isolated in-memory adapter, deterministic failure controls, CAS, clone, abort, and boundary tests added.

- 实现 Journey/Agent editor projection schemas。
- 实现 save input/result/error schemas。
- 在 `apps/web` 建立 repository port 和 in-memory implementation。
- 添加 clone、revision CAS、failure injection 和 invalid response tests。

输出：M2.2 可直接加载和保存的 application boundary。

### Step 6 — Fixtures、round-trip 与 boundary audit

Status: **Implemented on 2026-08-12** — deterministic builders, four Pattern and three Workflow proof fixtures, Journey/Agent round trips, automated boundary audits, and the [`M2.1 completion report`](./m2.1-completion-report.md) added.

- 实现最小 fixture set 和 builders。
- 运行 load → save → reload round-trip。
- 扫描 forbidden imports/fields。
- 运行 package/web lint、typecheck、test、build。
- 记录对 M2.2、M2.3、M2.6 暴露的稳定 exports。

输出：M2.1 completion report 和下一阶段可用接口清单。

## 11. 测试计划

### 11.1 Schema tests

- canonical valid examples 全部 parse 成功。
- invalid UUID、timestamp、revision、schemaVersion 被拒绝。
- unknown node type、tool kind、route target type 被拒绝。
- node config 与 `type` 不匹配被拒绝。
- top-level graph 不接受 `loop_start/loop_end`。
- Loop body 不接受 nested Loop。
- `nodePlacements` 拒绝 NaN/Infinity。
- status/ownership/tool kind 与 DB closed set 一致。

### 11.2 Cross-reference refinements

M2.1 至少验证：

- node ID 唯一；
- edge ID 唯一；
- edge endpoint 存在；
- placement node ID 存在；
- placement 对同一 node 不重复；
- Pattern slot/route ID 唯一；
- route source/slot target 存在；
- occupied slot 的 Agent ID 唯一；
- Agent variables/reusable tools ID 唯一。

Cycle、Start/End cardinality、Branch edge completeness 等业务 mutation invariant 可由 M2.6 权威实现，但 fixture 必须已经合法。

### 11.3 Repository tests

- load 不泄漏 mutable internal reference。
- save 不保留 caller mutable reference。
- expected revision 匹配时 revision + 1。
- mismatch 返回 conflict 且数据不变。
- injected network failure 不写数据。
- invalid stored/returned fixture 映射为 `RESPONSE_INVALID`。
- aborted operation 返回 `ABORTED`。
- Journey save 不改变 Agent revision；Agent save 不改变 Journey revision。

### 11.4 Boundary audit

自动或测试检查：

```text
packages/schemas 不导入 vue/pinia/vue-router/@vue-flow/naive-ui
repository payload 不含 selected/selection/openPanel/focusMode/dragSession
WorkflowGraph 不含 x/y/position/viewport
CanvasLayout 不含 config/selected/panel/focus
editor document 不暴露 normalized_name/reference-index rows/JSONB naming
```

## 12. Quality Gate

M2.1 完成必须满足：

1. `@odyssey/schemas` 同时提供 runtime schemas 和 inferred types。
2. Pattern、Workflow、Layout 不再依赖永久 `Record<string, unknown>`。
3. 现有 `nodePositions` 已迁移为 canonical `nodePlacements`。
4. 现有 `sourceHandle` 已对齐 canonical `sourceHandleId`。
5. editor projection 与 DB row/ZIP package 明确不同。
6. repository load/save 全部经过 runtime validation。
7. in-memory repository 正确实现 revision compare-and-swap。
8. fixture IDs/references 合法且 deterministic。
9. repository 不泄漏 mutable references。
10. schemas/domain/repository 无 Vue Flow 或 UI-only state。
11. schema package 拥有独立测试与 typecheck，并被 root quality command 覆盖。
12. lint、typecheck、test、production build 全部通过。

如果希望 canonical 文档改名为非 draft 文件，应单独做文档 rename，并更新仓库内引用；不要在实现提交中留下新旧两份互相竞争的 contract 文档。

## 14. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 根据 DB row 生成臃肿前端 model | editor projection 独立定义，只保留页面所需 aggregate 字段 |
| TypeScript type 与 runtime validator 漂移 | runtime schema 为实现来源，type 通过 inference 导出 |
| schema 一次性过大 | 按 leaf → node → graph → editor document 顺序实现 |
| Loop recursive schema 难以维护 | parent graph 与 loop-body union 分开；显式禁止 nested Loop |
| fixtures 成为不可替换 mock 特例 | fixture 必须通过 canonical schemas，并通过 repository port 使用 |
| in-memory 行为与未来 API 不一致 | 遵守 approved aggregate replacement + expected revision CAS |
| migration 旧结构误导实现 | mapping note 明确 migration 不是当前 contract source |
| schema package 未进入 root CI | 为 package 添加 scripts，并调整 root check 覆盖 workspace package |
| 为赶进度保留 `Record<string, unknown>` | quality gate 阻止；只有明确 extension bag 允许 JSON object |

## 15. 对后续任务的稳定接口

M2.1 完成后只承诺以下接口稳定：

- canonical schemas 与 inferred types；
- `JourneyEditorDocument` / `AgentWorkflowEditorDocument`；
- save input/result/error；
- `EditorRepository` port；
- deterministic fixture builders；
- in-memory repository scenario controls。

以下内容不在 M2.1 冻结：

- Pinia store shape；
- component props/emits；
- Vue Flow node data/view model；
- drag payload；
- autosave debounce policy；
- HTTP endpoint path 和 wire-level patch protocol。
