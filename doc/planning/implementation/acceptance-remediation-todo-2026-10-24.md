## FIX-01：切换显示模式后仍能看到当前工作区域

### 已观察到的问题

在 Configure 模式平移到 Loop 所在区域，再切换到 Flow，画布看起来为空白。切回 Configure 能重新看到节点，数据没有丢失。

复现入口：打开包含根节点、Branch 和 Loop 的 Agent Workflow → Configure → 平移到 Loop 区域，使部分根节点离开视野 → Flow。

证据：[失败截图](../../temp/acceptance-2026-10-23/flow-viewport-failure.png)。

### 实施要求

明确模式切换时如何处理视野，例如保留当前关注节点或映射当前可见区域，并在交付记录中说明。切换后用户应能继续浏览原来的工作区域；不能依赖用户自行缩放寻找节点。

先核对显示坐标与 viewport 的关系，再决定修复位置。可从 `WorkflowCanvas.vue`、`workflowCanvasAdapter.ts`、`workflowEditor.ts` 和 `AgentWorkflowView.vue` 查起。不要为了显示模式切换重写业务图或批量覆盖用户布局。

### 实施完成 checklist

- [ ] 原失败步骤可以稳定复现，并在修复后通过。
- [ ] 根图和 Loop 区域分别检查；有选中节点和无选中节点均可正常切换。
- [ ] 平移、放大、缩小后双向切换，当前内容仍可见；连续多次切换不产生位置漂移。
- [ ] 在 1440 × 900、1024 × 900 和 Focus 模式检查。
- [ ] 模式切换没有意外修改业务配置、节点持久化坐标或触发连续保存。
- [ ] 保存刷新后符合既定的布局与视野恢复规则；补充覆盖实际失败原因的回归测试。
- [ ] 提供修复前后相同步骤的截图或录像，以及采用的视野处理规则。

## FIX-02：Loop 能完整容纳实际显示的子节点

### 已观察到的问题

Configure 模式下，选中 Loop 内节点，通过 Add Branch 创建含布尔条件的 Branch。创建和保存成功，但展开卡片的下半部分超出 Loop 外框。

原验收中 Loop 为 815 × 555。已有紧凑卡片的拖动限制通过，但这个限制没有解决新建 Branch 的实际尺寸问题。

证据：[失败截图](../../temp/acceptance-2026-10-23/loop-branch-overflow.png)。

### 实施要求

根据实际卡片尺寸处理边界，明确创建、内容变化和容器缩小时采用什么策略，例如调整位置、扩大容器，或拒绝无法成立的尺寸变更。策略应保留用户配置，并尽量保留已有布局。不能用裁切卡片、隐藏内容或取消展开来掩盖越界。

持久化变更必须通过项目规定的命令与事务边界；DOM 测量和第三方画布状态留在相应适配层。防止尺寸观察、重新布局和自动保存互相触发。可从画布 adapter、节点 renderer、布局命令和应用事务查起，以实际代码确认修改范围。

### 实施完成 checklist

- [ ] 原失败步骤通过：在 Loop 内新建 Branch 后，卡片完整位于容器有效区域，不遮挡标题。
- [ ] 已有 Branch 增删 Case、增加条件、修改长名称后，实际变高或变宽仍受边界约束。
- [ ] 新建 Task、Agent Action 等允许的子节点也满足边界规则；各创建入口行为一致。
- [ ] 拖动子节点到四周边界、缩小容器、移动父容器后，节点及出口可用且没有意外数据变更。
- [ ] Configure / Flow、不同缩放比例下的坐标转换正确；嵌套 Loop 仍不可创建。
- [ ] 保存刷新后尺寸和位置保持；JSON 导出再导入、DSL 重新应用不会丢失已有布局。
- [ ] Preview 与编辑器使用一致的卡片显示规则，内容和连线没有被裁切。
- [ ] 增加覆盖新建、动态尺寸变化、容器缩小的有效回归测试；实际浏览器验证尺寸，不能只用 jsdom 结果代替。
- [ ] 提供边界处理策略、浏览器截图以及保存刷新后的验证结果。

## QA-01：补齐尚未覆盖的验收

以下是待检查范围，不是已经确认的缺陷。发现问题后记录复现步骤、影响和修复结果；未执行的检查继续保留未勾选。

- [ ] **冲突 Overwrite**：双窗口制造冲突，确认本地内容保留、自动保存暂停；取消覆盖不丢草稿，确认覆盖后刷新一致；覆盖期间再次冲突或网络失败不会静默覆盖较新数据。
- [ ] **Branch 编辑**：多 Case 排序后出口与连线仍对应原 Case；删除已连线 Case 有明确确认，取消不变更，确认后不误删目标节点；长文本、键盘操作和焦点恢复可用。
- [ ] **连接与拖放**：根图与 Loop、不同 Loop 之间的非法连接被拒绝；嵌套 Loop 禁止；资源拖放与节点拖放不会互相误消费，失败操作没有半完成的业务变更。
- [ ] **保存异常**：断网、请求失败、重试、离开页面与旧响应返回时，保存状态、草稿、已保存数据符合预期；失败不能显示 Saved，旧响应不能覆盖新状态。
- [ ] **Preview 扩展场景**：长内容、动态高度、负坐标、Loop 和特殊出口连线在缩放及容器尺寸变化后完整显示，保持只读。
- [ ] **视觉与可访问性**：依据当前 Figma UI-25～29 和仓库已有对照文档逐项核对，记录所用设计版本、差异及处理结果；覆盖 1440 / 1024 宽度、Focus 和键盘路径。无法获取设计源时明确标记未验。
