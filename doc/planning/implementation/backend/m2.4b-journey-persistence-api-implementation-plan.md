## 1. Frozen product and contract decisions

- Pattern is selected exactly once during Journey creation.
- `pattern.id`, `pattern.kind`, and `pattern.templateKey` are immutable afterward.
- There is no Pattern replacement endpoint.
- Changing Pattern requires deleting the Journey and creating another one.
- Pattern-internal Slot operations remain valid when allowed by the Pattern strategy.
- Journey and AgentWorkflow revisions remain independent.
- Journey Agents are assembled as a read-only projection from AgentWorkflow rows.
- The server determines Current Workspace; clients do not submit `workspaceId`.
- `diamond_loop` remains the persisted compatibility key but uses Circular Loop semantics.
- Removing the Circular Loop entry promotes its execution-order successor atomically.
- Legacy four-role Diamond documents are not silently migrated.

## 4. Boundary DTOs

Define strict Pydantic request/response models mirroring shared schemas.

### 4.1 Journey summary

```text
JourneySummary
  id: UUID
  name: string
  description: string | null
  status: draft | archived
  patternKind: PatternKind
  agentCount: non-negative int
  revision: positive int
  createdAt: UTC timestamp
  updatedAt: UTC timestamp
```

Do not return presentation fields (`updatedLabel`, `scope`) or fabricated runtime data.

### 4.2 Create Journey

Request body:

```json
{
  "name": "Research System",
  "description": null,
  "patternTemplateKey": "linear_sequence"
}
```

Success returns a complete canonical `JourneyEditorDocument`. The server generates all
UUIDs, timestamps, revision, Pattern, Slots and Routes.

### 4.3 Save Journey Pattern internals

Request body:

```json
{
  "expectedRevision": 3,
  "pattern": { "...": "canonical PatternConfig" }
}
```

The URL owns Journey identity. `agents` is never writable. The server validates full
Pattern topology and same-Journey Agent references before update. An existing Slot may be
unassigned by changing its `agentId` to `null`. Removing an occupied Slot through this
ordinary PUT is forbidden and returns `409 STATE_CONFLICT`; clients must use the occupied
Slot removal command so Agent impact is explicit and atomic.

### 4.4 Delete Journey

```text
DELETE /journeys/{journey_id}
If-Match: "<revision>"
```

This transport is frozen for V1: the expected revision is supplied only through the quoted
`If-Match` header. Success returns `204 No Content` with no response body.

### 4.5 Minimum Agent creation

```text
POST /journeys/{journey_id}/slots/{slot_id}/agent
body: { expectedRevision }
```

Success returns:

```text
{ journey: JourneyEditorDocument, agent: AgentWorkflowEditorDocument }
```

The server generates the next available default `Agent N` name.

### 4.6 Occupied Slot removal

```text
POST /journeys/{journey_id}/slots/{slot_id}/commands/remove
```

Request contains `expectedRevision`, `expectedAgentId`, and either discard or
save-as-template-and-discard action. Success returns latest Journey plus optional complete
AgentTemplate.

### 4.7 Agent Template recovery

```text
GET /agent-templates
```

Returns the complete Template records visible to Current Workspace. This endpoint is in
scope so a Template created by `save_as_template_and_discard` remains available after a
page refresh. Template load/save/instantiate endpoints may be delivered in a later batch;
the list response and occupied-remove response use the same canonical `AgentTemplate`
schema.

## 5. Application architecture

```text
FastAPI router
→ strict request DTO
→ CurrentWorkspace dependency
→ application service / transaction
→ Pattern domain service + repository
→ SQLAlchemy session
→ strict response DTO
```

Rules:

- routers contain no topology or transaction logic;
- SQLAlchemy models are not response DTOs;
- every external/stored JSON boundary is validated;
- Python Pattern semantics must be parity-tested against shared canonical fixtures;
- no component/view/session fields enter persistence;
- repository queries always include Current Workspace ownership scope.

## 6. Pattern domain parity

Backend services need authoritative Python behavior for built-in Pattern instantiation and
validation. Freeze parity fixtures for:

- Solo: one `solo` Slot, no internal routes;
- Linear: at least one Slot, continuous order, successor routes and terminal
  `journey_end` in persisted topology;
- Hub: exactly one immutable `hub`, at least one `spoke`, hub-to-spoke routes;
- Circular Loop: at least two Slots, one `entry`, remaining `loop`, continuous order,
  every Slot has one successor and final successor is entry.

Do not persist canvas coordinates or UI labels as topology identity. Route IDs and Slot IDs
are server-generated UUIDs.

## 7. Pattern immutability enforcement

On ordinary Journey save:

1. load Journey scoped to Current Workspace, with locking/CAS strategy;
2. compare submitted Pattern identity with stored Pattern;
3. reject any change to Pattern `id`, `kind`, or `templateKey`;
4. validate allowed topology mutations for the stored kind;
5. validate every assigned Agent belongs to the Journey and is assigned at most once;
6. update only if expected revision matches;
7. increment Journey revision exactly once.

Immutable change returns:

```text
409 STATE_CONFLICT
details.reason = PATTERN_IMMUTABLE
```

Do not classify a lifecycle violation as malformed JSON.

## 8. Transaction specifications

### 8.1 Create Journey

One transaction must:

- resolve Current Workspace;
- validate request;
- instantiate chosen built-in Pattern;
- insert `ody_journey` with revision 1;
- commit once;
- return the aggregate assembled from committed state.

Failure leaves no Journey or Pattern fragment.

### 8.2 Minimum Agent creation

One transaction must:

- lock/check Journey and expected revision;
- verify Slot exists and is empty;
- allocate unique default Agent name;
- create AgentWorkflow and minimum Start → End graph/layout;
- assign Agent ID into Pattern Slot;
- increment Journey revision once;
- commit all owned rows once.

### 8.3 Occupied Slot removal

One transaction must validate the expected occupant, optionally snapshot a Template,
derive the new valid topology, delete AgentWorkflow and owned rows, update Journey
projection source and revision, then commit once.

### 8.4 Delete Journey

One transaction/CASCADE boundary must:

- validate Current Workspace and expected revision;
- delete Journey-owned AgentWorkflows and owned rows;
- preserve independently saved Templates;
- return only after commit.

## 10. Error envelope

Server codes:

```text
VALIDATION_FAILED
NOT_FOUND
REVISION_CONFLICT
STATE_CONFLICT
LEGACY_PATTERN_UNSUPPORTED
```

Client-only codes remain `NETWORK_FAILED`, `ABORTED`, `RESPONSE_INVALID`.

Envelope:

```json
{
  "error": {
    "code": "STATE_CONFLICT",
    "details": {
      "reason": "PATTERN_IMMUTABLE"
    }
  }
}
```

Validation issues preserve `{ path, code }`. Do not rely on English error strings as API
contract.

Recommended status mapping:

| Status | Code |
| ---: | --- |
| 404 | `NOT_FOUND` |
| 409 | `REVISION_CONFLICT`, `STATE_CONFLICT` |
| 422 | `VALIDATION_FAILED`, `LEGACY_PATTERN_UNSUPPORTED` |

## 13. Database and test infrastructure strategy

The current behavior depends on PostgreSQL JSONB, asyncpg, foreign keys, CAS updates and
transaction rollback. Service and HTTP integration tests therefore run against PostgreSQL;
SQLite substitution is not accepted for these tests.

- add an async `get_session` dependency that owns request-scoped session lifecycle;
- application services use `async with session.begin()` as the single transaction boundary;
- repositories flush but never commit independently;
- tests override `get_session` and `CurrentWorkspace` dependencies explicitly;
- each integration test receives isolated committed state and deterministic cleanup;
- tests verify database state through a separate session after success or rollback;
- HTTP tests use an ASGI transport compatible with async dependency overrides;
- local test documentation names the required PostgreSQL URL and migration/setup command.

Before changing schema, implement a schema-fit test against the accepted DTOs. The initial
baseline already has the required Journey, AgentWorkflow, Variable, ReusableTool and
AgentTemplate storage. Add an Alembic revision only if an executable test proves the
accepted contract cannot be stored safely; record that reason in the migration docstring
and implementation completion report.

## 14. CAS and transaction implementation rules

Journey and AgentWorkflow writes use database-enforced compare-and-swap statements, not a
read-compare followed by an unconditional update:

```text
UPDATE ...
SET revision = revision + 1, ...
WHERE id = :id
  AND workspace ownership matches
  AND revision = :expected_revision
RETURNING revision, updated_at
```

When zero rows return, perform one scoped diagnostic read inside the transaction to map the
result to `NOT_FOUND` versus `REVISION_CONFLICT`. Never reveal that an ID exists in another
Workspace.

Multi-row commands may lock the scoped Journey row before deriving names or topology, but
the final mutation must still assert the expected revision. Exactly one Journey revision is
consumed by minimum-Agent creation or occupied-Slot removal. Creating/deleting owned Agent
rows does not cause additional Journey revision increments.

Agent Workflow save replaces its current owned Variable and ReusableTool collections in the
same transaction after validating the complete aggregate. It must synchronize any derived
Knowledge Space reference-index rows required by the database baseline; a failed reference
or owned-row write rolls back the graph, layout, revision and every collection together.

## 15. Shared-contract coordination

Backend Pydantic models must be checked against `packages/schemas`, but TypeScript shared

inside the HTTP adapter. Before frontend integration, freeze and add runtime schemas for:

- `CreateJourneyInput` and `JourneySummary`;
- revised `CreateMinimumAgentInput` with `expectedRevision` and without client name/snapshot;
- occupied Slot removal request/result;
- Journey deletion operation using quoted `If-Match` at the transport boundary;
- server errors `VALIDATION_FAILED`, `STATE_CONFLICT` and
  `LEGACY_PATTERN_UNSUPPORTED`, including structured details;
- server-versus-client-only repository error separation.

Contract parity tests use shared JSON examples as language-neutral fixtures. Python and
TypeScript both validate the same positive documents and reject the same cross-reference,
topology and immutable-transition cases. Copying TypeScript implementation logic into tests
is not parity proof.

## 16. Ordered execution and verification gates

The batches are executed in dependency order. A later batch starts only after its gate
passes:

1. **Foundation gate:** request session, Workspace dependency, error envelope and PostgreSQL
   test harness pass without Journey routes.
2. **Read/create gate:** all four Pattern creation cases round-trip through POST/GET/list and
   remain isolated by Workspace.
3. **Save gate:** legal Pattern transitions succeed; stale revisions, immutable Pattern
   changes, foreign Agent references and occupied-Slot removal through PUT are rejected.
4. **Agent gate:** Agent load/save and minimum creation round-trip; injected failures prove
   no orphan or partial assignment.
5. **Destructive gate:** occupied removal and Journey deletion pass discard,
   save-as-template, CAS, cascade/preservation and rollback tests.
6. **Recovery gate:** a Template created by occupied removal is returned by
   `GET /agent-templates` after a fresh request/session.
7. **Release gate:** OpenAPI examples are captured, local seed/smoke instructions work from
   a clean database, Ruff passes, and the complete `apps/api` pytest suite passes.

## 17. Test matrix

### Contract/API

- strict valid/invalid DTOs;
- error envelope for every code;
- status mapping;
- response aggregate validation;
- URL/body identity mismatch impossible or rejected.

### Workspace isolation

- list excludes other Workspaces;
- detail/Agent/delete return NOT_FOUND across Workspace boundary;
- client-supplied workspace fields rejected;
- production fail-closed dependency behavior.

### Transactions/concurrency

- create rollback;
- stale Journey/Agent save conflict;
- concurrent minimum Agent creates produce no duplicate assignment/name;
- minimum Agent failure leaves no orphan;
- occupied removal failure leaves Slot/Agent/Template unchanged;
- Journey delete stale revision leaves aggregate intact;
- delete preserves saved Templates.
- an occupied-remove Template is returned by `GET /agent-templates` after refresh;
- ordinary Journey PUT allows unassign but rejects removal of an occupied Slot.

### Pattern

- instantiate and validate all four kinds;
- reject kind/templateKey/id changes;
- allow legal Slot mutations;
- reject invalid cardinality/routes/order/foreign Agent references;
- Circular Loop entry deletion promotes successor;
- legacy four-role document returns dedicated error without mutation.

## 18. Definition of Done

1. All frozen endpoints are implemented through thin routers and tested services.
2. Four Pattern kinds can be selected only at Journey creation.
3. Pattern immutable fields are enforced server-side.
4. Journey list/create/load/save/delete work with Workspace isolation and revisions.

## 19. Completion status — 2026-08-15

Implemented the frozen Journey persistence slice and the HTTP Repository blockers:

- Current Workspace is injected through `Depends(get_settings)` and production fails closed.
- Development CORS normalizes trailing slashes and explicitly permits both Vite origins,
  CRUD methods, and `If-Match`; wildcard origins/headers are not used.
- OpenAPI contains business DTOs only and has contract coverage preventing Settings/secrets
  from appearing in request inputs or schemas.
- Pattern identity/provenance is immutable; ordinary Journey PUT can unassign but cannot
  remove an occupied Slot.
- Agent workflow save uses Agent-level CAS and replaces workflow-owned children in one
  transaction.
- Agent Templates support visible-library reads, private Workspace snapshots, instantiation
  with owned-ID remapping, and atomic occupied-Slot removal with optional save-as-template.

Canonical aggregate documents are returned for Journey and Agent mutations. The frontend
HTTP adapter should strip repository-only routing IDs (`journeyId`, `agentId`, `slotId`) from
request bodies, map successful canonical documents into `RepositoryResult.value`, and create
client-only `NETWORK_FAILED`, `ABORTED`, and `RESPONSE_INVALID` errors locally.
