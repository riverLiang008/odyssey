# M2.4B Frontend — New OdyJourney 与 Pattern Immutable 实施计划

> Status: Ready for implementation  
> Milestone: M2.4B Journey persistence vertical slice  
> Scope: Journey 创建体验、Pattern 模板选择与预览、Editor 当前 Pattern 信息、移除 Pattern replacement  
> Authoritative guideline: [`frontend-engineering-guidelines.md`](../../../frontend-engineering-guidelines.md)  
> Backend plan: [`m2.4b-journey-persistence-api-implementation-plan.md`](../backend/m2.4b-journey-persistence-api-implementation-plan.md)  
> Contract review: [`journey-persistence-contract-review-questions.md`](../backend/journey-persistence-contract-review-questions.md)

## 1. 产品结论

Pattern 是 OdyJourney 创建时选定的结构类型，不是创建后的普通配置项。

- 用户在 `New OdyJourney` 流程中比较并选择一个 built-in Pattern；
- 创建前可以任意切换预选 Pattern，且只修改本地 form/session draft；
- 点击 Create 后，Journey 与选定 Pattern 由 repository/API 原子创建；
- 创建后的 `pattern.id`、`pattern.kind`、`pattern.templateKey` 不可修改；
- Journey Editor 不提供 Pattern replacement；
- 用户若要改用其他 Pattern，必须删除 Journey 并重新创建；
- Pattern 内部允许的 Slot 增删、重排、Agent assignment 和配置仍由 strategy 控制。

本方案覆盖并移除 M2.4 中已经实现的 replacement 交互与临时 in-memory
replacement transaction。不能只隐藏按钮，必须删除完整业务路径。

## 2. 创建页信息架构

新增 route：

```text
/journeys/new
```

路由定义中必须把静态 `journeys/new` 放在 `journeys/:journeyId` 之前，或使用明确的
UUID route matcher，避免把 `new` 当成 Journey ID 后落入 invalid/not-found boundary。

建议页面结构：

```text
New OdyJourney
├─ Basic information
│  ├─ Journey name（必填）
│  └─ Description（可选）
├─ Pattern selection workspace
│  ├─ left: Pattern template library
│  └─ right: selected Pattern preview + explanation
└─ actions
   ├─ Cancel
   └─ Create OdyJourney
```

### 2.1 Pattern template library

继续使用 sidebar/card 作为 Pattern 的比较入口，这是 sidebar 的核心产品价值。

四张 built-in card：

| Pattern | 一句话说明 | 典型场景 |
| --- | --- | --- |
| Linear Sequence | 按固定顺序依次执行 | 流水线、多阶段处理 |
| Hub and Spoke | 一个协调 Agent 调度多个专业 Agent | 协调者—专家结构 |
| Circular Loop (`diamond_loop`) | 从指定入口循环执行 | 迭代、复核、持续改进 |
| Solo Component | 一个独立 Agent | 简单、单一职责任务 |

要求：

- 默认不预选，用户必须明确选择；
- click 和键盘操作完成 selection；创建页不需要 Pattern drag-and-drop；
- selected card 有可见 selected state 和 `aria-pressed`/等价语义；
- 选择只更新 UI session，不实例化或持久化 Journey；
- loading 时锁定重复提交，但不把 disabled 作为唯一反馈；
- card 文案来自共享 built-in definition/presentation metadata，不在多个 view 中复制。

### 2.2 Pattern preview

右侧复用现有 Pattern strategy、presentation adapter 和 route layer，显示真实拓扑：

- preview 使用临时、纯派生的 PatternConfig candidate；
- candidate IDs 由 deterministic preview-only factory 产生，不进入 repository；
- Linear 显示相邻顺序箭头，无尾线；
- Hub 显示 Hub 到 Spokes 的方向箭头；
- Circular Loop 显示唯一入口、闭环和方向箭头；
- Solo 显示一个节点且无内部连线；
- preview Slot 不可点击创建 Agent、不可拖拽、不可打开菜单；
- 不把 preview 实现成可编辑 System Canvas 的 CSS-disabled 版本；通过明确
  `readonly/preview` presentation contract 禁用 mutation emits。

右侧同时显示：

- 名称与说明；
- 默认 Slot 数量；
- 是否支持动态 Slot；
- 关键拓扑规则；
- `Pattern cannot be changed after this Journey is created.` 提示。

## 3. 创建表单与状态模型

建议使用独立 `journeyCreation` store/composable，不能复用 Journey Editor session：

```ts
interface JourneyCreationDraft {
  name: string
  description: string
  selectedPatternTemplateKey: PatternTemplateKey | null
}

type JourneyCreationStatus =
  | { type: 'idle' }
  | { type: 'submitting'; requestId: number }
  | { type: 'failed'; error: RepositoryError }
  | { type: 'succeeded'; journeyId: UUID }
```

要求：

- trim 后的 name 非空；长度以共享 schema 为准；
- Pattern 未选择时 Create disabled，并提供可访问提示；
- submit 使用单一 request ID/AbortController，阻止 double submit 和 stale response；
- 成功只采用 repository 返回的 canonical `JourneyEditorDocument`；
- 成功后 `router.replace` 到新 Journey 的 Pattern tab；
- 失败保留用户 draft；取消/离开页面 abort pending request；
- server `VALIDATION_FAILED.issues` 映射至字段；其他错误显示稳定页面反馈；
- 不把 form draft 写入 Journey Editor persistence。

## 4. Frontend repository 与共享 schema

新增 Journey lifecycle port，不把列表/创建/删除塞进 EditorRepository：

```ts
interface JourneyLifecycleRepository {
  listJourneys(options?): Promise<RepositoryResult<JourneySummary[]>>
  createJourney(input: CreateJourneyInput, options?): Promise<RepositoryResult<JourneyEditorDocument>>
  deleteJourney(input: DeleteJourneyInput, options?): Promise<RepositoryResult<DeleteJourneySuccess>>
}
```

共享 schema 至少包括：

```ts
interface CreateJourneyInput {
  name: string
  description: string | null
  patternTemplateKey: PatternTemplateKey
}

interface JourneySummary {
  id: UUID
  name: string
  description: string | null
  status: 'draft' | 'archived'
  patternKind: PatternKind
  agentCount: number
  revision: Revision
  createdAt: UTCTimestamp
  updatedAt: UTCTimestamp
}

interface DeleteJourneyInput {
  journeyId: UUID
  expectedRevision: Revision
}
```

HTTP adapter 负责：

- 从 path/body 拆分 repository input；
- runtime validate success/error response；
- 将 fetch/abort/invalid response 转换为 client-side repository errors；
- 不暴露 Response、HTTP DTO 或 SQL naming 给 store/component。

In-memory repository 必须实现相同 port，使前后端可独立开发和测试。

## 5. Journey list 调整

当前 `JourneyListView` 直接读取 feature-local fixture summary，`New OdyJourney`
按钮被禁用。改为：

- repository 加载真实 `JourneySummary[]`；
- New 按钮导航至 `/journeys/new`；
- list view model 派生 `updatedLabel`、scope 和展示状态；
- 不伪造 execution count；
- 覆盖 loading、empty、error、retry；
- 每张卡展示 Pattern 名称，帮助用户确认不可变的 Journey 类型；
- Journey deletion 使用显式 destructive confirmation，展示名称、Pattern 和 Agent
  数量；提交 expected revision；成功后从列表移除；失败保持列表与 dialog 稳定。

Community 区域继续作为 future unavailable state，不与 Workspace Journey API 混合。

## 6. Journey Editor 调整

### 6.1 移除 replacement 全路径

删除或重构以下能力：

- Editor 中 `PatternTemplateLibrary` 的四模板选择/drag；
- `pattern-template` 到 `system-canvas` 的 replacement drop action；
- `stagePatternReplacement`、`requestPatternReplacement`、`replacePattern`；
- `confirming-pattern-replacement`、`pattern-replacement-requested` 状态与事件；
- `PatternLifecycleRepository.replaceJourneyPattern`；
- `ReplaceJourneyPatternInput/Success` schema；
- in-memory replacement transaction；
- replacement dialog、copy、integration tests；
- backend handoff 中残留的 replacement endpoint 假设。

如果 `pattern-template` drag payload 未来只用于创建页，而创建页不采用 DnD，则从当前
DnD union 删除该 variant；若其他已确认功能仍消费，必须把 target capability 收紧为不可能
命中 Journey Editor。不能保留一个隐藏但可由 programmatic call 触发的替换路径。

### 6.2 Current Pattern sidebar

Pattern tab 左侧替换为 `CurrentPatternSummary`：

- 只显示当前 Pattern card；
- 名称、说明、Slot count、拓扑规则和 immutable 提示；
- 不显示其他三张模板；
- 无 choose、drag 或 replace event；
- Slot context menu 与 canvas 编辑能力保持原样；
- `Circular Loop` 为 UI 名称，persisted key 仍为 `diamond_loop`。

Editor 顶部或 summary 中提供 Journey 删除入口；删除成功导航 Journey list。

## 7. Pattern 不可变前端防线

后端是最终权威，但前端也必须防止错误 candidate：

- `saveJourney` 前保存 loaded immutable fingerprint：
  `{ patternId, kind, templateKey }`；
- store 普通 Pattern commands 只能改变 strategy 允许的内部结构；
- toSaveInput 不接受外部 Pattern kind/template candidate；
- HTTP `STATE_CONFLICT / PATTERN_IMMUTABLE` 显示稳定错误并停止重试；
- load 到 `LEGACY_PATTERN_UNSUPPORTED` 时显示只读说明、删除并重建入口；
- 不在 render/load 时迁移 legacy Pattern。

## 8. 实施批次

### Batch A — Shared contracts and repositories

- 增加 Journey summary/create/delete schemas；
- 增加 Journey lifecycle port 和 in-memory implementation；
- 更新 repository error union；

- 创建表单和状态机；
- selectable Pattern library；
- read-only live preview；
- success navigation 与 failure retention。

### Batch C — Journey list and delete

- repository-driven list；
- 启用 New 按钮；

### Batch D — Lock Editor Pattern

- CurrentPatternSummary；
- 移除 replacement UI/store/state/repository/schema；

- 按 backend contract 实现 fetch adapter；

- refresh persistence 和 revision conflict 浏览器验证。

## 9. 测试矩阵

### Domain/adapter

- 四种 preview candidate 全部通过 strategy validation；
- preview 不修改输入、不输出 persistence/UI state；
- immutable fingerprint 拒绝 id/kind/templateKey 变化；
- repository response/error runtime validation。

### Component/integration

- 创建页默认无选择；
- 每张模板卡可点击和键盘选择；
- 切换模板更新正确拓扑和说明；
- preview 不发 mutation intent；
- name/Pattern validation；
- double submit、abort、failure draft retention；
- success 导航到返回的 journeyId；
- Editor 只显示 Current Pattern；
- Editor DOM/interaction 中不存在 replacement；
- delete cancel/failure/success；
- legacy unsupported 只读提示。

### Browser

- 创建四个独立 Journey，分别选择四种 Pattern；
- 每次创建后 Editor 显示正确且锁定的 Pattern；
- 刷新后保持 Journey 和 Pattern；
- Editor 中无法 click、drag、keyboard 或直接 UI 路径替换 Pattern；
- 删除 Journey 后返回列表并消失；
- stale delete/save 显示 revision conflict；
- 1024 与 1440 desktop layout。

## 10. Definition of Done

1. New OdyJourney 按钮可用并进入正式创建页。
2. 用户在 sidebar 中比较四种模板，右侧看到真实只读拓扑预览。
3. 未明确选择 Pattern 不能创建。
4. 创建成功返回 canonical Journey 并导航 Editor。
5. Journey Editor 只展示当前 Pattern 信息，不展示替换入口。
6. replacement 的 UI、DnD、state、store、repository、schema 和测试完整移除。
7. Pattern immutable fingerprint 和 server conflict 均有处理。
8. Journey list 使用 repository DTO，不使用 feature-local fixture contract。
9. Journey delete 有确认、revision 和稳定失败行为。
10. 四种 Pattern create/save/reload/delete 浏览器路径通过。
11. lint、typecheck、tests 和 production build 全部通过。
