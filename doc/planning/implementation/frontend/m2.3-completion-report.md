## Duplication transaction boundary

`duplicateAgentAggregate` is pure and returns one indivisible result containing:

- the updated Journey editor document with the new Agent summary and target Slot assignment;
- the fully remapped new Agent workflow editor document.

It performs no repository writes. The current repository API has independent Journey and Agent saves and therefore cannot honestly guarantee a cross-document transaction. A real atomic persistence endpoint/transaction remains an explicit later API-integration requirement; M2.3 does not wrap two saves in a false transaction.

## Persistence handoff

M2.3 store actions update the in-memory canonical Pattern and increment `persistence.mutationSeq`. They do not debounce or save. M2.8 owns autosave state transitions, snapshot sequencing, stale-response protection, conflict recovery, and repository scheduling.
