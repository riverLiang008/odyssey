# M2.5 Acceptance Checklist — Read-only Workflow Preview

> Acceptance target: M2.5  
> Prerequisite: frontend and Web API are running with persisted Journey data  
> Runtime rule: use the real Web API; do not substitute mock or fallback data

## 1. Quality gates

Run from the repository root:

```bash
pnpm --filter @odyssey/web lint
pnpm --filter @odyssey/web typecheck
pnpm --filter @odyssey/web test
pnpm --filter @odyssey/web build
```

Acceptance requires all four commands to pass with no skipped failing suite.

## 2. Configured Execution Slot

- Open a persisted Journey containing at least one configured Slot.
- Left-click the configured Slot.
- Confirm exactly one `WORKFLOW PREVIEW` surface appears.
- Confirm the Journey URL does not change.
- Confirm the Preview Agent identity matches the Slot Agent.
- Confirm the graph, layout, node count, and edge count come from the persisted Agent Workflow.
- Click the same Slot again and confirm the Preview remains open rather than toggling closed.

## 3. Read-only contract

- Confirm the Preview shows the `Read only` badge.
- Confirm nodes cannot be dragged or selected for configuration.
- Confirm no connect handles, node palette, Delete action, property panel, or drop target exists.
- Confirm clicking nodes or edges does not mutate the graph and does not increment Journey or Workflow revision.
- Refresh the Journey and confirm Preview state is closed and was not persisted.

## 4. Selection and single-instance behavior

- With a Preview open, click an empty Slot.
- Confirm the empty Slot is selected, no Agent is created, no Workflow load is issued, and the Preview closes.
- Open Agent A, then select configured Agent B.
- Confirm the existing Preview replaces its content in place; a second Preview must not appear.
- Switch A → B quickly under delayed responses and confirm a late A response never replaces B.

## 5. Guardrails

- Create or use an active Input Guardrail and click its Agent.
- Confirm it opens the same Preview shell without changing the route.
- Repeat with an active Output Guardrail.
- Switch between a configured Execution Agent and a Guardrail Agent; confirm only one Preview exists.
- Remove the currently previewed Guardrail and confirm the Preview closes without retaining stale identity.

## 6. Loading, error, retry, and removal

- Delay `loadAgentWorkflow` and confirm a local loading state appears while the Journey remains usable.
- Force a retryable network or invalid-response failure and confirm only the Preview shows an error with `Retry`.
- Retry successfully and confirm the graph replaces the error state.
- Close while loading and confirm the request is aborted with no error flash.
- Remove the previewed Agent/Slot through the supported lifecycle command and confirm the Preview closes.

## 7. Nested navigation

- Open a configured Slot Preview and click `Open canvas`.
- Confirm navigation reaches `/journeys/:journeyId/agents/:agentId` for the same owning Journey and Agent.
- Use the Workflow Editor back link and confirm it returns to the owning Journey Execution surface.
- Confirm simply selecting a Slot or Guardrail never navigates.
- Confirm the existing context-menu `Open workflow` action still navigates directly, including empty-Slot atomic Agent creation from M2.4.

## 8. Visual and accessibility checks

- At approximately 1440 px and 1024 px viewport widths, confirm the Preview remains legible and does not cover global navigation.
- At narrow width, confirm the responsive card remains usable without distorted graph scaling.
- Confirm edges connect node boundaries, arrow direction is readable, labels do not overlap controls, and topology is uniformly scaled.
- Confirm the Preview has an accessible region name; Close, Open canvas, and Retry are keyboard-operable.
- Confirm loading uses status semantics and errors use alert semantics.
- Press Escape while Preview has focus and confirm it closes.
- Confirm no new browser console warnings or errors occur across the full path.

## 9. Acceptance result template

Record:

- frontend URL and API URL;
- commit/worktree identity and whether unrelated local changes exist;
- lint/typecheck/test/build results and test count;
- each checklist section as PASS, FAIL, or BLOCKED;
- reproduction steps and screenshots for every failure;
- IDs of any acceptance Journey/Agent data created;
- whether that data was retained or removed.

M2.5 is PASS only when all quality gates pass and the configured Slot, Guardrail, read-only, asynchronous safety, nested navigation, persistence isolation, and responsive visual paths have no P0/P1 failure.
