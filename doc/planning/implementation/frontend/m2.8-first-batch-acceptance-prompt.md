# Prompt — M2.8 First-Batch Independent Acceptance

请作为独立验收 Codex，对 Odyssey 前端 **M2.8 第一批**进行严格验收。不要因为实现者自报门禁通过而直接 PASS；请自行读取当前代码、计划、规范、运行命令并使用真实浏览器验证。

## 验收范围

本批只验收已经实现且不依赖缺失 Knowledge Space API 的部分：

1. Flow / Configure mode；
2. Focus Mode；
3. root / Loop child Canvas context 与 session 隔离；
4. Loop child graph + layout 编辑和保存；
5. Reusable Tool inventory 来自真实 Agent aggregate；
6. root / Loop-child Agent Action 的 Tool bind/unbind；
7. Knowledge Space 在 API 缺失时显示真实 unavailable，不使用 mock；
8. 既有 M2.4–M2.7 能力无回归。

以下内容不应导致本批 FAIL，但必须记录为后续 blocker：

- Knowledge Space inventory、搜索、分页和绑定尚未完成，因为当前后端未提供 `GET /api/v1/knowledge-spaces`；
- Agent Action 与 Loop 的“从 Palette 新建并配置 draft”若仍 disabled，不属于本批阻断；已有真实节点的配置和 Loop 子画布必须可用；
- M2.9 autosave debounce、完整竞态恢复与 E2E hardening 不属于本批。

从仓库根目录自行运行：


任何一项失败，本批整体为 FAIL。记录通过/失败数量和失败测试名称，不要把“浏览器看起来能用”当作测试门禁替代品。

## 静态架构检查

确认：

- `document` 与 session 分离；mode/focus/context/selection/panel 不进入 save payload；
- root 与每个 Loop child 有明确、namespaced Canvas context；
- Vue Flow view model 不进入 schema/repository/API；
- Configure mode 的 topology 限制不是仅隐藏按钮，Canvas mutation capability 也被关闭；
- Loop child 的成功操作一次性替换 graph + layout，只增加一次 mutation sequence；
- rejected child command 保持整个 parent Agent document 不变；
- nested Loop 不会进入 Loop child graph；
- Tool 数据只来自 `document.reusableTools`；
- resource payload 使用独立 namespace，resource drop 不会创建 workflow node；
- Agent Action 的资源绑定只有一个 canonical config source，node/panel 不维护副本；
- 没有 fixture/mock/localStorage fallback 冒充 Knowledge Space API。

若实现与 `doc/frontend-engineering-guidelines.md` 冲突，按架构缺陷报告，不因功能可见而豁免。

## 真实浏览器验收矩阵

必须使用真实 API 返回的 Journey/Agent aggregate。若现有数据没有 Loop、Agent Action 或 reusable Tool，可以通过已经存在的正式 API/产品入口准备验收数据；不要修改产品代码注入 fixture。无法安全准备时标记 BLOCKED，并说明缺少的具体数据/API。

### A. Flow / Configure

1. 打开 Agent Workflow Editor，记录当前 graph/layout/revision。
2. Flow mode：节点可选择、移动、连接/删除规则保持可用。
3. 切到 Configure：仍可选择节点、打开 inspector、pan/zoom。
4. Configure 中尝试 Palette click/drop、节点移动、connect、Delete/Backspace：均不得修改 topology/layout。
5. 切回 Flow：原 selection、panel、viewport 应合理保留。
6. 单纯切换 mode 不增加 mutation sequence，不使 Save 变为 dirty。

### B. Focus Mode

1. 在有 selection、panel 和非默认 viewport 的状态进入 Focus。
2. App shell/palette 按冻结设计收起，Canvas 与右侧 panel 可继续使用。
3. 进入/退出不新增 route，不重建领域 document。
4. Exit Focus 与 Escape 均验证；退出后 selection、panel、viewport 和焦点返回合理。
5. 在 1024px 与 1440×900 检查无页面级不必要滚动、遮挡或 panel 丢失。

### C. Loop child Canvas

1. 选择真实 Loop，Inspector 中应存在 `Open Loop body`。
2. 进入后显示明确 root/Loop breadcrumb 和返回入口。
3. Loop Start/End 正确显示并不可删除；Loop Palette 不允许 nested Loop。
4. 添加 Task/Branch、移动节点、连接和删除；验证 graph/layout 同步变化。
5. pan/zoom 后返回 root，再进入同一 Loop，child viewport/selection 不污染 root。
6. 若存在两个 Loop，交替进入并验证两个 child session 不串。
7. 保存、刷新、重新进入：Loop body graph、layout、viewport 和 revision 持久化。
8. 构造非法 self-edge/cycle/boundary delete/nested Loop（可用 domain test 补充）：操作拒绝且 parent aggregate deep-equal。

### D. Reusable Tool binding

1. 确认资源列表来自真实 `AgentWorkflowEditorDocument.reusableTools`。
2. empty Agent 显示真实 empty state；不得出现示例 Tool。
3. 对已有 Agent Action：通过 drag 或等价 click 路径绑定 Tool。
4. Tool 只能进入 Tool zone；落到 Canvas pane 不创建 node。
5. 重复绑定不产生第二个 ID，不制造额外 mutation。
6. unbind 后 UI 与 canonical `reusableToolIds` 同步。
7. root 与 Loop-child Agent Action 各验一次。
8. Save → refresh 后绑定结果保持；revision 恰好按成功保存前进。

### E. Knowledge Space blocker behavior

1. 当前 OpenAPI 不存在 `GET /api/v1/knowledge-spaces` 时，UI 明确显示 unavailable。
2. 不发起虚构成功请求，不显示 fixture cards，不把网络失败伪装成 empty。
3. Console 不应因 unavailable 状态产生 warning/error。

### F. Regression

抽查：

- M2.4 Journey/Pattern/Slot/Guardrail 主要路径；
- M2.5 Workflow preview；
- M2.6 graph validation；
- M2.7 Start/End、Branch、Task、save/reload；
- assign/remove/reassign Agent 回归；
- 浏览器控制台无新增 warning/error。

## PASS / FAIL 规则

仅当以下条件全部满足才可给 **M2.8 First Batch: PASS**：

- 四项自动化门禁全绿；
- Flow/Configure capability 真正生效；
- Focus 状态可逆且不污染持久化数据；
- Loop 子画布至少完成一次真实 save/reload round trip；
- root/child session 与 graph/layout 不串扰；
- Tool 使用真实 aggregate，bind/unbind/duplicate/save/reload 正确；
- Knowledge Space 缺 API 时没有 mock fallback；
- 无 P0/P1 产品或架构问题；
- 控制台无新增 warning/error。

以下任一项直接 FAIL：

- 任一质量门禁失败；
- Configure 仍能修改 topology；
- root/Loop child state 串扰；
- Loop child graph 更新但 layout 丢失，或一次动作产生多次不一致 mutation；
- 保存/刷新丢失 Loop 或 Tool 配置；
- resource drop 被 Canvas 当作 node drop；
- 使用 mock/fixture 冒充真实 API；
- session/Canvas third-party state 进入保存 payload；
- 跨组件维护两份 Agent Action resource config。

Knowledge Space API 缺失本身不使“第一批”FAIL，但报告必须将完整 M2.8 标为尚未完成。
