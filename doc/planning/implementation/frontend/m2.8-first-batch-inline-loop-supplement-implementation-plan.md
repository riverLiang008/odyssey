# Odyssey M2.8 First Batch 补充计划 — Inline Expanded Loop 与配置面板

> Status: Implemented and locally verified  
> Scope: M2.8 first-batch visual/interaction remediation  
> Figma source: `Odyssey UI Drafts` (`1:2`)  
> Primary frames: `Agent Workflow Canvas — Focus Mode / Loop Expanded Inline + Configuration` (`477:157`) and `Agent Workflow Canvas — Focus Mode / Loop Expanded Inline Configure` (`477:312`)

## 1. Outcome

把当前“进入 Loop 后用 child Canvas 替换整个 root Canvas”的呈现改为 Figma 已确认的 **inline expanded compound Loop**：

```text
Root Start
   ↓
┌─ Loop compound container ──────────────────┐
│ Loop Start                                 │
│    ↓                                       │
│ Agent Action / Task / Branch               │
│    ↓                                       │
│ Loop End                                   │
└────────────────────────────────────────────┘
   ↓
Root End
```

用户始终能看见 Root Workflow 的边界；Loop Start/End 始终位于 Loop-owned 子框内。该变化只调整 Canvas presentation/session 和配置 UI，不改变已冻结的 Workflow/Loop JSON、API 或数据库 contract。

## 3. Frozen product decisions

### 3.1 Root and Loop ownership

- Root graph 继续只拥有 top-level `start`、`end` 和包括 `loop` 在内的普通 Workflow nodes。
- `loop_start`、`loop_end` 只存在于目标 Loop 的 `config.body.graph`。
- Loop body graph/layout 继续由 parent Loop node owned，不创建第二条 AgentWorkflow。
- Loop body 允许 Agent Action、Task、Branch；nested Loop 禁止。
- Loop Start/End 不可删除，且分别禁止 incoming/outgoing illegal edges。

### 3.2 Inline expansion is UI-only

新增的 expanded/collapsed 状态属于 editor session：

```ts
type LoopPresentationState =
  | { type: 'collapsed' }
  | { type: 'expanded-inline'; loopNodeId: UUID }
```

- 不写入 WorkflowGraph、CanvasLayout 或 save payload。
- V1 同时最多展开一个 Loop，避免多个 nested Vue Flow instance 争夺 keyboard、drag、pan 和 selection authority。
- 展开另一个 Loop 时，先稳定关闭当前 child interaction，再展开目标 Loop。
- 保存/刷新后默认 collapsed；Loop body 自身的 persisted viewport/layout 仍按现有 contract 恢复。

### 3.3 Replace context switching, preserve context isolation

当前 `activeCanvasContext = loop-body` 的领域/application 语义继续保留，用于将 child intents 路由到正确 Loop command；视觉上不再把 root projection 替换掉。

```text
Root Vue Flow context
└─ Loop compound renderer
   └─ isolated Loop child Canvas context
```

必须保持：

- root and child graph/layout adapter 独立；
- root and child viewport/selection/panel session 独立；
- Vue Flow store、DOM IDs、node IDs 和 handles namespaced；
- child event 显式携带 `loopNodeId`；
- child mutation 只通过既有 Loop application transaction 原子写回 parent Loop body；
- child failure 不修改 root graph、root layout 或 parent session。

禁止为了 inline 展示把 root nodes 与 child nodes flatten 成一张 persisted graph。

### 3.4 Interaction semantics

- Flow mode：Loop collapsed node 可被移动、连接、选择或删除；展开后可编辑 child topology。
- Configure mode：禁止 node move/connect/delete；选择 Loop 打开 Loop Inspector；选择 child node 使用既有 node configuration UI。
- `Expand/Open Loop Body`：将目标 Loop 设置为 `expanded-inline` 并将 child body 居中到 compound container。
- `Collapse`：终止 child transient interaction、清除或保存 child selection session，并恢复 collapsed Loop renderer。
- 已展开时 Inspector 不再提供会进入替代式 child page 的 `Open Loop Body`。按 Figma intent 将该动作规范为 `Focus Loop Body`：仅聚焦/居中当前 inline child Canvas。
- Escape 优先关闭临时交互/面板；若无临时交互且 Loop expanded，则 collapse；Focus Mode 的退出规则保持现有可访问行为。
- 删除 expanded Loop 前使用既有 destructive node deletion path；成功后清理 orphan child session。

## 4. Loop configuration panel

Loop Inspector 按 Figma `477:157` 实现，且只拥有 settings draft：

- Name；
- Maximum turns；
- Exit condition variable；
- Operator；
- Comparison value；
- Body summary（node/edge count，说明包含 Loop Start/End）；
- Focus Loop Body；
- Remove Loop。

### 4.1 Contract mapping

- `maxTurns` 必须为正整数。
- V1 exit condition 固定为 `variable_comparison`。
- variable 必须引用当前 Agent 中存在且类型兼容的真实 Variable。
- operator/value 必须通过共享 runtime schema；不能以字符串拼装绕过 validation。
- Name 使用已存在的 typed node identity/config update path；Loop settings 使用专用 `updateWorkflowLoopSettings`。
- 不得通过通用 config object 替换 Loop config，以免覆盖 `body.graph` 或 `body.layout`。

### 4.2 Draft and submission

- 表单 draft 为 local/session-only，不进入 save payload。
- Cancel/close 丢弃未提交 draft，不产生 dirty state。
- Submit 先在 typed form mapper 中验证，再以一次 application action 提交 name/settings changes。
- 若 name 与 settings 同时提交，需要 transaction-like application action；任一项失败时 document 保持原样。
- 成功只增加一次 mutation sequence。
- Body summary 始终从 canonical Loop body 派生，不保存副本。

## 5. Canvas composition strategy

### 5.1 Root projection

扩展 `workflowCanvasAdapter` 的 presentation projection，使 root Loop node 可以产生两种 renderer view model：

- collapsed Loop node；
- expanded compound Loop container shell。

该 view model 只描述 presentation、bounds 和 target Loop ID；不得嵌入或复制 persisted child graph。

### 5.2 Child Canvas host

新增专用 presentational host，例如：

```text
WorkflowCanvas
└─ InlineLoopCanvasHost
   ├─ Loop header / Collapse
   └─ WorkflowCanvas (child namespace)
```

Child host 接收：

- `loopNodeId`；
- child graph/layout；
- mode；
- child selection/session；
- typed intent callbacks。

Child host 不读取 store、不直接修改 parent document，也不把 Vue Flow objects emit 到 application layer。

### 5.3 Container sizing and layout

- Figma 1440×960 是参考状态，不把 `800×600` 写成业务常量。
- compound bounds 由 child content bounds、header、安全 padding 和当前 viewport 计算，使用命名 layout constants/tokens。
- 首批支持一个 expanded Loop；对于超出容器的 child graph，使用 child-local pan/zoom，不无限撑大 root Canvas。
- Root connector 只连接 Root Start → Loop container boundary → Root End，不连接 child Loop Start/End。
- Child connectors 只存在于 container 内部。
- root/child hit testing、wheel、pan、drop 和 connect 必须停止错误的事件冒泡，但不能破坏合法 child interaction。

## 6. State and event routing

### 6.1 Session changes

把当前单一 `selectedNodeId/selectedEdgeId` 的使用收敛为 context-aware session access。继续复用既有 `contextSessions`，但 active presentation 不得通过替换整个 root graph 实现。

建议提供窄 actions：

```text
expandLoopInline(loopNodeId)
collapseInlineLoop()
focusExpandedLoop(loopNodeId)
selectCanvasNode(context, nodeId)
selectCanvasEdge(context, edgeId)
```

不得增加互相矛盾的 `isLoopOpen/isChildActive/isExpanded` booleans。

### 6.2 Typed intents

所有 child Canvas intent 必须带 context：

```ts
type ContextualWorkflowCanvasIntent = {
  context: { kind: 'root' } | { kind: 'loop-body'; loopNodeId: UUID }
  intent: WorkflowCanvasIntent
}
```

View/container 只负责 dispatch；store 根据 context 调用 root command 或既有 Loop transaction。

### 6.3 DnD arbitration

- child node drop 只能创建 Loop-allowed node kinds；Loop payload稳定返回 `NESTED_LOOP_FORBIDDEN`。
- child resource drop 只绑定 child Agent Action。
- valid child drop 必须阻止 root pane 二次消费。
- root drop 不能误投到 child graph。
- Configure mode 中 root/child node/resource mutation 全部被 capability gate 拒绝。

## 7. Implementation sequence

### Step 0 — Baseline and contract tests

- 记录当前 M2.8 green gates 和真实 acceptance aggregate IDs；
- 增加 root graph 与 Loop body ownership regression tests；
- 证明 save input 中不存在 expanded/collapsed/session state。

Gate：现有 M2.8 测试保持绿色，新增测试先描述目标行为。

### Step 1 — Introduce inline Loop presentation state

- 增加 discriminated presentation state；
- 增加 expand/collapse/focus actions；
- 复用并整理 context sessions；
- 删除 View 依赖“activeGraph 替换 root graph”的视觉切换路径。

Gate：root/Loop A/Loop B selection、panel、viewport state 不串扰；切换 Loop 不产生 document mutation。

### Step 2 — Build compound Loop renderer and child host

- root Canvas 投影 expanded Loop shell；
- child Canvas 使用独立 Vue Flow namespace；
- 实现 Figma header、Loop Body、Collapse、Loop Start/End visual hierarchy；
- root routes 与 child routes 分层渲染。

Gate：Root Start/End 始终在 compound container 外，Loop Start/End 始终在内；root/child IDs 和 handles 不冲突。

### Step 3 — Route child interactions through contextual intents

- move/connect/create/delete/viewport/select 全部携带 context；
- 复用 M2.8 Loop application transactions；
- 完成 DnD propagation/preflight；
- Configure capability 同时覆盖 root/child。

Gate：每个合法 child action只产生一次 parent Loop body replacement 和一次 dirty mutation；失败保持 parent/child document unchanged。

### Step 4 — Implement Loop Inspector

- 按 Figma 实现 Name、Maximum turns、Exit Condition、Body Summary、Focus、Remove；
- typed draft validation；
- settings-only/transaction-like submit；
- loading/invalid/disabled/conflict presentation；
- keyboard/focus return。

Gate：配置提交不改变 body graph/layout；无效变量、operator/value 或 maxTurns 不修改 document。

### Step 5 — Configure-mode expanded child nodes

- 按 Figma `477:312` 复用既有 node renderer/configuration component；
- Agent Action resource zones 使用 canonical resource bindings；
- 不在 Canvas component 内维护第二份 config；
- child node configure 仍通过 context-aware typed commands。

Gate：Flow/Configure 切换不改变 graph/layout；Configure 不允许 move/connect/delete。

### Step 6 — Responsive, focus and persistence verification

- 1440×960 对齐 Figma；
- 1024px 下保持 Root/Loop hierarchy、Inspector 或 overlay 可用；
- Focus enter/exit 后 root/child viewport、selection 和 keyboard focus 可恢复；
- save → refresh 后 graph/layout/settings/resources 恢复，UI-only expansion 默认 collapsed。

Gate：无水平页面溢出；child-local viewport 不被 root move/resize 覆盖。

### Step 7 — Quality gates and browser acceptance

运行：

```text
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

并使用真实 Web API 完成浏览器验收矩阵。

## 8. Required tests

### 8.1 Pure/domain/application

- Loop settings update preserves body graph/layout；
- name + settings atomic submit success/failure；
- child mutation success performs one parent replacement；
- child rejection leaves parent and child unchanged；
- nested Loop rejection；
- expanded UI state absent from save payload。

### 8.2 Adapter/component

- collapsed/expanded Loop projection；
- root/child connector ownership；
- context-aware select/move/connect/delete intents；
- child viewport round-trip；
- Loop Inspector validation and derived body summary；
- Focus Loop Body only changes viewport/session；
- Collapse clears transient interaction without mutating document；
- Configure disables root and child topology mutation。

### 8.3 Browser matrix

1. Root Canvas 显示 Root Start → collapsed Loop → Root End；
2. Expand 后 Root Start/End 仍可见，Loop Start/End 位于 container 内；
3. child create/move/connect/delete/save/refresh；
4. root/child selection、viewport、panel 不串扰；
5. Flow/Configure/Focusing combinations；
6. Loop settings edit、invalid validation、save/reload；
7. root and child Tool/Knowledge Space bind/unbind；
8. nested Loop drag/click/keyboard creation 均被拒绝；
9. Collapse/re-expand 恢复同一 session，刷新后使用 persisted child viewport；
10. 1024px 与 1440px visual inspection；
11. console 无 warning/error。

## 9. Acceptance criteria

M2.8 first-batch supplement 只有在以下条件全部满足时才通过：

1. Root Start/End 与 Loop Start/End 的视觉和数据归属明确且正确；
2. Loop body 以 inline compound container 展示，不再替换整个 Root Canvas；
3. parent/child graph、layout、viewport、selection、panel 和 Vue Flow namespaces 保持隔离；
4. Inspector 只更新 name/settings，不覆盖 body；
5. child mutation 继续使用既有 typed Loop transactions；
6. Flow/Configure capability 同时覆盖 root 和 child；
7. resource/node DnD 不串扰，nested Loop 可靠拒绝；
8. session-only expansion state 不进入 API payload；
9. save/reload 和 revision 行为保持正确；
10. lint、typecheck、test、build 全绿，真实浏览器矩阵通过。

## 10. Explicit non-goals

- 不修改后端 API、schema 或数据库；
- 不支持 nested Loop；
- 不把 Loop body flatten 到 root graph；
- 不支持同时展开多个 Loop；
- 不实现 Loop runtime/evaluator；
- 不实现任意 graph cycle；
- 不在本补充批次扩展完整 Task/Branch 产品配置；
- 不引入 Tailwind，也不直接复制 Figma React reference code。

## 11. Primary risks

| Risk | Required mitigation |
| --- | --- |
| nested Vue Flow event/store collision | 独立 namespace/context，contextual intents，browser test |
| child wheel/drop 被 root 二次消费 | central DnD arbitration + deliberate propagation boundary |
| inline renderer flatten persisted graphs | adapter-only compound presentation；domain contract regression test |
| settings submit overwrites body | settings-only command/atomic application action |
| expanded container creates unbounded page size | fixed responsive host + child-local pan/zoom |
| Configure renderer duplicates config state | canonical store document + local draft only |
| Figma absolute coordinates become magic numbers | design tokens and named layout constants |

## 12. Implementation result (2026-08-29)

- Inline expansion is stored only in the editor session and is absent from persistence payloads.
- Root Start/End render outside `InlineLoopCanvas`; Loop Start/End and the canonical child graph render inside its isolated `loop-{loopNodeId}` Canvas.
- Loop Name, Maximum turns and Exit condition use one typed settings update that preserves the owned body graph/layout.
- Configure mode expands the selected child Agent Action from canonical node data and shows Model, Goal, Knowledge Spaces and Toolbox summaries; no duplicated configuration document was introduced.
- The accepted real aggregate was verified in Flow, Configure and Focus modes without saving or mutating acceptance data.
- Root sibling nodes remain visible and selectable while the target Loop is expanded; selecting one switches interaction authority back to the root context without collapsing the Loop.
- Focus Mode now uses an explicit page-to-App-Shell presentation contract, hiding global navigation and the product header while preserving the editor toolbar, Canvas and Inspector.
- Quality gates: lint PASS; typecheck PASS; test PASS (`42` files / `284` tests); production build PASS (`3012` modules).
