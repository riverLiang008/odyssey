# Odyssey M2.2 Completion Report

> Status: Complete; awaiting acceptance  
> Completed: 2026-08-12  
> Scope: App Shell, Router, Journey/Workflow store boundaries, route loading and failure presentation

## 1. Outcome

M2.2 is implemented. Odyssey now preserves the existing Landing page while providing the Figma-designed application shell and the canonical navigation path:

```text
Landing `/`
→ Journey List `/journeys`
→ Journey Editor `/journeys/:journeyId?tab=...`
→ Agent Workflow Editor `/journeys/:journeyId/agents/:agentId`
```

Journey and Agent editor routes load the frozen M2.1 aggregates through the `EditorRepository` port. Persisted documents, editor session state, route state, and persistence state are separate and automatically tested.

## 2. Implemented boundaries

### Application shell and routes

- retained `/` as the independent Landing / Workspace Entry;
- made **Open workspace** navigate to the Figma `OdyJourney — Journey List` at `/journeys`;
- added shared `AppShell`, global navigation, product header and route outlet;
- added named Journey List, Journey Editor, Agent Workflow Editor and catch-all routes;
- added runtime UUID parsing, Journey tab allowlist/normalization and typed route-location helpers;
- kept preview, selection, panel, mode and focus out of the URL.

### Composition and read model

- created one application-level `EditorRepository` instance and provided it through a typed injection key;
- populated the in-memory adapter from fresh deterministic M2.1 fixtures;
- projected the M2 Journey fixture into a read-only Journey List summary instead of introducing an unfrozen list DTO or fake CRUD port;
- kept create/search/filter actions explicitly disabled until their application use cases exist.

### Store boundaries

`journeyEditor` and `workflowEditor` each expose three explicit state groups:

```text
document      persisted M2.1 aggregate
session       temporary editor interaction state
persistence   load/save status and modeled RepositoryError
```

Both stores:

- orchestrate repository loads outside components;
- clear the previous document before a new identity load;
- bind requests to `AbortSignal` and a monotonically increasing request identity;
- prevent aborted or stale responses from committing state;
- reset temporary session state on identity change/dispose;
- expose save selectors that contain only frozen repository input fields;
- unwrap Vue proxies before cloning repository payloads.

The Workflow store additionally validates the Agent summary belongs to the requested Journey before loading the Agent aggregate, then rechecks aggregate ownership.

The returned Agent aggregate must match both the requested `journeyId` and `agentId`; an identity mismatch is rejected as `RESPONSE_INVALID` before it can become the active document or a save input.

### Failure presentation

- added one reusable `RouteBoundary` for loading, not-found and modeled repository errors;
- maps network, invalid response, conflict and aborted errors to accessible user-facing copy;
- supports retry through the current store load action;
- keeps not-found separate from retryable transport/contract failures;
- added an explicit unknown-route page with a safe return to `/journeys`.

## 3. Figma implementation notes

The implementation used formal design context from:

- `OdyJourney — Journey List` (`247:33`);
- `OdyJourney — Resource Library Open` (`59:2`);
- `Research Agent — Workflow Canvas` (`62:2`).

Verified design structure includes:

- 204 px desktop global navigation;
- 58 px implemented product header within the Figma 58–64 px range;
- canvas/panel/surface hierarchy and semantic accent/status colors;
- Journey toolbar, grouped cards and shared editor panel/canvas regions;
- 1440 px desktop composition and a dedicated narrow-desktop treatment.

The copied hidden Knowledge Space layers inside Figma `247:33` were deliberately ignored according to the canonical IA. React/Tailwind output was not copied and Tailwind was not added.

## 5. Stable downstream interfaces

M2.3 and M2.6 may rely on:

- route names and `routeLocations` helpers;
- `JourneyTab` and route runtime parsers;
- the application `EditorRepository` provider;
- `useJourneyEditorStore` document/session/persistence split;
- `useWorkflowEditorStore` document/session/persistence split;
- store `load`, `dispose` and persisted-only `toSaveInput` actions;
- the shared App Shell and editor-region CSS structure;
- `RouteBoundary` for modeled load failures.

Future domain work must add command actions to these stores rather than allowing components to mutate `document` directly.
