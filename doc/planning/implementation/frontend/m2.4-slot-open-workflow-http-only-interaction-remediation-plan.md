# M2.4 Slot Open Workflow 与纯 Web API 交互纠偏计划

> Status: Frontend implementation complete; live API acceptance blocked by canonical response mismatch  
> Scope: OdyJourney Execution 页面、Agent Slot 交互、Workflow 跳转与 Execution Template 数据来源  
> Engineering baseline: [`frontend-engineering-guidelines.md`](../../../frontend-engineering-guidelines.md)  
> Supersedes: 旧 M2.4 文档中“点击空 Slot 即创建 Agent 并进入 Workflow”的交互描述

## 1. 目标

本计划用于完成 M2.4 当前实现的交互纠偏，并冻结后续编码依据：

1. 左键点击 Slot 只更新选择状态，不创建 Agent、不修改 Journey、不跳转页面。
2. 空 Slot 与已配置 Slot 使用一致的右键菜单结构。
3. 用户只在右键选择 `Open workflow` 时进入 Workflow 流程。
4. 空 Slot 的 Agent 创建、最小 Workflow 初始化、Slot 分配必须由一个后端原子命令完成。
5. 正式运行时的 Journey、Agent、Workflow 与 Template 数据全部来自 Web API，不允许 mock、fixture 或内存仓库静默兜底。

## 2. 已冻结的产品行为

### 2.1 左键选择

左键点击任意 Slot：

```text
click Slot
→ emit select-slot intent
→ 更新 selectedSlotId（仅 editor session）
→ 不调用 repository
→ 不改变 Journey aggregate
→ 不导航
```

未来左键选择后可在页面左下区域展示 Slot 配置面板。该面板已有 Figma 方向，但不属于本次必须交付内容；当前组件和 store API 不得阻碍后续接入。

### 2.2 右键菜单

空 Slot 与已配置 Slot 使用相同的菜单容器、分组、顺序和视觉样式。菜单能力根据 Slot 当前状态决定，不通过创建两套互相漂移的菜单实现。

| 菜单项 | 空 Slot | 已配置 Slot |
| --- | --- | --- |
| Open workflow | 可用；执行原子创建并进入新 Workflow | 可用；进入已有 Workflow |
| Replace agent | 不可用 | 可用 |
| Duplicate | 不可用 | 可用 |
| Save as template | 不可用 | 按当前 Agent 能力显示 |
| Remove agent | 不可用 | 可用 |
| Pattern Slot 操作 | 由 Pattern strategy/capability 决定 | 由 Pattern strategy/capability 决定 |

不可用操作采用明确 disabled 状态并提供可理解的语义，不用点击后才报错。菜单必须支持键盘打开、方向键导航、Enter 执行和 Escape 关闭。

### 2.3 Open workflow：已配置 Slot

```text
open-slot-workflow(slotId)
→ store 从当前 Journey aggregate 解析 Slot
→ 验证 Slot 具有 agentId
→ 导航至该 Agent 的 Workflow Editor
```

该路径不创建 Agent，也不写 Journey。

### 2.4 Open workflow：空 Slot

```text
open-slot-workflow(slotId)
→ store 验证 Slot 仍为空并读取 expectedRevision
→ repository 调用 createJourneyAgent Web API
→ 后端在一个事务中：
   创建最小 Agent identity
   → 初始化 Start → End Workflow
   → 将 Agent 分配给 Slot
   → 更新 Journey revision
→ 前端校验响应并替换最新 Journey aggregate
→ 导航至返回 Agent 的 Workflow Editor
```

Agent name 等模板元数据不在此流程中向用户索取。Agent 默认与当前 Journey 一起保存；只有后续执行 `Save as template` 时才进入模板元数据流程。

## 3. 数据与架构约束

实现必须遵守：

```text
Component event
→ typed intent
→ store/application orchestration
→ typed repository port
→ HttpEditorRepository
→ Web API
```

- Component 不直接调用 `fetch`、repository 或 router。
- Component 不直接修改 Slot、Agent 或 Journey。
- `selectedSlotId`、context menu、loading target 属于 UI session，不进入保存 payload。
- API 响应必须经过 runtime validation 和 DTO/domain mapping 后才能写入 store。
- 正式运行时只创建 `HttpEditorRepository`；`InMemoryEditorRepository` 只允许作为测试替身。
- 禁止网络失败后自动切换 mock/fixture/in-memory 数据。
- 请求失败时保留原 Journey aggregate，不导航，并显示 repository error 对应的 UI 反馈。

建议冻结以下 typed intent：

```ts
type JourneySlotIntent =
  | { type: 'select-slot'; slotId: string }
  | { type: 'open-slot-workflow'; slotId: string }
```

最终业务分支由 store 基于最新 aggregate 判断，展示组件不得用 DOM 状态或显示文案推测 Slot 是否为空。

## 4. Execution Templates 数据规则

当前硬编码 Execution Template 卡片不能进入正式实现。

- 如果后端已有 Template list API：通过 repository port 获取、runtime validate，并覆盖 loading、empty、error 状态。
- 如果本批没有对应 API：移除静态假卡片，展示明确的 unavailable/empty state；不得伪造可拖拽数据或伪造成功操作。
- Template API 的缺失不阻塞 Slot `Open workflow` 纠偏，两条路径分别验收。
- 后续接入 API 时，页面仍只消费 domain/view model，不直接依赖 HTTP DTO。

## 5. 异步与一致性要求

空 Slot 创建属于持久化命令，必须覆盖以下情况：

1. 请求期间同一 Slot 的 `Open workflow` 禁止重复提交。
2. 请求携带当前 `expectedRevision`，revision conflict 映射为稳定的 repository/UI error。
3. 路由切换或 Journey 切换后，旧响应不得覆盖新页面状态；使用 abort 或 request sequence/stale-result ignore。
4. 只有响应仍对应当前 Journey、当前请求且通过校验时，才能替换 aggregate 并导航。
5. 创建成功但导航失败时保留服务端已确认的新 aggregate，并提供可重试导航入口，不能再次创建 Agent。
6. 请求失败、响应非法或 conflict 时，不得留下前端半创建 Agent、临时 agentId 或局部 Slot 修改。

## 6. 预计修改范围

实施时先以仓库实际路径为准，预计涉及：

- `AgentSlot.vue`：左键仅派发 `select-slot`；右键派发菜单 intent。
- `AgentSlotContextMenu.vue`：统一空/已配置 Slot 菜单结构及 disabled capability。
- Journey Execution container/view：接收 typed intent，不再在 Slot click 中创建或导航。
- Journey editor Pinia store：编排选择、已有 Workflow 导航、空 Slot 原子创建及异步保护。
- `EditorRepository` port 与 `HttpEditorRepository`：复用或校正 `createJourneyAgent`，保证响应校验与错误归一化。
- `ExecutionTemplateLibrary.vue`：删除硬编码运行时数据，切换为 API-backed state 或显式 unavailable/empty state。
- 相关 component、store、repository、browser tests。

本计划原则上不修改 Pattern domain strategy，也不在前端实现 Start/End Workflow 初始化规则；该原子业务由后端命令负责。

## 7. 实施批次

### Batch A — 行为锁定与回归测试

- 先补失败测试，证明当前左键空 Slot 会错误创建/跳转。
- 锁定统一右键菜单的状态矩阵。
- 锁定 configured/empty 两条 `Open workflow` 分支。
- 锁定 runtime 不得读取 fixture 或静态 Template 数据。

### Batch B — Slot intent 与菜单纠偏

- 将 Slot 左键改为纯选择 intent。
- 将 `Open workflow` 暴露给空 Slot 和已配置 Slot。
- 统一菜单结构、disabled 状态、focus 与 Escape 行为。
- 保持 Pattern capability 驱动 add/remove/move 等 Slot 操作。

### Batch C — Web API 原子流程接入

- configured Slot 直接导航已有 Workflow。
- empty Slot 通过 store 调用 `createJourneyAgent`。
- 接入 expected revision、loading target、abort/stale-result guard 和错误映射。
- 使用服务端返回的最新 Journey aggregate 更新 store，成功后导航。

### Batch D — 移除正式运行时 mock 数据

- 删除 Execution Template 静态卡片数据及虚假 DnD 行为。
- 有 API 则接 repository；无 API 则交付明确空态/不可用态。
- 检查 repository factory，确认正式应用无 in-memory/fixture fallback。

### Batch E — 验证与文档同步

- 运行 lint、typecheck、unit/component/integration tests 与 production build。
- 使用真实浏览器连接本地 Web API 验收关键路径。
- 更新旧 M2.4 计划中冲突的点击行为与完成报告。

## 8. 测试与验收矩阵

### 8.1 Component

- 左键空 Slot 只 emit `select-slot`。
- 左键已配置 Slot 只 emit `select-slot`。
- 两种 Slot 的右键菜单结构一致。
- 空 Slot 的 `Open workflow` 可用，Agent-only 操作 disabled。
- context menu 可通过鼠标和键盘操作，关闭后焦点返回 Slot。

### 8.2 Store/Application

- configured Slot 不调用 create API，只导航已有 `agentId`。
- empty Slot 只调用一次 create API，并携带正确 journeyId、slotId、expectedRevision。
- 成功响应先更新 aggregate，再导航返回的 Agent。
- request failure、invalid response、revision conflict 均不导航、不局部修改 aggregate。
- 双击/重复触发不会创建两个 Agent。
- Journey 切换后的旧响应不会污染当前状态。

### 8.3 Repository

- request/response contract 与 Web API 一致。
- 响应经过 runtime validation。
- 404、409、422、网络错误和非法响应映射到稳定 `RepositoryError`。
- production repository factory 不回退到 in-memory/fixture。

### 8.4 Browser E2E

使用真实后端和非 mock 网络验证：

1. 新建 Journey，右键空 Slot，选择 `Open workflow`。
2. Network 中只出现一次原子创建请求。
3. 返回后进入包含 Start → End 的 Workflow Editor。
4. 返回 Journey 后该 Slot 已配置；再次 `Open workflow` 进入同一个 Agent，不重复创建。
5. 左键另一个空 Slot 不产生写请求、不跳转。
6. API 失败时停留原页面并可重试。
7. Execution Templates 无 API 数据时只显示明确空态，不显示硬编码卡片。

## 9. Definition of Done

- [ ] 左键 Slot 只选择，不创建、不保存、不导航。
- [ ] 空/已配置 Slot 使用统一右键菜单结构。
- [ ] 两种 Slot 都可以通过 `Open workflow` 进入正确流程。
- [ ] 空 Slot 使用单个后端原子命令创建 Agent、初始化 Start → End、分配 Slot。
- [ ] store 只接受已通过 runtime validation 的最新 Journey aggregate。
- [ ] 正式运行时无 mock、fixture、静态 Template 或 in-memory fallback。
- [ ] loading、empty、error、disabled、conflict 与 stale response 状态均已处理。
- [ ] 行为测试、repository 测试和真实浏览器验收通过。
- [ ] `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 通过。
- [ ] 与本计划冲突的旧文档已同步，M2.4 完成报告已更新。

## 10. 非目标与后续工作

本批不包含：

- 左键选择 Slot 后的左下配置面板完整实现；
- Agent Template 全生命周期 UI；
- 自定义 Pattern；
- M2.5 Workflow Preview；
- 在前端拼装或保存最小 Start → End Workflow。

如果 Execution Template list API 尚不存在，应另行冻结其跨端 contract；不得以此扩大本次 Slot 修复范围，也不得用 mock 数据掩盖缺失能力。

## 11. 实施结果与当前 Blocker

前端已完成：

- 左键 Slot 改为纯选择；
- 空/已配置 Slot 统一菜单结构，`Open workflow` 均可用；
- 空 Slot 只从 `Open workflow` 调用原子创建接口；
- Execution Templates 静态假数据已替换为明确的 Web API unavailable state；
- production repository factory 保持纯 `HttpEditorRepository`；
- component、view、store 和 repository 回归测试通过。

真实 Web API 验收发现后端最小 Workflow 的普通边返回：

```json
{ "sourceHandleId": null }
```

共享 canonical `workflowEdgeSchema` 要求 `sourceHandleId` 为 UUID string 或省略，`null` 会被 runtime validation 正确拒绝为 `RESPONSE_INVALID`。后端需输出符合 canonical schema 的边；前端不得放宽 validator 或静默删除非法字段。修复后重新执行第 8.4 节浏览器验收即可关闭本计划。
