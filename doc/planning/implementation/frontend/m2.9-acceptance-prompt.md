# Prompt — Independent M2.9 Acceptance

请对 Odyssey M2.9 做独立验收。不要只做静态 review；必须使用真实 Web API 和真实 Chromium 浏览器，不允许用 fixture、mock、localStorage 或 jsdom 冒充 browser E2E。

先完整阅读：

1. `AGENTS.md`
2. `doc/frontend-engineering-guidelines.md`
3. `doc/planning/implementation/frontend/m2.9-autosave-races-e2e-adr-implementation-plan.md`
4. `doc/planning/implementation/frontend/m2.9-completion-report.md`
5. `doc/architecture/frontend/m2-interaction-proof-architecture-decision.md`

验收环境默认：

- Frontend: `http://127.0.0.1:4173`
- API: 使用前端当前配置的真实 `/api/v1`
- retained Journey: `3b5613a3-7287-4733-bade-0ca885bd1673`
- retained Agent: `ea0d292f-5a78-4568-a6ea-fe6d111cc45a`

开发环境提供一次性、不会进入 production 的保存故障注入。验证 Retry 前在浏览器控制台执行：

```js
window.__ODYSSEY_ACCEPTANCE__.failNextSave()
```

它只让下一次 Journey 或 Workflow save 返回 `NETWORK_FAILED`，之后自动恢复；可用 `window.__ODYSSEY_ACCEPTANCE__.clear()` 主动清除。不要通过停止整个 API 服务替代这一确定性路径。

请先记录 branch、commit、dirty worktree、Node/pnpm、browser、Frontend/API URL。然后执行：

```text
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

任一门禁失败，结论必须为 FAIL。

必须覆盖以下矩阵：

1. Journey 连续三次合法 Pattern mutation 在 800ms debounce 后只保存 latest snapshot；
2. Workflow root 与 Loop child mutation 均自动保存，刷新后等价恢复；
3. manual Save now 复用 autosave pipeline，不并行发第二个请求；
4. saving 期间继续编辑，旧 success 不覆盖新 document，并只产生一个 follow-up；
5. follow-up 使用首次 success 返回的新 revision；
6. network/invalid-response failure 保留最新本地数据，Retry 保存最新 snapshot；
7. 双 session 制造真实 `REVISION_CONFLICT`，确认 autosave 停止且本地数据保留；
8. Reload server version 使用应用内二次确认，确认后才丢弃本地状态；Escape/Back 返回 conflict choices；
9. Overwrite 使用应用内二次确认，先 load 最新 revision，再做一次 CAS save；若再次 conflict 仍停留在可恢复状态；
10. dirty/saving 内部导航先 flush；failure/conflict 阻止并显示应用内 Leave without saving dialog；Stay/Escape 保持当前页面，Leave 才继续导航；
11. dirty/saving/failed/conflict 的 browser refresh/close 有 native protection；clean 无提示；
12. Guardrail add/remove、empty Slot Open workflow、Template instantiate、occupied Slot removal 前先 flush local Pattern dirty；成功后不 double-save；
13. rejected command、selection、panel、mode、focus、context 不触发 autosave；
14. save payload 不含 session、router、Vue Flow VM、timer 或 DnD state；
15. 1024×900 与 1440×900 可用，无横向页面溢出；Focus/Configure/Loop context 中状态与恢复入口可见；
16. console 无 warning/error/unhandled rejection；
17. M2.4–M2.8 关键路径无回归。

特别做 code review：

- shared persistence union 是否真的是唯一状态源；
- Journey/Workflow 是否共享 coordinator，而不是复制 timer race；
- stale/abort 是否同时用 request identity 防护；
- server-authoritative command 是否先 flush、后使用最新 revision；
- conflict 是否存在任何自动改 revision 后静默覆盖路径；
- route guard 是否只注册一次并在 unmount 清理；
- document/session/canonical payload 边界是否保持。

输出格式：

- `M2.9 Acceptance: PASS|FAIL`
- Environment
- Quality gates
- Acceptance matrix（逐项 PASS/FAIL/BLOCKED + evidence）
- Findings（P0/P1/P2，文件与行号、复现、期望、实际、最小修复）
- Browser/API evidence（IDs、revision、request count、reload result）
- Console/responsive/performance evidence
- Cleanup（默认 retained；删除前必须询问用户）
- Verdict

PASS 必须满足全部强制项且没有 P0/P1。环境缺失或真实冲突/浏览器路径未执行时只能 BLOCKED/FAIL，不能以 unit test 替代。
