# Odyssey M2.6 Independent Acceptance Checklist

> Milestone: M2.6  
> Scope: pure Workflow domain commands and graph validation; no editable Canvas visual acceptance

## 1. Quality gates

Run from repository root:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

All must pass. Any failing test makes M2.6 acceptance fail.

## 2. Architecture acceptance

- Inspect `apps/web/src/domain/workflow/` for forbidden imports: Vue、Pinia、DOM、Vue Flow、router、repository、HTTP。
- Confirm persisted Workflow types come from `@odyssey/schemas` rather than private duplicates。
- Confirm schema changes add type exports only and do not change persisted JSON shape。
- Confirm graph commands do not accept or modify CanvasLayout/session state。
- Confirm Workflow store replaces graph only from successful command results。

## 3. Domain acceptance

Verify automated tests cover:

- minimal Agent graph is exactly Start → End and execution-ready；
- minimal Loop body is exactly Loop Start → Loop End and execution-ready；
- Start/End and Loop boundaries cannot be deleted or duplicated；
- missing endpoint、self-edge、semantic duplicate and duplicate edge ID are rejected；
- arbitrary back-edge/cycle is rejected without changing source graph；
- Branch requires an owned Case/Default handle；
- non-Branch handle is rejected；
- each Branch handle has at most one outgoing edge structurally；
- missing Branch routes are readiness errors rather than structural corruption；
- Branch Case removal atomically removes its outgoing route；
- Loop body invalidity/nested Loop is rejected without changing parent；
- `updateLoopBody` accepts only child graph and preserves nested placements/viewport；
- Loop child node/edge commands operate on graph only and do not accept CanvasLayout；
- `UpdateNodeConfigIntent` excludes Loop entirely；
- Store exposes separate settings-only and graph-only Loop actions；
- disconnected nodes may exist as draft but make graph not execution-ready；
- every successful generated command sequence preserves structural invariants。

## 4. Store acceptance

- Load a validated Agent Workflow document through the existing repository boundary。
- Apply a successful add node action and confirm only `document.workflow` changes。
- Confirm layout and Agent revision are unchanged by domain mutation。
- Attempt deleting Start and confirm graph/save projection remain unchanged with stable domain error。
- Select an ordinary node, remove it, and confirm selection/panel reconciliation。
- Confirm validation reports、last domain error and session are absent from `toSaveInput()`。

## 5. Regression acceptance

- Existing M2.4 Pattern/Slot/DnD/Guardrail/Template tests remain green。
- Existing M2.5 Preview/navigation tests remain green。
- Existing fixtures parse and validate without migration or mock fallback。
- No new browser console check is required because M2.6 adds no visual/browser interaction。

## 6. Failure conditions

Acceptance must fail if any of these are found:

- component/store directly mutates `workflow.nodes` or `workflow.edges`；
- failed command returns or commits a partial candidate；
- UI text is used as domain error identity；
- Canvas position participates in graph validation；
- cycle is permitted because it visually resembles a Loop；
- Branch route target is duplicated inside Branch config；
- structurally valid draft is automatically treated as execution-ready；
- Vue Flow types leak into schemas/domain/repository payload；
- any quality gate fails。
