# M2.5 Completion Report — Read-only Workflow Preview

> Status: Implementation complete; ready for independent acceptance  
> Completed: 2026-08-22  
> Scope: Journey Editor read-only Workflow Preview and nested Agent Workflow navigation

## Delivered

- A configured Execution Slot opens a single picture-in-picture Workflow Preview without changing the route.
- An active Input or Output Guardrail uses the same Preview path and the same single-instance invariant.
- Selecting an empty Slot closes the current Preview without creating or loading an Agent.
- The Preview loads the persisted Workflow through `EditorRepository.loadAgentWorkflow`; no mock or fallback Workflow is used at runtime.
- `Open canvas` navigates through the typed Agent Workflow route; the existing context-menu `Open workflow` path remains unchanged.
- The Preview is structurally read-only: it exposes no drag, connect, delete, configure, drop, or persistence handlers.
- Loading, retryable error, close, Agent switch, request abort, stale-response rejection, Journey unload, and removed-Agent reconciliation are owned by the Journey store.
- The Preview graph is projected by a pure SVG adapter with uniform fit-to-bounds scaling, edge-to-node boundary anchoring, arrow markers, and diagnostics for invalid placements or endpoints.

## Main implementation boundaries

- `apps/web/src/canvas/workflow-preview/`: pure graph/layout projection and tests.
- `apps/web/src/features/journey-editor/WorkflowPreview.vue`: Preview shell and typed UI intents.
- `apps/web/src/features/journey-editor/WorkflowPreviewCanvas.vue`: read-only SVG renderer.
- `apps/web/src/stores/journeyEditor.ts`: asynchronous Preview state and request ownership.
- `apps/web/src/views/JourneyEditorView.vue`: Slot/Guardrail intent wiring and typed navigation.

The editable `workflowEditor` store is not reused by the Preview, and fitted presentation coordinates are never written back to repository data.
