# M2.4B Frontend — Create OdyJourney Modal 改版实施计划

> Status: Ready for review  
> Scope: 将现有 `/journeys/new` 独立创建页改为 Journey List 上的路由驱动 Modal  
> Figma: `OdyJourney — Create Journey Modal`，node `417:33`  
> Authoritative guideline: [`frontend-engineering-guidelines.md`](../../../frontend-engineering-guidelines.md)  
> Related plan: [`m2.4b-new-journey-pattern-selection-implementation-plan.md`](./m2.4b-new-journey-pattern-selection-implementation-plan.md)

## 1. 结论与范围

本改版只改变创建体验的 presentation、临时表单状态和路由呈现，不改变已经冻结的领域规则或后端创建 contract。

- Pattern 仍在 Journey 创建时一次性选定，创建后不可替换；
- `pattern.id`、`pattern.kind`、`pattern.templateKey` 的不可变约束保持不变；
- 创建仍通过现有 `createJourney` repository operation 原子完成；
- 成功后仍导航到 repository 返回的 Journey Editor；
- `/journeys/new` 保留为可直接访问、可刷新和可使用浏览器前进/后退的 URL；
- 当前独立页面的 sidebar + 大型 readonly preview 被 2 × 2 Pattern 选择卡片替代；
- 本批不新增 Custom Pattern、Pattern replacement 或创建前 Slot 编辑。

本计划覆盖原计划第 2、3 节和 Batch B 中的创建页 UI 方案；其他 Journey persistence、Editor immutable 和 backend contract 内容继续有效。

## 2. 目标交互

```text
/journeys
  └─ click “New OdyJourney”
       └─ navigate /journeys/new
            └─ Journey List 保持为背景
                 └─ 打开 Create OdyJourney Modal
                      ├─ 输入 name
                      ├─ 输入 optional description
                      ├─ 明确选择一个 built-in Pattern
                      └─ create → /journeys/:journeyId?tab=pattern
```

关闭规则：

- Close、Cancel、Esc 和浏览器 Back 都关闭 Modal 并回到 `/journeys`；
- 创建中禁用 Close、Cancel、Pattern selection 和重复 submit，避免中断语义不一致；
- repository failure 后保留完整 draft，并恢复可操作状态；
- 关闭后焦点返回触发创建的 `New OdyJourney` 按钮；
- 直接访问 `/journeys/new` 时，关闭后仍回到 `/journeys`。

## 3. 路由与组件边界

Modal 必须由 route 决定是否打开，不能只使用 `JourneyListView` 内的局部 boolean。

建议结构：

```text
JourneyListRouteHost
├─ JourneyListView
└─ RouterView / route-derived create overlay
   └─ CreateJourneyDialog
```

允许根据现有 Router 结构选择 nested route 或 route host，但必须满足：

- `/journeys` 与 `/journeys/new` 共享同一份 Journey List presentation；
- 不复制两份 Journey List DOM、load state 或 repository 请求；
- 不把一个 Figma UI state 建成额外业务页面；
- route navigation 是 imperative shell，dialog 组件只 emit `cancel`/`submit` intent；
- Modal open/closed、focus target 和未提交 draft 属于 UI-only state，不进入 persistence payload。

现有 `JourneyCreationView.vue` 可以重构为 route overlay container，不能继续保留当前大型独立页面布局。

## 4. 创建状态模型

当前默认值：

```ts
ref<PatternTemplateKey>('linear_sequence')
```

必须改为显式未选择：

```ts
interface JourneyCreationDraft {
  name: string
  description: string
  selectedPatternTemplateKey: PatternTemplateKey | null
}

type JourneyCreationState =
  | { type: 'editing' }
  | { type: 'creating'; requestId: number }
  | { type: 'failed'; error: RepositoryError }
```

创建条件：

```text
trim(name) 非空
AND selectedPatternTemplateKey !== null
AND state.type !== 'creating'
```

要求：

- Description 在 UI 中明确标注 `Optional`；
- 未选择 Pattern 时不得调用 `instantiatePattern` 或 repository；
- Pattern selection 只改变 form/session draft；
- submit 前将 nullable selection 收窄为 `PatternTemplateKey`；
- double submit 被状态机拒绝；
- error 使用稳定 presentation mapping，不能只展示裸 error code；
- 成功仅信任 repository 返回的 canonical Journey ID。

## 5. Modal 信息架构

顺序以已确认 Figma 为准：

```text
Create OdyJourney
├─ short introduction
├─ Journey name (required)
├─ Description (optional)
├─ Pattern
│  ├─ immutable notice
│  └─ four selectable cards
└─ Cancel / Create OdyJourney
```

### 5.1 Pattern cards

四张卡片是一个单选组，整张卡片都可点击和键盘选择：

| UI name | Persisted key | Descriptor | Use case |
| --- | --- | --- | --- |
| Hub and Spoke | `hub_and_spoke` | Flexible coordinator + spokes | Coordinator-led specialist teams |
| Circular Loop | `diamond_loop` | Directed cycle · one entry | Review, refinement, and iteration |
| Linear Sequence | `linear_sequence` | Flexible ordered sequence | Ordered pipelines and handoffs |
| Solo Component | `solo_component` | One focused Agent | Focused single-Agent tasks |

要求：

- 默认四张均为 unselected；
- 使用原生 radio group 或等价的完整 ARIA radio semantics，不使用四个互不关联的 toggle button；
- selected state 同时使用 radio indicator、边框和语义属性，不能只依赖颜色；
- `Circular Loop` 只用于 UI，内部 key 继续为 `diamond_loop`；
- 文案集中在共享 presentation metadata，不能在 view、card 和测试各复制一份；
- “Best for …” 是说明文字，使用 secondary text，不使用链接色或链接语义；
- Pattern 图只表达 topology 与方向，不显示固定 Slot 数量承诺。

### 5.2 Compact Pattern Preview

新增或重构为共享的纯展示组件，例如：

```text
CompactPatternPreview
  input: PatternTemplateKey
  output: no domain mutation events
```

要求：

- Linear：相邻 Slot 之间有箭头，无尾线；
- Hub：Coordinator 与 Spokes 的方向关系清楚；
- Circular：显示闭环、执行方向和唯一入口；
- Solo：单节点、无内部连线；
- 图形不能依赖固定数量来定义 Pattern 领域规则；
- SVG 可用于小型拓扑图，但 topology/presentation metadata 必须来自共享 definition；
- 不复用可编辑 System Canvas，也不创建第二份 Pattern domain state。

## 6. Layout 与响应式

Desktop 基准以 Figma 820 px dialog 为准。实现必须使用 design token 或已有变量，避免在 feature 中散布 raw color。

### Desktop

- dialog width：`min(820px, calc(100vw - 48px))`；
- Pattern cards：两列；
- Header、Body、Actions 分区明确；
- Actions 固定在 dialog 底部视觉区域；
- immutable notice 在 Pattern heading 右侧。

### Short viewport

- dialog `max-height: calc(100vh - 48px)`；
- Body 独立纵向滚动；
- Header 与 Actions 保持可见；
- 不允许整个页面被 Modal 内容撑出不可控双重滚动。

### Narrow viewport

- Pattern cards 改为单列；
- immutable notice 移到 Pattern title 下方并允许换行；
- dialog 接近全屏，但保留可触达的 Close 与 Actions；
- name、description 和按钮不得产生水平溢出。

最低需要验证 1440、1024、768 px 宽度，以及约 700 px 高度。

## 7. Dialog 可访问性

必须覆盖：

- `role="dialog"`、`aria-modal="true"`、可关联 title/description；
- 打开后焦点进入第一个可编辑字段；
- Tab/Shift+Tab focus trap；
- Esc 关闭（creating 状态除外）；
- Close button 有明确 accessible name；
- Pattern 使用 radio group 键盘行为，方向键可切换；
- Create disabled 的原因可被辅助技术理解；
- validation/error 使用 `aria-describedby`/`role="alert"` 等稳定关联；
- 关闭后恢复到 New OdyJourney trigger；
- backdrop click 是否关闭必须显式决定；本批建议允许 editing 状态关闭、creating 状态拒绝。

可复用现有 dialog primitive 时优先复用；若当前 `journey-staged-dialog` 不具备 focus trap 和焦点恢复，不得仅复制它的 CSS 并宣称完成。

## 10. 测试矩阵

### Component

- 初始状态没有选中的 Pattern；
- Create 初始 disabled；
- 只输入 name 仍 disabled；
- 只选择 Pattern 仍 disabled；
- name + Pattern 后 enabled；
- radio 点击与方向键切换一致；
- 四个 preview 与 key 对应正确；
- creating 状态阻止重复提交和关闭；
- failure 保留 name、description 和 Pattern；
- Esc、Cancel、Close 行为一致；
- focus trap 与 trigger focus restoration。

### Integration

- `/journeys` 点击 New 导航 `/journeys/new` 且列表保持背景；
- 浏览器 Back 关闭 Modal；
- 直接访问 `/journeys/new` 可正常展示；
- submit payload 仅包含 trim 后 name、nullable description 和已选 key；
- repository failure 不导航；
- repository success 使用返回 ID 导航 Editor；
- internal `diamond_loop` 在 UI 中显示为 Circular Loop。

### Browser/visual

- 1440 × 960 与 Figma 主基准一致；
- 1024 px 宽度无裁切；
- 768 px 宽度卡片正确转单列；
- 约 700 px 高度时 Body 滚动、Actions 可见；
- 键盘可以完成打开、填写、选择、取消和提交；
- 无水平滚动、双重滚动或被遮挡操作。

## 11. Definition of Done

1. `/journeys/new` 以 Journey List 上的 Modal 呈现，不再显示旧的独立左右栏页面。
2. 默认不选择任何 Pattern，用户必须显式选择。
3. Create 仅在有效 name、Pattern 已选且非 creating 时可用。
4. 四张卡片符合 radio group 语义并支持键盘操作。
5. 四种紧凑拓扑图正确表达执行方向，Linear 无尾线，Circular 有入口。
6. Pattern immutable 提示明确，且创建后 replacement 仍不存在。
7. submit failure 保留 draft，success 导航 canonical Journey。
8. dialog 具备 focus trap、Esc、焦点恢复和稳定错误反馈。
9. desktop、short viewport 和 narrow viewport 均无裁切或不可达操作。
10. 相关 component、integration 和 browser 验收通过。
11. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。
