## 1. Outcome

M2.7 把 M2.6 已验收的 Workflow domain command system 接入真正可编辑的 Agent Workflow Canvas：

```text
Vue Flow / Browser event
→ adapter-produced typed intent
→ Workflow Editor application transaction
→ M2.6 domain command and/or pure layout command
→ atomic document replacement
→ adapter derives the next Canvas view model
→ explicit save → Web API → reload-equivalent graph/layout/viewport
```

完成后，用户可以从真实 Web API 加载一个 Agent Workflow，在 top-level Canvas 中创建、移动、选择和删除节点，创建/删除 edge，检查基础配置与 readiness，显式保存并在刷新后恢复 graph、layout 和 viewport。

M2.7 是 editable Canvas core，不是最终完整 Agent Builder。Nested Loop Canvas、resource DnD arbitration、真正的 Flow/Configure 双模式、Focus Mode 和 autosave race hardening 保留给 M2.8/M2.9。

## 2. Non-negotiable architecture boundaries

### 2.1 Three independent state owners

```text
WorkflowGraph
  semantic nodes, edges, node configuration

CanvasLayout
  top-level node placements and persisted viewport

WorkflowEditorSession
  selection, open inspector, interaction, create draft, transient errors
```

必须保持：

- node create/delete 可由 application transaction 同时提交 graph + layout；
- node move 只修改 CanvasLayout；
- viewport change 只修改 CanvasLayout；
- edge create/delete 只修改 WorkflowGraph；
- config edit 只修改 WorkflowGraph；
- selection、hover、connect preview、drag state、panel draft 不进入 graph/layout/save payload；
- readiness diagnostics 是 graph 派生结果，不持久化；
- Vue Flow node/edge 不是任何 persisted state。

### 2.2 Vue Flow import boundary

`@vue-flow/*` 只允许出现在：

```text
apps/web/src/canvas/workflow/
apps/web/src/features/workflow-editor/  # renderer/UI boundary only
```

不得进入：

- `packages/schemas`；
- `apps/web/src/domain`；
- repository port/implementation；
- HTTP DTO/payload；
- Pinia persisted document shape；
- read-only Workflow Preview contract。

建立 automated import audit，不能只靠 code review。

### 2.3 Vue Flow is a transient renderer, not a second source of truth

- Canvas nodes/edges 由 `document.workflow + document.layout + session selection` 派生；
- Store 不保存 Vue Flow node/edge arrays；
- 组件不把 `v-model:nodes`/`v-model:edges` 作为长期 document；
- Vue Flow 在 drag/connect 期间可以维护必要的临时 view state；
- drag stop/connect commit 后，权威状态来自 store，再由 adapter 重投影；
- Vue Flow transient fields（selected、dragging、dimensions、handleBounds、computedPosition 等）永不进入 repository payload。

### 2.4 M2.6 remains the graph authority

UI preflight 可以提前拒绝明显非法连接，但最终结果必须调用 M2.6：

```text
connectNodes
removeEdge
addNode
removeNode
updateNodeConfig
updateLoopSettings
updateLoopBody
```

Canvas/UI 不得复制 cycle、Branch handle 或 Start/End invariant。M2.6 error code 是最终 authority。

## 5. Canvas adapter contract

### 5.1 Adapter inputs and outputs

建议提供：

```ts
interface WorkflowCanvasProjectionInput {
  readonly graph: WorkflowGraph
  readonly layout: CanvasLayout
  readonly selectedNodeId: UUID | null
  readonly selectedEdgeId: UUID | null
  readonly diagnostics: WorkflowValidationReport
  readonly contextId: string
}

interface WorkflowCanvasProjection {
  readonly nodes: readonly WorkflowCanvasNode[]
  readonly edges: readonly WorkflowCanvasEdge[]
  readonly viewport: CanvasViewport
  readonly diagnostics: readonly WorkflowCanvasDiagnostic[]
}
```

`WorkflowCanvasNode/Edge` 可以在 adapter/UI boundary 使用 Vue Flow types，但其 `data` 必须是小型、只读、严格 typed presentation model，不能嵌入可修改的完整 WorkflowNode reference。

### 5.2 Required adapter functions

```text
toCanvasNodes(graph, layout, session, diagnostics)
toCanvasEdges(graph, session, diagnostics)
toCanvasViewport(layout)
fromCanvasViewport(viewport)
createConnectionIntent(connection)
createNodeMoveIntent(nodeDragStop)
createNodePlacementIntent(screenPoint, projection)
createSelectionIntent(change)
```

规则：

- adapter 不修改输入；
- node identity 始终使用 domain UUID；
- DOM/Vue Flow internal ID 使用明确 context namespace，但 mapper 必须无损恢复 domain UUID；
- target handle 可以是 renderer-only generic handle，不得持久化为 `targetHandleId`；
- Branch source handle 映射到 Case/Default UUID；
- non-Branch source handle 不制造持久化 handle ID；
- missing placement 使用 deterministic presentation fallback + diagnostic，不自动写回 layout；
- edge endpoint/placement 异常不得使用 non-null assertion 掩盖。

### 5.3 Round-trip invariants

```text
domain node UUID → Canvas node → select/move/delete intent → same domain UUID
Branch Case UUID → Canvas source handle → connection intent.sourceHandleId
Canvas viewport → CanvasLayout viewport → reload → equivalent viewport
```

Adapter 不需要把任意 Vue Flow object“反序列化”为 WorkflowGraph。Graph 变化只能来自 typed intent + M2.6 command。

## 6. Node renderer and handle rules

| Node | Target handle | Source handle | Delete | M2.7 inspector |
| --- | --- | --- | --- | --- |
| Start | none | one generic renderer handle | protected | identity/readiness only |
| End | one generic renderer handle | none | protected | identity/readiness only |
| Agent Action | one generic | one generic | allowed | basic model/goal proof；resources deferred |
| Task | one generic | one generic | allowed | summary only；Tool sequence editor deferred |
| Branch | one generic | one per Case + Default UUID | allowed | Case/Default summary；full condition editor deferred |
| Loop | one generic | one generic | allowed | maxTurns/exit summary or safe settings proof；nested Canvas deferred |

Node renderer 只 emit intents：select、open inspector、request delete、start connection。不得直接调用 store 或修改 node config。

Selected/error/readiness 状态必须用视觉 + accessible text/description 表达，颜色不是唯一反馈。

## 7. Node creation contract

### 7.1 No fake required configuration

Palette 不得为了立即创建节点而伪造 model、Variable、Tool 或 Knowledge Space ID。

创建分为两类：

#### Immediate valid defaults

- Task：`localVariables: []`、`steps: []`；
- Branch：生成 required Default Case UUID，Cases 初始可为空。

#### Creation requirements/preflight

- Agent Action：需要可用 model/default model policy 与 goal value；
- Loop：需要 `maxTurns` 和真实 Agent Variable-backed exit condition；无可用 Variable 时明确阻止并指向 Agent Variables future flow。

使用 typed result：

```ts
type NodeCreationEvaluation =
  | { status: 'ready'; node: AddableWorkflowNode }
  | { status: 'requires-configuration'; draft: NodeCreationDraft }
  | { status: 'unavailable'; code: NodeCreationUnavailableCode }
```

`NodeCreationDraft` 是 UI-only session state。只有 submit 后生成合法 node 并执行 graph+placement transaction；取消不能留下 node、placement 或 dirty state。

### 7.2 Palette interaction

- mouse drag 使用现有 typed `workflow-node-template` payload namespace；
- click/Enter 提供等价创建路径，默认放在 current viewport center；
- screen coordinate 只在 Vue Flow boundary 转为 flow coordinate；
- domain/application transaction 接收最终 `{ x, y }`，不接收 DOM event；
- Start/End 不出现在 palette；
- Loop 可展示但 unmet requirements 时不得伪造可用。

## 8. Pure CanvasLayout commands

新增独立、无 Vue Flow import 的 layout functions：

```text
addNodePlacement(layout, nodeId, position)
moveNodePlacement(layout, nodeId, position)
removeNodePlacement(layout, nodeId)
updateCanvasViewport(layout, viewport)
validateCanvasLayoutForGraph(layout, graph)
```

要求：

- finite x/y；zoom positive finite；
- placement node ID 唯一；
- placement 只引用当前 graph node；
- input immutable；
- failure 返回 stable layout error code；
- 不调用 graph validator；
- viewport update 不复制/修改 graph；
- node move 不引发全图 M2.6 validation。

Missing placement 可被 adapter fallback 渲染，但 save readiness/diagnostic 应明确提示。M2.7 不在 load 时静默“修复并保存”用户 layout。

## 9. Application transactions

### 9.1 Create node + placement

```text
typed create intent
→ build valid semantic node with injected IDs
→ M2.6 addNode(candidate graph)
→ addNodePlacement(candidate layout)
→ validate graph/layout cross-reference
→ atomically replace graph + layout
→ select new node / open inspector (session only)
```

任一步失败，graph、layout、session selection、dirty sequence 都不变。

### 9.2 Delete node + placement

```text
request delete
→ M2.6 removeNode(candidate graph, removes incident edges)
→ removeNodePlacement(candidate layout)
→ validate graph/layout cross-reference
→ atomically replace graph + layout
→ clear selected node/edge/panel if owned by deletion
```

Start/End delete 由 M2.6 稳定拒绝。不得先删 graph、再尝试修 layout。

### 9.3 Move node

- Vue Flow drag 中的位置仅为 renderer transient state；
- `nodeDragStop` 转换为 typed `{ nodeId, x, y }`；
- store 只调用 `moveNodePlacement`；
- WorkflowGraph object/deep value 保持不变；
- 不在每个 pointer move 调 repository save 或 graph validation；
- 高频视觉更新由 Vue Flow boundary 处理，持久化 state 只在明确 commit point 更新。

### 9.4 Connect and remove edge

- connection preflight 提供即时 feedback；
- commit 必须调用 M2.6 `connectNodes`；
- invalid connection 不显示为已成功持久化 edge，不使用“先加后回滚”；
- edge delete 调用 M2.6 `removeEdge`；
- readiness 可能变为 incomplete，但 structural graph 保持合法；
- edge selection 是 session-only。

### 9.5 Config edit

- safe typed edit 调用 M2.6 store actions；
- `UpdateNodeConfigIntent` 不包含 Loop；
- Loop settings 只调用 settings-only action；
- Loop graph editing 在 M2.7 UI 不开放；
- nested layout 没有 config command 写入口；
- unsubmitted form draft 只在 SidePanel session/local state。

## 10. Connection preflight and error presentation

### 10.1 UI preflight

纯 adapter/application helper 可提前判断：

- missing Canvas endpoint mapping；
- self-edge；
- obvious Start/End direction；
- Branch handle required/ownership；
- non-Branch handle forbidden；
- semantic duplicate edge。

Cycle detection 和完整 invariant 仍由 M2.6 authoritative command 执行；不在组件模板复制算法。

### 10.2 Error mapping

建立单一 UI mapper：

```text
WorkflowDomainError code
→ localized/presentation message
→ optional node/edge/handle highlight identity
→ accessible live-region announcement
```

至少覆盖：

- `SELF_EDGE`；
- `DUPLICATE_EDGE`；
- `CYCLE_DETECTED`；
- `INVALID_EDGE_DIRECTION`；
- `HANDLE_REQUIRED/NOT_FOUND/ALREADY_CONNECTED/NOT_ALLOWED`；
- `BOUNDARY_NODE_IMMUTABLE`；
- layout placement errors。

Domain 不包含最终 UI 文案；组件不解析 error message 字符串。

## 11. Store and session model

建议扩展 Workflow Editor session：

```ts
type WorkflowInteractionState =
  | { type: 'idle' }
  | { type: 'dragging-palette-node'; nodeType: AddableWorkflowNodeType }
  | { type: 'moving-node'; nodeId: UUID }
  | { type: 'connecting'; sourceNodeId: UUID; sourceHandleId?: UUID }
  | { type: 'creating-node'; draft: NodeCreationDraft }

interface WorkflowEditorSession {
  selectedNodeId: UUID | null
  selectedEdgeId: UUID | null
  panel: WorkflowPanel
  interaction: WorkflowInteractionState
  lastCanvasError: WorkflowCanvasError | null
}
```

M2.7 不使用多个互相矛盾的 drag/connect boolean。

Store actions 分为：

```text
Graph-only
  connectWorkflowNodes
  removeWorkflowEdge
  updateWorkflowNodeConfig
  updateWorkflowLoopSettings

Layout-only
  moveWorkflowNode
  updateWorkflowViewport

Graph + layout transaction
  createWorkflowNodeAt
  removeWorkflowNodeAndPlacement

Session-only
  selectWorkflowNode
  selectWorkflowEdge
  open/close inspector
  begin/cancel creation draft
  transition interaction
```

组件只调用这些 actions/emits，不直接访问 mutable document collections。

## 12. Explicit save and persistence safety

### 12.1 Why explicit Save in M2.7

M2.7 必须证明 graph/layout/viewport save-reload，但完整 autosave orchestration 属于 M2.9。因此本阶段冻结：

- 用户显式点击 Save；
- local mutation 标记 dirty；
- 不使用 debounce autosave；
- node drag/pan/zoom 不直接触发 HTTP；
- 离开 dirty editor 前提供 browser/router confirmation baseline；完整 navigation/save orchestration 可在 M2.9 harden。

### 12.2 Minimum safe save state

即使是显式 Save，也必须防 stale snapshot：

```ts
type WorkflowSaveState =
  | { type: 'clean'; revision: Revision }
  | { type: 'dirty'; mutationSeq: number; revision: Revision }
  | { type: 'saving'; requestSeq: number; snapshotSeq: number; revision: Revision }
  | { type: 'saved-with-newer-local-changes'; mutationSeq: number; revision: Revision }
  | { type: 'failed'; mutationSeq: number; revision: Revision; error: RepositoryError }
  | { type: 'conflict'; mutationSeq: number; localRevision: Revision; serverRevision?: Revision }
```

- save 使用 immutable snapshot；
- save response 只更新对应 snapshot 的 server revision；
- saving 中若继续编辑，成功响应不得把 newer local document 标为 clean；
- 同一时刻最多一个 explicit save；
- abort/dispose 后 late response 被忽略；
- revision conflict 不覆盖本地 document；
- Retry 使用当前最新 snapshot；
- Reload/discard local change 必须明确确认。

M2.9 再扩展 debounce、多请求乱序、自动重试和完整 conflict UX。

### 12.3 Save payload

继续复用真实：

```text
EditorRepository.saveAgentWorkflow
PUT /api/v1/journeys/{journeyId}/agents/{agentId}
```

Payload 只包含 canonical graph、layout、variables、reusableTools、expectedRevision。禁止包含：

- Vue Flow nodes/edges；
- selection/panel/mode/interaction；
- readiness diagnostics；
- creation draft；
- domain/UI errors。

### 15.1 Adapter

| Scenario | Expected |
| --- | --- |

### 15.3 Application transactions

| Scenario | Expected |
| --- | --- |
| create node succeeds, placement fails | neither graph nor layout commits |
