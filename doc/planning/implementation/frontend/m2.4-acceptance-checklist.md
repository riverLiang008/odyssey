# Odyssey M2.4 验收标准与执行清单

> Status: Ready for independent acceptance  
> Milestone: M2.4 — Journey persistence, Pattern System Canvas, Agent Slot interaction, optional Guardrails  
> Acceptance target: `http://127.0.0.1:4173/journeys`（若本地实际端口不同，以当前 dev server 输出为准）  
> API target: `http://127.0.0.1:8000/api/v1`  
> Rule: 必须使用真实 Web API 和专用验收 Journey；不得用 mock、fixture 或直接修改前端 store 代替用户交互。

## 1. 验收目标

M2.4 验收通过意味着以下纵向路径已经闭合：

```text
Create OdyJourney
→ choose immutable Execution Pattern
→ configure Pattern Slots and Agents
→ open/create Agent Workflow
→ refresh and recover persisted state
→ optionally add/remove Input or Output Guardrail
→ delete dedicated acceptance Journey
```

验收者应同时检查：

- 用户可观察的视觉和交互结果；
- 刷新后的真实持久化结果；
- URL、revision 和错误反馈；
- 操作失败时不存在前端伪成功或部分本地修改。

## 2. 验收数据与安全规则

1. 新建专用 Journey，名称建议使用：`M2.4 Acceptance <timestamp>`。
2. 四种 Pattern 应分别创建独立 Journey，不能通过替换现有 Journey Pattern 完成。
3. 不删除或修改用户已有 Journey。
4. 删除、occupied Slot removal、Guardrail removal 仅针对本次验收创建的数据。
5. 每个持久化步骤后至少刷新一次页面验证恢复。
6. 记录每个失败项的：Journey ID、Pattern、revision、操作、预期、实际、截图和控制台/API 错误。

## 3. P0 阻断项

以下任一失败，M2.4 整体判定为不通过：

- 正式页面使用 mock/fixture 数据或刷新后数据丢失；
- 无法创建、加载或删除 Journey；
- 创建后的 Pattern 可以被替换；
- 四种 built-in Pattern 任一种无法创建或无法呈现其正确拓扑；
- 空 Slot 的 `Open workflow` 无法原子创建 Agent、最小 Workflow 并导航；
- API 已成功但前端显示失败，或前端显示成功但刷新后未持久化；
- occupied Slot/Agent/Guardrail 删除产生部分状态或孤儿引用；
- revision conflict 覆盖了服务端较新数据；
- 页面出现阻断使用的运行时异常、白屏或不可恢复 loading。

## 4. Journey 创建与 Pattern 不可变

### AC-01 Journey 列表

- [ ] `/journeys` 从真实 API 加载。
- [ ] loading、empty、error/retry、ready 状态均稳定。
- [ ] `New OdyJourney` 可用。
- [ ] 刷新后 Journey 列表和数量不依赖内存数据恢复。

### AC-02 创建表单

- [ ] Name 必填；Description 可选。
- [ ] 默认没有选中 Pattern。
- [ ] 未填写有效 Name 或未选择 Pattern 时不能提交。
- [ ] Pattern 库同时展示四种 built-in Pattern：
  - Hub and Spoke
  - Circular Loop（内部 key 为 `diamond_loop`）
  - Linear Sequence
  - Solo Component
- [ ] 每张卡包含名称、简述、典型用途和只读拓扑预览。
- [ ] 四种预览使用一致的箭头视觉；Linear 无尾线；Circular 为有向闭环；Solo 无内部连线。
- [ ] 创建前可以切换选择；Create 只提交一次，不产生重复 Journey。

### AC-03 创建后 Pattern 不可变

- [ ] 创建成功后进入返回 Journey ID 对应的 Editor。
- [ ] Editor 中不存在 Pattern replacement 按钮、拖放目标、右键动作或其他替换入口。
- [ ] 页面明确表达 Pattern 创建后固定；换 Pattern 的路径是删除并重新创建 Journey。
- [ ] 刷新后 `pattern.id`、`kind`、`templateKey` 保持不变。

## 5. 四种 Execution Pattern

每种 Pattern 使用独立验收 Journey。

### AC-04 Linear Sequence

- [ ] Slot 按顺序横向或自适应排列。
- [ ] 只在相邻 Slot 之间显示带箭头的连线。
- [ ] 最后一个 Slot 后没有多余尾线。
- [ ] Slot 数量动态可变。
- [ ] 右键可增加、删除允许删除的 Slot。
- [ ] reorder 后 Slot identity 和已配置 Agent identity 不变，箭头顺序重新派生。

### AC-05 Hub and Spoke

- [ ] Hub 位于中心，Spoke 围绕 Hub 排布。
- [ ] 1、2、3、4 个 Spoke 分别遵守右；左右；上/左下/右下；上/右/下/左的布局规则。
- [ ] 5–8 个 Spoke 按环形均匀排布，标签不进入中心安全区。
- [ ] Hub 不可删除；Spoke 数量动态可变。
- [ ] 每条 route 从 Hub 圆边缘指向 Spoke 圆边缘。
- [ ] 标签、状态、选中光环和连线不重叠，不出现明显裁切。

### AC-06 Circular Loop

- [ ] UI 名称为 `Circular Loop`，持久化 kind/template key 仍为 `diamond_loop`。
- [ ] 显示单向闭环和明确箭头方向。
- [ ] 具有唯一入口标识。
- [ ] 最少两个 Slot；Slot 数量动态可变。
- [ ] 本阶段只验收环，不要求分支与汇合。

### AC-07 Solo Component

- [ ] 仅有一个 Slot。
- [ ] 不显示内部 route/箭头。
- [ ] 不提供增加、删除或重排 Slot 的能力。

## 6. Slot 与 Agent 交互

### AC-08 Slot 状态

- [ ] empty Slot 是空心圆并显示 `Empty slot`。
- [ ] configured Slot 是实心圆并显示 Agent 名称与 `Configured`。
- [ ] missing Agent summary 是独立错误/诊断状态，不能伪装成 empty。
- [ ] 左键 empty Slot 只选择，不创建 Agent、不导航。
- [ ] empty 与 configured Slot 右键使用同一菜单结构；不支持的动作正确 disabled。
- [ ] 右键菜单可用 Escape 关闭，并有合理的键盘焦点行为。

### AC-09 Empty Slot → Open workflow

- [ ] 在 empty Slot 上右键选择 `Open workflow` 后，只发出一个原子 API command。
- [ ] command 创建 Journey-owned Agent identity。
- [ ] command 初始化最小 `Start → End` Workflow，即 `2 nodes · 1 edge`。
- [ ] command 将 Agent 分配至原 Slot，并返回最新 Journey aggregate/revision。
- [ ] 成功后直接进入该 Agent 的普通 Workflow Editor。
- [ ] 刷新 Workflow 和返回 Journey 后，Agent、Slot assignment 和 Workflow 仍存在。
- [ ] Agent name/description 不在此流程中要求填写；只有 Save as Template 时要求 Template 信息。

### AC-10 configured Agent

- [ ] `Open workflow` 直接进入现有 Agent，不创建新 identity。
- [ ] Save as Template 使用真实 API，刷新 Template library 后仍存在。
- [ ] Agent Template 拖到 empty Slot 后实例化为新的 Journey-owned Agent，而不是复用同一个 Agent ID。
- [ ] assigned Agent 的合法 move/exchange 保持每个 Agent 最多占用一个 Slot。
- [ ] invalid/duplicate/unsupported drop 不修改 canonical document，并给出稳定反馈。

### AC-11 Slot 增删与 occupied removal

- [ ] 除 Solo 外，Slot 增删能力由 Pattern strategy 决定。
- [ ] empty Slot 删除不会留下悬空 route。
- [ ] occupied Slot 不能通过普通 Journey PUT 直接删除。
- [ ] occupied removal 使用原子 command。
- [ ] `discard` 删除 Slot、Agent 和 Workflow。
- [ ] `save_as_template_and_discard` 先持久化 Template，再原子删除 Slot、Agent 和 Workflow。
- [ ] cancel 或 command failure 时 Journey canonical document 不变。

## 7. Optional Guardrails

### AC-12 inactive 状态

- [ ] Input Guardrail 与 Output Guardrail 默认且相互独立地 inactive。
- [ ] inactive 卡片显示标题、`Optional`、圆形 `+` 和 `Add`。
- [ ] 不显示 Linear Pattern、Pattern selector、Pattern drag 或 chain。
- [ ] Guardrail 与 Main Execution 是不同的领域投影。

### AC-13 Add Guardrail

- [ ] 点击 `+` 或 `Add` 只产生一个 add command。
- [ ] Add 自动创建固定 `single` 结构和一个 Guardrail Agent，不要求选择 Pattern。
- [ ] 新 Agent 包含最小 `Start → End` Workflow。
- [ ] active 卡片高亮并显示 Agent 名称和 `Configured`。
- [ ] 刷新后仍 active，Agent summary 与 Workflow 可重新加载。
- [ ] Input 和 Output 可以同时 active，且 Agent ID 不同。

### AC-14 Guardrail Agent 与 Remove

- [ ] active Guardrail Agent 左键进入已有选择路径。
- [ ] 右键菜单包含 `Open workflow` 与 `Remove guardrail`。
- [ ] `Open workflow` 进入普通 Agent Workflow Editor，不使用独立 Guardrail Editor。
- [ ] `Remove guardrail` 需要明确确认。
- [ ] Remove 永久删除该 Guardrail Agent 与 Workflow，不创建 Template。
- [ ] 成功后恢复 inactive；刷新后仍 inactive，旧 Agent URL 返回 not found。
- [ ] 取消或失败时 active 状态不被本地提前清空。

## 8. System Configuration 布局与视觉

### AC-15 外层语义和边界

- [ ] 桌面端第一行为 `Input Guardrail | Main Execution | Output Guardrail`。
- [ ] 两侧 Guardrail 等宽，Main Execution 使用剩余空间。
- [ ] `Execution Behavior` 位于第二行并跨越完整三列。
- [ ] Behavior 左边界与 Input Guardrail 对齐，右边界与 Output Guardrail 对齐。
- [ ] Guardrail inactive/active 切换不引起列宽或页面跳动。
- [ ] 页面缩窄时按已定义 breakpoint 降级，无横向溢出或语义错序。

### AC-16 Pattern 图形通用视觉

- [ ] 每个 Slot 的圆、名称和状态作为一个完整视觉单元排布。
- [ ] 连线只连接圆形边缘，不能穿过名称和状态文字。
- [ ] 箭头形状在 Pattern preview 和 Editor 中保持一致。
- [ ] configured、empty、selected、focus 状态不改变拓扑坐标。
- [ ] 1024px 与 1440px 桌面宽度下可读且无明显重叠。

## 9. Persistence、并发与错误边界

### AC-17 刷新恢复

- [ ] Journey metadata、Pattern、Slots、Agent assignment、Guardrails 和 Workflow 均可刷新恢复。
- [ ] 正式 runtime 使用 `HttpEditorRepository`，Network 面板中请求指向 `/api/v1`。
- [ ] 页面不存在 local-only success fallback。

### AC-18 Revision 与 stale response

- [ ] mutation request 携带当前 expected revision。
- [ ] stale revision 返回明确 conflict，不覆盖服务端状态。
- [ ] double click、pending request 和较旧响应不会产生重复 Agent 或覆盖较新 aggregate。
- [ ] conflict 后刷新可恢复服务端 canonical document。

### AC-19 错误状态

- [ ] `404`、`409`、`422`、`503`、network failure 和 invalid response 有稳定反馈。
- [ ] error 后允许 retry 或刷新恢复。
- [ ] 失败操作不留下半创建 Agent、悬空 Slot、孤儿 Workflow 或错误 Guardrail binding。
- [ ] Console 不出现未处理异常。

## 10. 自动化质量门禁

在仓库根目录执行：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

- [ ] 四条命令全部退出码为 0。
- [ ] Frontend 全量测试通过。
- [ ] Shared schema tests 通过。
- [ ] 不通过删除/跳过测试来获得绿色结果。

## 11. 明确不属于 M2.4 的内容

以下内容不应作为 M2.4 失败项：

- M2.5 的完整 Workflow Preview 面板；
- Behavior 的实际策略、policy 或 observability 配置；
- Circular Loop 中的分支与汇合；
- 用户自定义 Pattern；
- Hub and Spoke 超过 8 个 Spoke 的双圈布局；
- 完整 Workflow Canvas 编辑能力的后续里程碑内容，但 M2.4 创建的最小 Workflow 数据必须真实存在且可加载。

## 12. 最终判定格式

验收者必须输出：

```text
M2.4 Acceptance: PASS | FAIL | BLOCKED

Environment
- Frontend URL:
- API URL:
- commit/worktree:
- browser:

Quality gates
- lint:
- typecheck:
- tests:
- build:

Acceptance summary
- Passed: <count>
- Failed: <count>
- Blocked: <count>

P0 findings
- none | <finding list>

Non-blocking findings
- none | <finding list>

Created acceptance data
- <Journey IDs>

Cleanup
- deleted | retained with reason
```

只有所有 P0 项、AC-01 至 AC-19 的适用项和质量门禁全部通过，才能判定 `PASS`。环境服务、数据库或浏览器不可用导致无法完成核心路径时判定 `BLOCKED`，不能用单元测试结果替代真实浏览器验收。
