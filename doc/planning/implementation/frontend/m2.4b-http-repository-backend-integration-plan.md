## 1. 目标与当前基线

目标路径：

```text
Journey list
→ New OdyJourney
→ choose one immutable built-in Pattern
→ create and navigate to Journey Editor
→ edit Slots / assign or create Agent
→ edit and save Agent Workflow
→ refresh and recover the same persisted state
→ delete Journey with optimistic concurrency
```

2026-08-16 的真实环境验证结果：

- `GET http://127.0.0.1:8000/api/v1/health` 返回 `200`；
- `GET /api/v1/journeys` 返回 `200`；
- `GET /api/v1/agent-templates` 返回 `200`；
- `http://127.0.0.1:5173` 与 `http://localhost:5173` 的 CORS preflight 均通过；
- OpenAPI 中 `POST /journeys` 使用 `CreateJourneyRequest`，GET 没有错误 request body；
- 当前前端 `createEditorRepository()` 仍固定返回 `InMemoryEditorRepository`；
- 仓库尚无 HTTP repository implementation。

因此后端环境不再是 blocker。当前工作是前端 boundary、contract 和运行时切换。

## 2. 不可违反的边界

```text
Component / Store
→ typed repository port
→ HTTP adapter
→ fetch / API
```

- component 和 store 不直接调用 `fetch()`；
- HTTP status、`Response`、header 和 API error envelope 不得越过 repository boundary；
- 所有 response body 先作为 `unknown`，经共享 Zod schema 验证后才能进入 domain/store；
- repository 负责 DTO mapping、AbortSignal、错误归一化和 URL/header 构造；
- Workspace 由后端可信 dependency 决定，前端不得发送或选择 unrestricted `workspaceId`；
- in-memory repository 保留为 test double，但正式 app runtime 不再回退到 fixture；
- 不允许 HTTP 失败后静默切回 in-memory 数据，这会制造两个事实来源；
- autosave 的 request sequence、snapshot sequence 和 stale-response 处理仍由 store/application shell 负责，HTTP adapter 不拥有 editor session。

## 3. 实施前必须收口的前端 contract

现有 Journey CRUD 和 Workflow save port 大体可映射，但 Agent lifecycle port 仍反映早期前端假设。必须先修改共享 schema、port、store 和 in-memory implementation，不能在 HTTP adapter 中静默丢弃旧字段。

### 3.1 Agent Template list/load

当前：

```ts
listAgentTemplates(workspaceId, options)
loadAgentTemplate(workspaceId, templateId, options)
```

目标：

```ts
listAgentTemplates(options)
loadAgentTemplate(templateId, options)
```

理由：Workspace 由服务端解析。`workspaceId` 不属于客户端请求，也不应成为 HTTP adapter 的伪参数。

### 3.2 创建最小 Agent

当前 input 含 `name`、`description`、可选 `journeySnapshot`；最终 API 只接受 Journey 当前 revision：

```ts
interface CreateJourneyAgentInput {
  journeyId: UUID
  slotId: UUID
  expectedRevision: Revision
}
```

点击空 Slot 后创建只有 Start 和 End 的最小 Agent，并用 canonical response 替换 Journey snapshot 后导航 Workflow Editor。Agent name/description 不在此步骤采集；只有 Save as Template 时需要 Template metadata。

### 3.3 实例化 Agent Template

当前前端 input 的 `name`、`dependencyMappings` 不在冻结 API request 中。目标：

```ts
interface InstantiateAgentTemplateInput {
  journeyId: UUID
  slotId: UUID
  templateId: UUID
  expectedRevision: Revision
}
```

本批不得把 dependency mapping 私自编码进 HTTP body。若未来出现需要用户映射且后端无法解析的 Template，应显示明确 unavailable state，另开 contract milestone。

### 3.4 Save Agent as Template

移除客户端 `ownerWorkspaceId`：

```ts
interface SaveAgentAsTemplateInput {
  journeyId: UUID
  agentId: UUID
  name: string
  description: string | null
}
```

owner Workspace 只采用服务端 current Workspace。

### 3.5 Occupied Slot removal

为 backend atomic command 新增正式 port；不能通过普通 `saveJourney` 删除 occupied Slot：

```ts
type RemoveOccupiedSlotAction =
  | { type: 'discard' }
  | {
      type: 'save_as_template_and_discard'
      template: { name: string; description: string | null }
    }

interface RemoveOccupiedSlotInput {
  journeyId: UUID
  slotId: UUID
  expectedRevision: Revision
  expectedAgentId: UUID
  agentAction: RemoveOccupiedSlotAction
}

interface RemoveOccupiedSlotSuccess {
  journey: JourneyEditorDocument
  template: AgentTemplate | null
}
```

成功后用返回的 canonical Journey 替换本地 document；若返回 Template，同步更新 Template library。失败不得先局部删除 Slot 或 Agent。

## 4. HTTP endpoint 映射

Base URL 来自 `VITE_API_BASE_URL`，本地默认值为 `http://localhost:8000/api/v1`。创建 repository 时去除末尾 `/`，使用 `URL` 验证配置；无效或缺失时 fail fast，不加载 fixture。

| Repository operation | HTTP | Request mapping | Success validation / mapping |
| --- | --- | --- | --- |
| `listJourneys` | `GET /journeys` | 无 body | `journeySummaryListSchema` |
| `createJourney` | `POST /journeys` | `{name, description, patternTemplateKey}` | `journeyEditorDocumentSchema` |
| `loadJourney` | `GET /journeys/{journeyId}` | path | `journeyEditorDocumentSchema` |
| `saveJourney` | `PUT /journeys/{journeyId}` | `{expectedRevision, pattern}` | 验证 canonical `JourneyEditorDocument`，再映射 `{journeyId, revision, updatedAt}` |
| `deleteJourney` | `DELETE /journeys/{journeyId}` | `If-Match: "<revision>"`，无 body | 仅接受 `204` 和空 body，再映射 `{journeyId}` |
| `loadAgentWorkflow` | `GET /journeys/{journeyId}/agents/{agentId}` | path | `agentWorkflowEditorDocumentSchema` |
| `saveAgentWorkflow` | `PUT /journeys/{journeyId}/agents/{agentId}` | `{expectedRevision, workflow, layout, variables, reusableTools}` | 验证 canonical Agent document，再映射 compact save success |
| `listAgentTemplates` | `GET /agent-templates` | 无 Workspace 参数 | Agent Template list schema |
| `loadAgentTemplate` | `GET /agent-templates/{templateId}` | path | Agent Template schema |
| `createJourneyAgent` | `POST /journeys/{journeyId}/slots/{slotId}/agent` | `{expectedRevision}` | create-or-instantiate response schema |
| `instantiateAgentTemplate` | `POST /journeys/{journeyId}/slots/{slotId}/agent-template/{templateId}` | `{expectedRevision}` | create-or-instantiate response schema |
| `saveAgentAsTemplate` | `POST /journeys/{journeyId}/agents/{agentId}/commands/save-as-template` | `{name, description}` | Agent Template schema |
| `removeOccupiedSlot` | `POST /journeys/{journeyId}/slots/{slotId}/commands/remove` | expected revision/Agent/action | remove response schema |

所有 UUID path segment 必须先通过共享 schema 验证并使用 `encodeURIComponent`。JSON mutation 使用 `Content-Type: application/json`。当前 API 不需要 credentials 或客户端 Workspace header。

## 5. HTTP adapter 结构

建议文件：

```text
apps/web/src/repositories/
├─ editorRepository.ts              # ports
├─ http/
│  ├─ httpEditorRepository.ts       # OdysseyEditorRepository implementation
│  ├─ httpTransport.ts              # request, JSON/204 handling, AbortSignal
│  ├─ apiError.ts                    # error envelope validation + normalization
│  └─ responseSchemas.ts             # endpoint-specific response schemas/mappers
├─ inMemoryEditorRepository.ts      # test double, aligned ports
└─ index.ts
```

`HttpEditorRepository` 支持注入：

```ts
interface HttpEditorRepositoryOptions {
  baseUrl: string
  fetchImplementation?: typeof fetch
  systemVariableIds?: readonly string[]
}
```

注入 fetch 只用于 deterministic adapter tests；业务代码使用浏览器 global fetch。

`httpTransport` 必须区分：

- JSON success；
- `204 No Content`；
- JSON API error；
- non-JSON/invalid JSON；
- network rejection；
- AbortSignal cancellation；
- 非预期 status/code 组合。

不能对 `204` 调用 `response.json()`，也不能把非 2xx 的任意 payload 强制断言成 error contract。

## 6. Repository error model

扩展当前过窄的 repository error union，保留 transport 与 server domain error 的区别：

```ts
type RepositoryError =
  | { code: 'ABORTED' }
  | { code: 'NETWORK_FAILED' }
  | { code: 'REQUEST_INVALID' }
  | { code: 'RESPONSE_INVALID' }
  | { code: 'NOT_FOUND' }
  | {
      code: 'REVISION_CONFLICT'
      expectedRevision: Revision
      currentRevision: Revision
    }
  | { code: 'VALIDATION_FAILED'; issues: ValidationIssue[] }
  | { code: 'STATE_CONFLICT'; reason: StateConflictReason }
  | { code: 'LEGACY_PATTERN_UNSUPPORTED' }
  | { code: 'CURRENT_WORKSPACE_UNAVAILABLE' }
```

`ValidationIssue`、`StateConflictReason` 和 conflict details 使用严格 schema，不以长期 `Record<string, unknown>` 代替。当前已知 state reasons：

- `PATTERN_IMMUTABLE`；
- `OCCUPIED_SLOT_REMOVAL_REQUIRES_COMMAND`；
- `SLOT_OCCUPIED`；
- `SLOT_AGENT_CHANGED`。

映射规则：

- DOM `AbortError` → `ABORTED`；
- fetch rejection → `NETWORK_FAILED`；
- 本地 input runtime validation failure → `REQUEST_INVALID`；
- success/error payload schema failure → `RESPONSE_INVALID`；
- backend stable code → 对应 repository error；
- `REVISION_CONFLICT` 必须验证 expected/current revision；
- 不能仅凭 HTTP status 猜测业务 code；status 与合法 error envelope 共同校验；
- UI 文案仍由 view/store presentation mapping 决定。

## 7. App runtime 选择

`createEditorRepository()` 改为创建 `HttpEditorRepository`：

```text
import.meta.env.VITE_API_BASE_URL
→ validate configuration
→ new HttpEditorRepository(...)
→ provide as OdysseyEditorRepository
```

要求：

- 正式 `main.ts` 路径只提供 HTTP repository；
- component/store tests 继续显式 inject `InMemoryEditorRepository`；
- fixture 不进入 HTTP runtime fallback；
- 如需要独立交互演示，应建立显式 demo/test harness，而不是生产分支中的隐式 fallback；
- 增加 `vite-env.d.ts` 或等价严格 `ImportMetaEnv` 声明；
- `.env.example` 保持唯一公开配置样例，不提交个人 secrets。

## 8. Store 与交互调整

### 8.1 Journey list/create/delete

- list、create、load 使用 canonical response；
- empty list 是正常 ready state，不回填 fixture；
- create 成功导航返回的 Journey ID；
- delete 使用当前 summary revision 生成 quoted `If-Match`；
- delete `204` 后才从列表移除；失败保持原列表和确认 UI。

### 8.2 Journey autosave

- `saveJourney` adapter 验证完整 canonical response；
- store 只采纳与当前 request/snapshot sequence 对应的 revision/updatedAt；
- stale response 不覆盖新编辑；
- `REVISION_CONFLICT` 进入明确 conflict state并停止自动重试；
- `STATE_CONFLICT` 不伪装成 network failure。

### 8.3 Agent lifecycle

- 创建最小 Agent 时从当前 Journey document 读取 `expectedRevision`；
- 不再弹出或发送 Agent name/description；
- Template list/load 不传 Workspace；
- instantiate 从当前 Journey revision 构造 request；
- save-as-template 不传 owner Workspace；
- create/instantiate/remove command 成功后原子替换 canonical Journey；
- 返回 Agent 时再导航 Workflow Editor，不能先乐观创建本地 Agent ID。

### 8.4 Occupied Slot removal

- empty Slot 可继续由纯 domain command 删除后 ordinary Journey save；
- occupied Slot 必须进入确认状态并调用 `removeOccupiedSlot`；
- 用户明确选择 discard 或 save-as-template-and-discard；
- request 携带 `expectedAgentId`，防止确认期间 Slot Agent 被替换；
- command 失败时本地 Journey、Template library 和路由均保持不变。

## 9. 实施批次

### Batch A — Contract convergence

- 调整共享 Agent lifecycle inputs 和 repository ports；
- 新增 occupied Slot removal schemas/port；
- 扩展严格 RepositoryError union；
- 同步修改 stores、in-memory repository 和现有 tests；
- 运行 schemas/web typecheck 和 tests，确保尚未接 HTTP 时行为仍稳定。

### Batch B — HTTP transport and adapter

- 实现 base URL/config validation；
- 实现 JSON、204、abort、network 与 error-envelope transport；
- 实现 endpoint-specific request/response mapping；
- 为每个 repository operation 增加 request assertion 和 success validation test；
- 覆盖 invalid response、404、409 revision、409 state、422、503、abort、network failure。

### Batch C — Runtime wiring

- app runtime 切换为 HTTP repository；
- 保留 tests 的显式 in-memory injection；
- 移除 Journey list 的 runtime fixture；
- 验证 loading、empty、error、retry 和 route boundary。

### Batch D — Agent and occupied removal integration

- 收口最小 Agent 创建交互；
- 接入 Template list/load/save/instantiate；
- 接入 occupied Slot atomic removal confirmation；
- 验证 canonical response replacement 与 revision advancement。

### Batch E — Real backend acceptance

- 在 PostgreSQL 环境执行浏览器 CRUD；
- 验证 refresh persistence；
- 验证 stale revision conflict；
- 清理由验收创建的专用 Journey，不触碰用户已有数据；
- 完整 lint、typecheck、test、build。

## 10. 测试矩阵

### 10.1 HTTP adapter tests

每个 endpoint 至少覆盖：

- 正确 method、URL、body、header；
- AbortSignal 被传递；
- success response runtime validation；
- malformed JSON / schema mismatch → `RESPONSE_INVALID`；
- abort → `ABORTED`；
- fetch rejection → `NETWORK_FAILED`。

专项覆盖：

- DELETE 使用精确 `If-Match: "3"` 且接受空 `204`；
- save Journey/Workflow 从 canonical document 映射 compact success；
- Agent Template request 不含 Workspace；
- create/instantiate request 只发送 expected revision；
- occupied removal action discriminated union 序列化正确；
- revision conflict details 完整；
- status 与 error code 不匹配时 fail closed。

### 10.2 Store/component tests

- HTTP empty Journey list 不出现 fixture；
- create success/failure/double-submit/abort；
- autosave saving 中继续编辑；
- stale save response 不覆盖新 document；
- revision conflict 停止 retry；
- create minimal Agent 不要求 name；
- create/instantiate 返回后才导航；
- occupied removal cancel/failure/discard/save-template-and-discard；
- Template 列表 refresh 后可恢复后端 Template；
- 503 Workspace error 有稳定页面反馈。

### 10.3 Browser acceptance

使用专用验收数据：

1. 初始空列表正常显示；
2. 分别创建四种 Pattern Journey；
3. 刷新列表和 Editor，数据保持；
4. 对动态 Pattern 增加/删除 empty Slot并保存；

6. 修改 Workflow，保存并刷新恢复；

浏览器验收不得删除非本次创建的数据。

## 11. Definition of Done

1. 正式 app runtime 使用 `HttpEditorRepository`，不再显示内存 fixture。
2. 所有 API response 和 error envelope 均在 repository boundary runtime validated。
3. Workspace 不出现在客户端 Template list/load/save request 中。
4. Journey create/list/load/save/delete 全部使用真实 PostgreSQL persistence。
5. Journey 和 Workflow save 正确处理 revision、stale response 和 conflict。
6. Agent minimal create、Template list/load/save/instantiate 使用冻结 API contract。
7. occupied Slot removal 只通过 atomic command 完成。
8. delete 使用 quoted `If-Match` 并正确处理 `204`。
9. abort、network、invalid response、404、409、422、503 均有稳定 typed error 路径。
10. In-memory repository 继续作为相同 port 的 deterministic test double。
11. adapter、store、component 和真实浏览器验收通过。
12. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。

## 12. 实施结论

后端与本地环境已经 ready，不存在继续阻止编码的 backend blocker。前端不能直接只新增一个 `fetch` class；必须先完成 Batch A 的 port 收口，尤其是移除客户端 Workspace、把 expected revision 加入 Agent command，并补齐 occupied Slot atomic command。完成该收口后，Batch B–E 可以连续实施。
