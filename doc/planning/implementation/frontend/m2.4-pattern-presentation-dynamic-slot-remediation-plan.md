# Odyssey M2.4 Pattern Presentation 与动态 Slot 交互修正方案

> Status: Product decisions confirmed; ready for implementation  
> Milestone: M2.4 remediation  
> Scope: 固定 System Canvas 中的 Pattern topology presentation、动态 Slot 增删/重排、空 Slot 创建 Agent、Agent/Slot typed DnD 隔离  
> Authoritative design: **Odyssey UI Drafts**；被遮挡或缺失的拓扑细节参考早期 `Header - TopNavBar` 设计  
> Authoritative engineering guideline: [`frontend-engineering-guidelines.md`](../../../frontend-engineering-guidelines.md)  
> Parent plan: [`m2.4-system-canvas-agent-slot-typed-dnd-implementation-plan.md`](./m2.4-system-canvas-agent-slot-typed-dnd-implementation-plan.md)
> Diamond decision: [`diamond-loop-pattern-decision.md`](../../../architecture/domain/diamond-loop-pattern-decision.md)

## 1. 背景与问题

当前 Journey Editor 已接入 M2.4 的 Pattern、Agent Slot、typed DnD 和 context menu，但 System Canvas 中的 Pattern 图形存在明显 presentation 缺陷：

- `pattern-stage` 使用固定 `720 × 420` 逻辑画布，再整体 `scale(.48)` 塞入约 370 px 的 Execution 容器；
- Slot 圆形节点、名称、状态与拖动把手被同时缩小，交互目标和文字可读性不足；
- Route 使用 Slot 中心作为端点，连线穿过名称、状态或控制元素；
- Linear 示例看似被固定为三个 Slot，布局不能正确表达动态 Slot 数量；
- Slot reorder 控件的 presentation 与节点割裂；
- 点击空 Slot 仍显示临时创建表单，没有直接完成最小 Agent 创建并进入 Workflow Editor。

这些问题属于 M2.4，而不是 M2.5：M2.4 的职责包含固定 System Canvas、四种 Pattern topology、Slot/Route presentation、Agent Slot DnD 与真实浏览器交互证明。M2.5 只负责只读 Workflow Preview，不负责修正 Pattern topology。

## 2. 已确认的产品决策

### 2.1 Pattern 与 Slot 数量

Pattern kind 定义拓扑规则，不把示例 Slot 数量当成固定数量。

| Pattern kind | Slot 数量 | 增删 | 重排 |
| --- | --- | --- | --- |
| `solo_component` | 固定 1 个 | 不允许 | 不允许 |
| `linear_sequence` | 动态 | 允许 | 允许 |
| `hub_and_spoke` | 动态 | 允许增删 Spoke；Hub 必须保留 | 不按 Linear 顺序重排 |
| `diamond_loop` | 动态，至少 2 个 | 允许；保持单向闭环与唯一入口 | 允许 strategy 定义的环顺序重排；不包含分支/汇合 |

Slot 的新增、删除和重排能力必须来自 `PatternStrategy` / Pattern definition，不由组件根据 kind 临时拼接规则。

### 2.2 Slot 视觉状态

- 未配置 Agent 的 Slot：空心圆；
- 已配置 Agent 的 Slot：实心圆；
- 缺失 Agent summary：独立诊断状态，不能伪装为空 Slot；
- 无论是否配置 Agent，Slot 都属于 Pattern topology，route 必须继续连接它；
- 状态反馈不能只依赖颜色，必须保留可访问名称或文本反馈。

### 2.3 点击空 Slot

点击空 Slot 不显示 Agent name/description 表单，而是执行单一原子用例：

```text
Click empty Slot
→ typed create-minimal-agent intent
→ repository/application transaction
→ create Agent identity
→ create minimum Start → End WorkflowGraph and CanvasLayout
→ append Journey Agent summary
→ assign Agent to the selected Slot
→ persist with the Journey transaction
→ navigate to the new Agent Workflow Editor
```

要求：

- 失败时不留下 orphan Agent、半完成 Slot assignment 或错误导航；
- 请求期间阻止重复提交；
- 响应必须经过 runtime validation；
- 只有原子创建成功后才导航；
- 普通 Journey Agent 创建阶段不要求用户输入名称或描述；
- 如果当前 schema 强制要求 `AgentSummary.name`，由 application/domain factory 生成稳定的默认展示名，不把该默认名冒充用户命名的 Template 名称。

### 2.4 Save as Template

- Agent Template 的名称与描述只在 `Save as template` 时要求用户输入；
- 保存的是独立 reusable snapshot，不与 Journey Agent 建立 live link；
- Template 名称不得反向覆盖 Journey 中 Agent identity 或 Workflow；
- 操作继续使用右键菜单与 modal/dialog，不恢复常驻底部表单。

### 2.5 Slot context menu

按能力显示或禁用以下操作：

- `Add slot before`；
- `Add slot after`；
- Pattern 只有无方向 add 语义时显示 `Add slot`；
- `Remove slot`；
- Linear 可用时显示 `Move earlier` / `Move later`；
- 已配置 Agent 时继续显示 Agent 相关操作。

组件只 emit typed intent；可用性与最终合法性由 Pattern capability 和 domain command 决定。

### 2.6 删除规则

- 删除空 Slot：可以直接 dispatch domain command，但仍需验证 minimum cardinality、immutable role 和 topology invariant；
- 删除已配置 Agent 的 Slot：必须先显示 destructive confirmation，明确 Agent 影响范围；
- 确认后通过正式的原子 transaction boundary 同时处理 Slot、routes、assignment 与受影响 Agent；
- 当前 repository/API 若没有可信事务接口，只能 stage typed request，不能通过多个独立 save 伪造成功；
- 失败或取消不得改变 canonical document。

## 3. 交互语义隔离

### 3.1 Agent drag

拖动实心 Agent 节点：

```ts
{ version: 1; kind: 'assigned-agent'; agentId: UUID; sourceSlotId: UUID }
```

只表达：

- move Agent 到空 Slot；
- exchange 两个已配置 Slot 的 Agent；
- 不改变 Slot identity、order 或 topology role。

### 3.2 Slot reorder drag

拖动 Slot 自身的 reorder handle：

```ts
{ version: 1; kind: 'pattern-slot'; slotId: UUID }
```

只表达：

- Linear Slot reorder；
- Agent 跟随其所属 Slot；
- drop 前通过 `evaluatePatternDrop` / strategy capability preflight；
- 成功后由 `reorderSlot` command 生成新 PatternConfig，再重新派生 routes/layout。

Agent drag 与 Slot drag 必须拥有不同的可见拖动入口，不能依赖按下位置、CSS class 或运行时猜测来区分业务语义。

### 3.3 Slot add/remove intent

建议冻结为显式 intent：

```ts
type SlotMenuIntent =
  | { type: 'add-slot'; anchorSlotId: UUID; placement: 'before' | 'after' }
  | { type: 'remove-slot'; slotId: UUID }
  | { type: 'request-remove-occupied-slot'; slotId: UUID; agentId: UUID }
```

`hub_and_spoke` 或 `diamond_loop` 如果不适合通用 before/after 语义，必须由 strategy 将 UI intent 映射为正式 operation，或向组件暴露对应的菜单 capability。Circular Loop 的 before/after 表示环形执行顺序中的前驱/后继位置；组件不得自行指定或迁移入口。

## 4. Pattern presentation 方案

### 4.1 禁止整体缩放交互内容

移除当前依赖：

```css
.pattern-stage {
  width: 720px;
  height: 420px;
  transform: scale(.48);
}
```

不得再把字体、点击目标、focus ring 和 drag handle 与几何画布一起整体缩小。

### 4.2 分离逻辑拓扑与容器布局

Domain/strategy 继续派生无 DOM 依赖的逻辑拓扑；System Canvas adapter 接收可用 presentation bounds，并生成：

```ts
interface SystemCanvasGeometry {
  readonly viewport: { width: number; height: number }
  readonly slots: readonly {
    slotId: UUID
    center: CanvasPoint
    inputAnchor: CanvasPoint
    outputAnchor: CanvasPoint
    labelPlacement: 'top' | 'bottom' | 'left' | 'right'
  }[]
  readonly routes: readonly {
    routeId: UUID
    points: readonly CanvasPoint[]
  }[]
}
```

要求：

- persisted PatternConfig 不保存像素坐标；
- resize 只重新计算 presentation geometry；
- Slot key 与 route identity 保持稳定；
- 高频 resize 不修改 document 或触发 persistence；
- adapter 不依赖 Vue、DOM 或 Vue Flow 类型。

### 4.3 Route anchor

- route 连接圆形 Slot 节点的边缘 anchor，不连接整个 Slot 文本容器的中心；
- Linear 通常使用左右 anchor；
- Hub/Diamond 根据 strategy presentation 使用明确方向的 anchor；
- route 位于节点视觉层下方；
- label、status、feedback、reorder handle 不得覆盖 route；
- route endpoint 必须引用存在的 Slot view model。

### 4.4 动态数量布局

布局算法至少考虑：

- 可用容器宽高；
- Slot 直径；
- label/status 所需空间；
- 最小可操作间距；
- Pattern-specific topology；
- 实际 Slot 数量。

推荐策略：

- Linear：在可用主轴空间内均匀分布，数量增加时优先扩展/滚动 presentation surface，而不是无限缩小节点；
- Hub and spoke：Hub 固定为中心角色，Spoke 按数量分布在允许的弧线或环形区域；
- Diamond loop / Circular Loop：按环形执行顺序布局，明确标记唯一入口，最后一个 Slot 以带箭头 route 连回入口；不绘制分支、审核层或汇合结构；
- Solo：单节点居中。

当 Slot 数量超过当前容器的舒适容量时，采用明确的局部 overflow/pan 策略；不得缩小到低于可读字体和可操作目标下限。

### 4.5 Slot 组件结构

Slot presentation 应明确分层：

```text
Slot wrapper
├─ route anchors（非交互 presentation）
├─ Agent node button（空心/实心、点击与 Agent drag）
├─ label/status
├─ reorder handle（仅 capability 允许时）
└─ feedback / selection / focus state
```

拖动把手必须属于 Slot 节点，不再成为路线下方的孤立符号。默认低对比显示，hover/focus/dragging 时增强；键盘等价操作由 context menu 提供。

## 5. 分层修改范围

### 5.1 Domain / Pattern strategy

审计并补齐：

- `addSlot`、`removeSlot`、`reorderSlot` 的 capability；
- `solo_component` 固定 cardinality；
- Linear 动态 cardinality 与 reorder invariant；
- Hub 的 immutable Hub 与动态 Spoke；
- Circular Loop 的唯一入口、环形顺序、闭环 route、至少两个 Slot，以及删除入口时由 domain 原子提升相邻 Slot 的规则；
- operation success 后 routes 完整重新派生；
- command 输入不被 mutation。

Circular Loop 的总体语义已由产品确认。实现前仅需冻结“删除入口时提升前驱还是后继”为入口这一条 domain 规则；在冻结前不得由 UI 猜测或开放该删除路径。

### 5.2 Repository / transaction boundary

确认或增加：

- `createMinimumAgentAndAssign` 原子 port；
- occupied Slot deletion 的原子 request/result contract；
- stale request/abort/navigation protection；
- runtime response validation；
- transaction failure 不改变本地 canonical document。

### 5.3 Store

增加或调整：

- click empty Slot → create minimum Agent → success navigation result；
- Slot menu add/remove intents；
- occupied remove confirmation state；
- drag session 对 `assigned-agent` 与 `pattern-slot` 的互斥处理；
- command success 后 selection/menu/preview reconciliation；
- operation loading/error state；
- 不把 container size、anchor 或 hover 写入 save payload。

### 5.4 Canvas adapter

调整：

- 从固定坐标输出升级为基于 bounds 的 geometry；
- 为 Slot 输出 route anchors 和 label placement；
- 四种 Pattern 采用各自 strategy presentation；
- 动态 Slot 数量与 resize；
- diagnostic 不使用 fallback 坐标掩盖 topology 错误。

### 5.5 Components

主要文件：

- `SystemCanvas.vue`：提供容器 bounds、渲染 geometry，不实现业务规则；
- `PatternRouteLayer.vue`：支持 route points/path 与正确 layering；
- `AgentSlot.vue`：空/实心节点、Agent drag、Slot reorder handle；
- `AgentSlotContextMenu.vue`：按 capability 渲染 add/remove/move；
- `JourneyEditorView.vue`：连接 store/repository/router，不再渲染空 Slot 创建表单；
- `journey-editor.css`：移除整体 scale，建立正常字体、节点和交互目标尺寸。

## 6. 建议实施批次

### Batch A — Freeze dynamic Slot capabilities

- 审计四种 Pattern definitions/strategies；
- 明确每种 Pattern 的 add/remove/reorder operation；
- 补齐 domain invariant tests；
- 按 accepted Circular Loop decision 更新 strategy；冻结删除入口时的新入口提升规则。

验收：没有 Vue/DOM 改动；纯 domain 测试证明动态 Slot 不破坏 topology。

### Batch B — Responsive presentation geometry

- 定义 bounds 与 route anchor view model；
- 实现四种 Pattern 的动态布局；
- 移除 `.pattern-stage` 整体缩放；
- 修正 Slot、label、route、handle layering。

验收：四种 Pattern 在多种 Slot 数量下无重叠、无穿字、无失配端点。

### Batch C — Empty Slot creation and navigation

- 删除空 Slot inline create form；
- 接通原子 minimum Agent creation；
- 成功后进入 Workflow Editor；
- 覆盖 failure、abort、double click 与 stale navigation。

验收：成功只产生一个 Agent；失败不产生 orphan；导航只发生在成功后。

### Batch D — Slot menu add/remove and destructive confirmation

- 添加 capability-driven menu actions；
- 空 Slot remove 直接走 domain command；
- occupied Slot remove 使用 confirmation 与 transaction boundary；
- add/remove 后 reconciliation。

验收：Solo 不显示非法操作；其他 Pattern 的操作保持 invariants；失败不产生部分状态。

### Batch E — DnD integration and browser proof

- 复核 Agent drag 与 Slot drag 的入口隔离；
- 添加 reorder insertion feedback；
- 覆盖 resize、drag cancel、invalid drop；
- 真实浏览器验证。

验收：Agent move/exchange 不触发 reorder；Slot reorder 不交换 Agent identity；route/layout 正确重新派生。

## 7. 测试矩阵

### 7.1 Domain

- Solo add/remove/reorder 全部按 capability 拒绝；
- Linear 3、4、N Slot add/remove/reorder；
- Hub 增删 Spoke，不允许删除 Hub；
- Circular Loop 增删/重排后保持唯一入口、至少两个 Slot，以及每个 Slot 恰好一个 successor 的闭环 route；
- minimum cardinality；
- occupied remove transaction candidate；
- 输入 immutable；
- route 只引用存在 Slot；
- Slot ID 始终唯一；
- 一个 Agent 最多占用一个 Slot。

### 7.2 Adapter

- 四种 Pattern × empty/configured/missing-summary；
- 四种 Pattern × minimum/default/many Slot counts；
- 1024 与 1440 desktop bounds；
- route endpoint 等于对应 orb anchor；
- route 不经过 label/status bounds；
- resize 前后 document 深度相等；
- output 不含 DOM/Vue Flow 类型。

### 7.3 Components / integration

- 空 Slot 为空心，配置后为实心；
- 点击空 Slot只发出 create intent，不出现 name form；
- create 成功导航，失败停留并显示 stable error；
- context menu capability 显示正确；
- occupied remove confirmation；
- `assigned-agent` 与 `pattern-slot` payload 不串扰；
- keyboard menu 可以完成 add/remove/reorder；
- Esc 取消 drag/menu/dialog；
- focus return 正确。

### 7.4 Browser

- 1440×900 与约 1024px narrow desktop；
- Linear 3、4、较多 Slot；
- Hub/Circular Loop 动态 Slot；Circular Loop 的最后一个 Slot 必须带箭头连回入口；
- route 不穿过文字；
- Agent drag move/exchange；
- Slot drag reorder；
- 点击空 Slot创建并导航；
- add/remove 与 destructive confirmation；
- resize 后 Slot/route 对齐。

## 8. Definition of Done

1. 不再使用整体 transform 缩小 Pattern 的文字和交互目标。
2. Route 使用节点边缘 anchor，不穿过 label、status 或 reorder handle。
3. Solo 固定一个 Slot；Linear、Hub、Circular Loop 按 strategy 支持动态 Slot 数量；Circular Loop 至少两个 Slot并保持唯一入口。
4. 空 Slot为空心、配置 Slot为实心，二者均参与 topology。
5. 点击空 Slot原子创建最小 `Start → End` Agent，成功后直接进入 Workflow Editor。
6. 普通 Agent 创建不要求 name/description 表单；Template 保存继续要求名称。
7. Slot context menu 支持 capability-driven add/remove；Linear 支持 move earlier/later。
8. occupied Slot 删除经过破坏性确认和可信 transaction boundary。
9. Agent drag 与 Slot reorder 使用不同 typed payload，互不串扰。
10. Slot 数量变化后 routes/layout 由 strategy/adapter 重新派生，坐标不进入 persistence。
11. domain、adapter、component、integration 和 browser tests 覆盖本方案矩阵。
12. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。

## 9. 实施前剩余 Decision Gate

Circular Loop 的产品语义已经确认：动态 Slot、唯一入口、单向闭环、最后 Slot 返回入口，不包含分支或汇合。实现前只剩一个需要由 domain 冻结的细节：

- 删除当前入口时，是提升执行顺序中的后继 Slot，还是前驱 Slot为新入口。

建议默认提升后继 Slot，因为它最能保持入口之后的原执行顺序。该规则需要写入 strategy/command test，并与 Slot 删除作为一次原子变更；组件或 adapter 不得自行决定。
