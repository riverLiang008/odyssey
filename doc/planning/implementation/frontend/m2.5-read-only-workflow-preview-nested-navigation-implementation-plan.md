# Odyssey M2.5 Read-only Workflow Preview 与 Nested Navigation Implementation Plan

> Status: Implemented — ready for independent acceptance  
> Milestone: M2.5  
> Scope: Journey Editor 中单一只读 Workflow Preview、异步加载、切换/关闭与 Agent Workflow nested navigation  
> Prerequisite: M2.2、M2.4 accepted  
> Authoritative guideline: [`frontend-engineering-guidelines.md`](../../../frontend-engineering-guidelines.md)  
> IA reference: [`odyssey-figma-information-architecture.md`](../../../product/information-architecture/odyssey-figma-information-architecture.md)  
> Parent plan: [`m2-interaction-proof-frontend-implementation.md`](./m2-interaction-proof-frontend-implementation.md)

## 1. 目标

M2.5 完成以下 progressive disclosure：

```text
configured Agent Slot / active Guardrail Agent
→ select
→ Journey Editor 右下角唯一的 read-only Workflow Preview
→ Open canvas
→ owning Agent Workflow Editor
→ Back
→ owning Journey Editor
```

完成后，用户可以在不离开 Journey 的情况下快速理解某个 Agent Workflow 的拓扑；只有显式点击 `Open canvas` 或使用已有右键菜单 `Open workflow` 时才进入完整 Workflow Editor。

M2.5 不重写 M2.4 的 Pattern presentation、Slot layout、route、DnD、Guardrail lifecycle 或 context menu。

## 2. 已冻结的产品与工程决策

### 2.1 Preview 行为

1. 左键或键盘激活 configured Execution Slot 时，选中 Slot 并打开该 Agent Preview。
2. 左键或键盘激活 active Input/Output Guardrail Agent 时，打开同一个 Preview 组件。
3. Empty Slot 左键仍然只选中，不创建 Agent；同时显式关闭现有 Preview，避免 selection 与 Preview identity 不一致。
4. 同时最多一个 Preview；选择另一 configured Agent 时原位替换内容，不叠加窗口。
5. 点击当前 configured Agent 保持 Preview 打开，不执行 toggle close。
6. Preview 只能通过明确的 Close 按钮、选择 Empty Slot、Agent/Slot 被删除或 Journey 被卸载而关闭。
7. 右键 context menu 保持 M2.4 行为，不以 hover、menu open 或 drag 触发 Workflow 加载。

### 2.2 数据与后端边界

1. 复用现有 `EditorRepository.loadAgentWorkflow(journeyId, agentId, { signal })`。
2. 不新增 Preview endpoint、backend entity、数据库字段或保存接口。
3. Preview 使用 repository 返回并通过 runtime schema 验证的 `AgentWorkflowEditorDocument`。
4. Preview 不复制到 Journey document，也不写入 Journey/Agent save payload。
5. Preview 不复用可编辑 `workflowEditor` Pinia session，避免 selection、panel、mode、focus 和 mutation handler 串扰。

### 2.3 Canvas 技术选择

M2.5 使用独立、轻量的 SVG/HTML read-only adapter，不依赖 Vue Flow：

- 当前完整 Workflow Editor 仍是 M2.6/M2.7 前的占位页面；提前复用不存在的 editable adapter 会阻塞 M2.5；
- Preview adapter 只把 `WorkflowGraph + CanvasLayout` 投影成只读 node/edge view model；
- M2.7 若引入统一 adapter，可在保持 M2.5 public contract 与测试不变的前提下替换内部 renderer；
- Preview 组件不得暴露 drag/connect/delete/configure emits，不能仅靠 CSS 隐藏编辑控件模拟只读。

### 2.4 布局与视觉

1. Preview 是 Journey Editor 内的 picture-in-picture surface，不是 modal、panel route 或新的 tab。
2. 桌面端锚定 Journey System Canvas 右下角，位于内容之上但不遮挡全局导航。
3. 推荐基准尺寸约 `360 × 230 px`，使用 token、现有圆角与阴影；具体尺寸在实现前对照对应 Figma node。
4. 约 1024 px 宽度下仍保持可读，可收窄但不得压缩成不可识别拓扑；更窄 viewport 可改为 System Canvas 下方的流式 card。
5. Header 显示 Agent name、只读状态、Close 和 `Open canvas`；主体显示 loading/ready/empty/error 四类状态。

## 3. 状态所有权与状态机

### 3.1 UI-only state

Journey store 保留现有 `selectedSlotId` 和 `previewAgentId`，并新增明确的 Preview load state：

```ts
type WorkflowPreviewState =
  | { type: 'closed' }
  | { type: 'loading'; agentId: UUID; requestSeq: number }
  | { type: 'ready'; agentId: UUID }
  | { type: 'error'; agentId: UUID; error: RepositoryError }
```

实际加载的 `AgentWorkflowEditorDocument | null` 使用独立 `shallowRef` 保存。它是当前 repository snapshot，不是持久化 UI state，也不是 Journey document 的嵌套副本。

必须保持：

```text
previewAgentId === null  ⇔  previewState.type === 'closed'
previewState ready       ⇒  previewDocument.agent.id === previewAgentId
previewDocument.agent.journeyId === current Journey id
```

### 3.2 Typed intents

建议 store/application shell 只暴露：

```ts
selectSlotForPreview(slotId, repository)
selectGuardrailForPreview(side, repository)
openWorkflowPreview(agentId, repository)
closeWorkflowPreview()
retryWorkflowPreview(repository)
```

组件只 emit identity intent；不得直接调用 repository、router 或写 store document。

### 3.3 异步安全

Preview loader 必须维护：

- `previewRequestSeq`；
- 单一 `AbortController`；
- current Journey/Agent identity 校验；
- stale response ignore；
- close、switch Agent、route unload 和 store dispose 时 abort。

切换 `Agent A → Agent B` 后，A 的晚到响应不得覆盖 B。切换时旧图立即离场，显示 B 的局部 loading state，不展示错 Agent 的旧内容。

Repository errors 映射为 Preview 局部错误：

- `NOT_FOUND`：Agent Workflow unavailable；
- `NETWORK_FAILED` / `RESPONSE_INVALID`：显示 Retry；
- `ABORTED`：不展示错误；
- Journey 主 document 保持可用，Preview 加载失败不能升级成整页 RouteBoundary。

## 4. Read-only Preview Adapter

### 4.1 输入与输出

```ts
interface WorkflowPreviewBounds {
  width: number
  height: number
  padding: number
}

interface WorkflowPreviewViewModel {
  agentId: UUID
  agentName: string
  nodes: readonly WorkflowPreviewNode[]
  edges: readonly WorkflowPreviewEdge[]
  bounds: WorkflowPreviewBounds
  diagnostics: readonly WorkflowPreviewDiagnostic[]
}
```

Adapter 输入只包含经过验证的 `WorkflowGraph`、`CanvasLayout` 与 presentation bounds；输出只包含 SVG/HTML renderer 所需字段，不包含 Vue、DOM、Vue Flow 或 mutable handler。

### 4.2 Fit-to-bounds 算法

1. 通过 `nodeId` 合并 semantic node 与 layout placement。
2. 计算所有有效 placement 的 source bounding box。
3. 在扣除 header 和 padding 后计算统一 scale：

```text
scale = min(availableWidth / sourceWidth, availableHeight / sourceHeight)
```

4. 保持纵横比并居中，禁止 x/y 分别拉伸。
5. source width/height 为 0 时使用稳定 fallback extent，避免除零。
6. Node 使用固定的 Preview minimum/maximum size；长 label 截断并保留可访问名称。
7. Edge 从节点边缘连接，箭头形状复用 Odyssey 当前 route visual language。
8. layout placement 缺失、edge endpoint 缺失时输出 diagnostics，跳过无效 edge，不使用 non-null assertion 掩盖问题。
9. Adapter 不修改 graph/layout 输入，不把 fit 后坐标写回 repository。

### 4.3 Read-only contract

`WorkflowPreviewCanvas.vue` 只能提供：

- rendered nodes/edges；
- accessible topology summary；
- Empty/diagnostic presentation。

不得提供：

- draggable attribute；
- connect handle；
- node/edge selection emit；
- Delete/Backspace mutation handler；
- configuration panel intent；
- viewport persistence；
- drop target。

建议新增：

```text
apps/web/src/
├─ canvas/workflow-preview/
│  ├─ workflowPreviewAdapter.ts
│  └─ workflowPreviewAdapter.test.ts
├─ features/journey-editor/
│  ├─ WorkflowPreview.vue
│  ├─ WorkflowPreviewCanvas.vue
│  └─ WorkflowPreview.test.ts
```

建议修改：

```text
apps/web/src/stores/journeyEditor.ts

apps/web/src/views/JourneyEditorView.vue
apps/web/src/views/JourneyEditorView.test.ts
apps/web/src/features/journey-editor/journey-editor.css
```

边界：

- `workflowPreviewAdapter.ts` 是纯函数；
- `WorkflowPreviewCanvas.vue` 是纯展示组件；
- `WorkflowPreview.vue` 负责 Preview shell 与 typed emits，不调用 repository/router；
- Journey store 负责加载、abort、stale response 与 session reconciliation；
- Journey view 负责把 `Open canvas` intent 转换成 typed route navigation。

## 6. 导航 contract

### 6.1 Open canvas

Preview 的 `Open canvas` 使用既有：

```ts
routeLocations.agentWorkflow(journeyId, agentId)
```

禁止字符串拼接 URL。Slot select 只打开 Preview，不调用 router。

### 6.2 Back to Journey

Agent Workflow Editor 使用既有 owning Journey route：

```ts
routeLocations.journey(journeyId)
```

M2.5 不创建 Preview route，也不把 `previewAgentId` 写入 query。返回 Journey 后不保证恢复 Preview；默认重新进入稳定 closed session，避免把临时 UI 状态伪装成浏览器历史事实。

## 7. 实施步骤

### Step 1 — Freeze state、intent 与 error contract

交付：

- `WorkflowPreviewState` discriminated union；
- Preview session invariant；
- Slot/Guardrail selection → Preview intent mapping；
- error/loading/retry/close transition。

测试：

- configured、empty、missing Agent projection；
- close/retry/switch transition；
- session 不进入 `toSaveInput()`。

### Step 2 — Implement pure read-only adapter

交付：

- graph/layout → Preview view model；
- fit-to-bounds、edge anchoring、label simplification 与 diagnostics；
- Start/End/Task/Branch/Loop/Agent Action 的稳定 node presentation mapping。

测试：

- minimum `Start → End`；
- 多节点非方形 layout；
- single/zero extent；
- missing placement/endpoint；
- 输入未修改；
- bounds 改变时等比缩放且 topology identity 不变。

### Step 3 — Implement Preview components

交付：

- picture-in-picture shell；
- header、Agent identity、Read only badge、Close、Open canvas；
- loading/ready/error/retry/empty/diagnostic states；
- SVG nodes/edges；
- responsive desktop/narrow behavior。

测试：

- props → observable state；
- Close/Open/Retry 发出 typed identity intent；
- Canvas DOM 中不存在 draggable、connect、delete/configure control；
- keyboard focus、button labels、Escape close。

### Step 4 — Add async Preview orchestration to Journey store

交付：

- load、abort、retry、switch、close、dispose；
- configured Slot 与 active Guardrail 共用同一路径；
- Agent/Guardrail/Slot removal 后 reconciliation；
- stale response protection。

测试：

- single Preview invariant；
- A → B 切换且 A 晚到；
- close while loading；
- failure/retry；
- Journey unload abort；
- Preview document/session 不进入保存 payload。

### Step 5 — Connect Journey Editor and nested navigation

交付：

- configured Slot click 打开 Preview；
- Empty Slot click 选择并关闭 Preview；
- active Guardrail click 打开同一 Preview；
- Preview Close；
- Preview `Open canvas` 导航；
- Workflow Editor Back 返回 owning Journey。

测试：

- Slot click 不导航；
- Open canvas 才导航；
- context-menu Open workflow 继续直接导航；
- 切换 Slot 原位替换；
- Empty Slot 不调用 `loadAgentWorkflow`；
- Guardrail 与 Execution Agent 不产生两个 Preview。

### Step 6 — Accessibility、visual 与真实浏览器验证

交付：

- Preview region accessible name；
- Close/Open/Retry 可键盘操作；
- loading 使用 `role=status`，error 使用 `role=alert`；
- 1440 px 与约 1024 px viewport 检查；
- topology、箭头、label、overflow 与遮挡检查；
- console warning/error 检查。

浏览器路径：

```text
Journey → configured Slot → Preview
→ switch configured Slot → content replacement
→ close → reopen
→ Open canvas → Workflow Editor
→ Back → owning Journey
```

同时验证 active Input/Output Guardrail、minimum Start → End Workflow 与复杂 Workflow fixture。

### Step 7 — Full regression gate and completion handoff

运行：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

交付：

- M2.5 completion report；
- 独立 acceptance checklist/prompt；
- 测试数量与命令结果；
- M2.6 handoff：Preview adapter 只读事实、Workflow graph/layout fixtures 与 diagnostics，不把 renderer 反向变成 domain contract。

## 8. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| configured Execution Slot click | Slot selected，显示该 Agent Preview，不导航 |
| active Guardrail Agent click | 显示相同 Preview shell，不创建第二实例 |
| Empty Slot click | 只选择，不加载/创建 Agent，现有 Preview 关闭 |
| 当前 Agent 再次 click | Preview 保持打开 |
| Agent A → Agent B | 原位替换，最多一个 Preview |
| A request 晚于 B 返回 | A 不覆盖 B |
| loading 时 Close | request abort，Preview closed，无错误闪烁 |
| load failure | Journey 保持可用，Preview 局部错误可 Retry |
| minimum Workflow | Start → End 与箭头清晰可读 |
| complex Workflow | 等比 fit，拓扑关系与方向保持 |
| Preview node click/drag/Delete | 不产生 mutation、selection、panel 或 save |
| Open canvas | typed route 导航到对应 Agent Workflow Editor |
| Workflow Back | 返回 owning Journey |
| refresh Journey | Preview 默认 closed，持久化文档不含 Preview state |
| Agent/Slot/Guardrail removal | 相关 Preview 自动关闭，不保留 stale identity |

## 9. Definition of Done

M2.5 只有同时满足以下条件才可验收通过：

- configured Execution Slot 和 active Guardrail Agent 都使用唯一 Preview；
- Slot selection 与 Open canvas navigation 明确分离；
- Preview 从真实 Web API 加载，不使用 mock/fallback Workflow；
- graph/layout 只经纯 adapter 投影，fit 坐标不持久化；
- Preview 没有任何 mutation handler 或可编辑 session 泄漏；
- async switch/abort/stale/failure/retry 有自动化测试；
- 1440/1024 px 真实浏览器路径通过；
- console 无新增 warning/error；
- lint、typecheck、全部 tests、production build 全绿；
- M2.4 Pattern/Slot/DnD/Guardrail/Template 回归路径保持通过。

## 10. 明确不做

- Workflow graph mutation commands 与 validation（M2.6）；
- 完整 Vue Flow editable adapter（M2.7）；
- node palette、connect、drag、delete、configure panel；
- Preview 拖动、缩放、窗口位置持久化；
- Preview route/query/backend entity；
- 新的后端 CRUD 或专用 Preview API；
- 重写 M2.4 System Canvas、Pattern topology 或 context menu。

## 11. 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 快速切换 Agent 被旧响应覆盖 | requestSeq + AbortController + identity 校验 |
| Preview 与 editable store 相互污染 | 独立 read-only adapter/document/session，不挂载 workflowEditor store |
| 只隐藏控件但仍可修改 | Preview component API 不提供 mutation emit/handler |
| fit 算法拉伸或除零 | 单一等比 scale、fallback extent、纯函数边界测试 |
| Preview 状态进入保存数据 | `toSaveInput()` regression assertion |
| Teleport/浮层再次造成定位问题 | Preview 锚定明确 containing block；真实 1440/1024 浏览器检查 |
| M2.5 提前吞并 M2.6/M2.7 | 使用轻量 SVG renderer，冻结 replaceable adapter contract |
