> Status: Implemented and locally verified (2026-08-30)  
> Scope: M2.8 completion batch after First Batch acceptance  
> Depends on: M2.8 First Batch PASS, real Knowledge Space inventory API, current Agent aggregate load/save contract  
> Primary product reference: `doc/product/feature-specifications/resources/Update Agent Action Resource Configuration UI.md`

## 1. Outcome

Second Batch 将 M2.8 从“已有复杂节点和资源的主要编辑路径可用”补齐为完整产品路径：

```text
Workflow Palette
  ├─ Agent Action → typed creation draft → atomic node + placement
  └─ Loop         → typed creation draft → atomic Loop + body graph/layout

Collapsible Resource Browser
  ├─ Tools              → local search/page from current Agent aggregate
  └─ Knowledge Spaces   → Web API search/page
                              ↓
                    typed resource drag/drop
                              ↓
             root / Loop-child Agent Action config
```

本批不实现资源资产的创建与管理；只负责发现、绑定、解除绑定以及相关编辑器交互。

## 5. Entry audit and blockers

编码前记录真实环境证据：

1. `GET /api/v1/knowledge-spaces` 的 query/page/pageSize contract 与 stable ordering；
2. 当前 Agent aggregate 中 `variables` 和 `reusableTools` 的真实返回；
3. Agent save payload 仍只接受 `expectedRevision/workflow/layout/variables/reusableTools`；
4. 至少准备以下真实验收状态：
   - no variables；
   - at least one compatible Agent Variable；
   - no resources；
   - multiple Tools；
   - multiple Knowledge Spaces；
   - Knowledge Space empty/error；
5. 不允许使用 fixture、mock、localStorage 或假 UUID 补齐产品路径。

### 5.1 Model decision

当前 Agent Action canonical schema 只要求 non-empty `model` string，尚无 Model inventory API。本批 draft 使用用户显式填写且 runtime validated 的 model identifier；不得暗填固定模型。未来接入 Model inventory 时替换该 field adapter，不修改 Agent Action domain schema。

### 5.2 Loop prerequisite

Loop 必须引用当前 Agent aggregate 中真实存在且类型兼容的 Variable。若不存在：

- Palette 显示明确 prerequisite；
- click/keyboard/drop 均不得创建 Loop；
- 不提供假 Variable；
- 引导信息说明需要后续 Agent Variables 能力或已有 aggregate data。

这不是 Second Batch 内实现 Variable CRUD 的理由。

## 6. State model

### 6.1 Creation draft

新增互斥 session state，而不是多个 boolean：

```ts
type WorkflowCreationDraft =
  | { type: 'closed' }
  | {
      type: 'agent-action'
      context: CanvasContext
      placement: { x: number; y: number }
      values: AgentActionDraftValues
      submit: 'idle' | 'invalid' | 'submitting'
    }
  | {
      type: 'loop'
      context: { kind: 'root' }
      placement: { x: number; y: number }
      values: LoopDraftValues
      submit: 'idle' | 'invalid' | 'submitting'
    }
```

- draft、validation errors 和 staged placement 都是 UI-only；
- 不进入 WorkflowGraph、CanvasLayout 或 repository payload；
- Cancel/Escape 清理 draft，canonical document deep-equal；
- route change/dispose 必须清理 draft；
- 同时只能存在一个 creation draft。

### 6.2 Resource Browser session

```ts
interface ResourceBrowserSession {
  collapsed: boolean
  category: 'tools' | 'knowledge-spaces'
  query: string
  filter: 'all' | 'available'
  page: number
  pageSize: number
  requestSeq: number
}
```

- 全部属于 session；
- category/query/filter 变化时 page 回到 1；
- Tool query/page 在当前 aggregate 上本地派生；
- Knowledge Space query/page 通过 repository；
- 旧 request/已 abort request 不得覆盖当前 inventory；
- mode/focus/Loop 切换不复制 inventory 或 canonical config。

## 7. Agent Action creation

### 7.1 Draft fields

- Name：non-empty；
- Model identifier：non-empty trimmed string；
- Goal：首批使用 literal ValueSource；
- initial Knowledge Spaces：默认 empty；
- initial Tools：默认 empty。

资源可以在创建成功后通过统一 Resource Browser 绑定。Creation dialog 不复制完整资源浏览器。

### 7.2 Typed mapping

建立纯 mapper：

```text
AgentActionDraftValues
→ validateAgentActionDraft
→ AgentActionNode candidate
```

- candidate 使用 schema/runtime validation；
- ID 只在确认提交时生成；
- Cancel/invalid submit 不消耗持久化 identity；
- component 不直接构造或插入 graph node。

### 7.3 Atomic submission

一次确认必须通过一个 store/application action：

```text
validated node + placement
→ addWorkflowNodeAt(context, node, placement)
→ graph/layout candidate validation
→ one document replacement
→ one mutationSeq
```

成功后选择新节点并打开 Agent Action Inspector；失败保持 graph/layout 不变并展示稳定错误。

Agent Action 可以在 root 或 Loop child 创建；child path 继续使用既有 Loop application transaction。

## 8. Loop creation

### 8.1 Draft fields

- Name；
- positive integer Maximum turns；
- Exit Variable（来自当前真实 Agent Variables）；
- compatible operator；
- typed comparison value。

Loop 只允许在 root Canvas 创建；Loop child Palette、native payload、keyboard action 和 drop preflight 必须继续返回 `NESTED_LOOP_FORBIDDEN` 或既有稳定等价错误。

### 8.2 Deterministic body factory

纯 factory 一次性创建：

```text
LoopNode
└─ body
   ├─ graph: Loop Start → Loop End
   └─ layout: two placements + default viewport
```

要求：

- 所有 owned IDs 唯一；
- Loop Start/End immutable；
- body graph 和 layout 同时通过 canonical schema；
- factory 不读取 store、DOM、Vue Flow 或 API；
- 默认布局使用命名常量，不使用 Figma ID/坐标作为 identity；
- root node + root placement 通过一次 transaction 提交。

成功后选择新 Loop、打开 Loop Inspector；是否立即 inline expand 由明确产品 action决定，默认保持 collapsed，避免创建与导航耦合。

## 9. Resource Browser

### 9.1 Placement and information architecture

实现 Canvas 内的 collapsible horizontal Resource Browser：

```text
Workflow toolbar
Resource Browser: [Tools] [Knowledge Spaces] [Search] [Filter] [‹ 1/4 ›]
Canvas + Inspector
```

这不是 Figma 中包含 `Agent Variables / DSL Edit / Reusable Tools` 的未来全局资源 top-bar；本批只显示真实可用的 Tools 与 Knowledge Spaces 两类，避免不可用导航误导用户。

Flow mode 默认 collapsed；Configure mode 选择 Agent Action 时可以展开。用户手动状态在当前 session 内保留。Focus Mode 下不得遮挡 Canvas，可折叠为紧凑 header。

### 9.2 Inventory rules

Tools：

- 唯一来源为当前 `document.reusableTools`；
- name/kind 本地搜索；
- local compact pagination；
- 无完整 Tool CRUD 入口。

Knowledge Spaces：

- 唯一来源为 Workspace-scoped Web API；
- repository mapping + runtime validation；
- server query/page/pageSize；
- lifecycle/graph state决定是否 draggable；
- loading、empty、error 与 no-match 分开；
- 不把 network failure 显示为 empty。

Filter 只暴露当前数据/API真实支持的 `All` 与 `Available`。不显示不可工作的 Recent/Favorite/Built-in/Community。

### 9.3 Components

建议职责拆分：

```text
WorkflowResourceBrowser            # presentational host
├─ ResourceCategoryTabs
├─ ResourceSearch
├─ ResourceAvailabilityFilter
├─ ResourcePagination
└─ WorkflowResourceCard
```

Container/store 提供 typed inventory/session/actions；组件不 fetch、不写 store document、不决定最终 drop command。

### 9.4 Compact Agent Action presentation

Agent Action 在 Configure mode 中显示：

- Model / Goal summary；
- Knowledge Space zone；
- Toolbox zone；
- 前若干 chips；
- 超出显示 `+N more`；
- full list 仍在 Inspector；
- chip remove 使用 typed unbind action；
- node、Inspector、Resource Browser 只读取同一个 canonical config。

节点尺寸必须有上限，资源数量不能无限撑大 Canvas。Flow mode 保持 compact topology card。

## 10. DnD arbitration

### 10.1 One payload boundary

继续使用 runtime-validated canonical Odyssey drag payload；禁止 Resource Browser、Palette 和 Canvas 维护互不兼容的第二套 payload。

### 10.2 Required cross-matrix

| Payload | root pane | Loop pane | Tool zone | Knowledge zone |
| --- | --- | --- | --- | --- |
| Task/Branch template | create in Flow | create in Flow | reject | reject |
| Agent Action template | open draft in Flow | open draft in Flow | reject | reject |
| Loop template | open draft in root Flow | nested rejection | reject | reject |
| Tool resource | reject | reject | bind | cross-type reject |
| Knowledge Space resource | reject | reject | cross-type reject | bind |
| Agent/Pattern payload | reject | reject | reject | reject |

每个 cell 必须覆盖 click/keyboard path 或 browser drag path中适用的一项，关键交叉项必须有真实浏览器验证。

### 10.3 Feedback and atomicity

- valid：目标轻量高亮；
- invalid：blocked cursor/图标和稳定短文案，不显示大面积红框；
- duplicate：不 mutation，短暂强调已有 chip；
- unavailable：资源卡不可拖并说明原因；
- drop success/failure/Escape 后 interaction 回到 idle；
- valid nested zone 阻止 pane/parent 二次消费；
- rejection 发生在 command 前，禁止“先写入再回滚”。

## 11. Keyboard and accessibility

- Palette item 可聚焦；Enter/Space 打开对应 draft；
- dialog 使用语义标题、initial focus、focus trap 和 return focus；
- Escape 关闭 draft或 drag feedback，不误删 Canvas node；
- Resource category 使用 tabs/radio-group 等明确语义；
- search 有 label；pagination buttons 有页码语义；
- draggable card 同时提供等价的 click-to-bind path；
- drop zones 和 remove buttons 有具体资源类型/name 的 accessible label；
- valid/invalid 不只依赖颜色；
- Focus Mode 进入/退出继续恢复焦点。

## 12. Responsive behavior

### 12.1 1440×900

- Resource Browser 横向紧凑展示；
- Canvas、Palette、Inspector 层级清晰；
- Configure Agent Action 不遮挡关键 handles；
- inline Loop 的 root siblings 保持可见。

### 12.2 1024×900

- 不产生页面级水平溢出；
- Resource Browser 使用自身横向卡片滚动或分页，不撑宽页面；
- Inspector 保持可访问；
- Focus Mode 隐藏 App Shell 后充分利用 viewport；
- Canvas pan/zoom 与浏览器页面滚动不冲突。

## 15. Acceptance gate
