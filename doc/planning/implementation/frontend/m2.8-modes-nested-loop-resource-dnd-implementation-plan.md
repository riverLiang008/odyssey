# Odyssey M2.8 — Modes、Nested Loop 与 Resource DnD Arbitration 实施计划

> Status: Proposed — ready for review  
> Date: 2026-08-26  
> Milestone: M2.8  
> Depends on: M2.4、M2.6、M2.7 accepted  
> Primary Figma references: `Research Agent — Workflow Canvas` (`62:2`)、`Agent Workflow Canvas — Resource Configuration` (`98:2`)、`Agent Workflow Canvas — Focus Mode` (`166:2`)

## 1. Outcome

M2.8 将 M2.7 已验收的单层 editable Workflow Canvas 扩展为可组合的 Agent Workflow Editor：

```text
Flow / Configure mode
          +
Focus Mode
          +
parent Workflow / Loop body 独立 Canvas context
          +
workflow-node / Tool / Knowledge Space drag arbitration
```

本阶段的核心目标不是完成全部 Agent Builder 表单，而是证明最容易发生状态串扰的交互可以在同一页面稳定共存，并继续保持：

```text
Domain State ≠ Canvas View Model
Persisted State ≠ Temporary UI State
Parent Canvas Session ≠ Loop Child Canvas Session
Workflow Node Drag ≠ Resource Drag
```

M2.8 完成后，用户应能够：

1. 在 Flow 与 Configure 之间切换，且 graph/layout identity 不发生隐式变化；
2. 进入和退出 Focus Mode，恢复 viewport、selection 和 panel；
3. 从父 Workflow 显式进入一个 Loop body，编辑独立子画布后返回父画布；
4. 从真实资源数据中拖动 Tool 或 Knowledge Space，并只投放到 Agent Action 的兼容区域；
5. 在所有非法、重复、跨层 drop 中得到稳定反馈，且 domain state 保持不变；
6. 保存并刷新后恢复 Loop body graph/layout 与 Agent Action resource references。

## 2. Accepted constraints

### 2.1 Canonical ownership

- 一个 AgentWorkflow 拥有一个 top-level `WorkflowGraph + CanvasLayout`。
- Loop body 是 Loop node 内嵌的 owned `graph + layout`，不创建第二条 AgentWorkflow 记录。
- Loop body 允许 Agent Action、Task、Branch；禁止 nested Loop。
- Tool 不是 Workflow node。
- Agent Action 的 Tool 引用使用现有 `reusableToolIds`。
- Agent Action 的 Knowledge Space 引用使用现有 `knowledgeSpaceIds`。
- Agent Action node、side panel 和 resource zone 必须编辑同一份 node config。
- mode、Focus、selection、panel、active Canvas context 和 drag session 都是 UI-only state，不进入 repository payload。

### 2.2 No mock path

M2.8 不使用 fixture、硬编码资源、假 UUID 或仅存在于浏览器内的 mock library 组成产品路径。

- Tool inventory 只读取当前真实 Agent aggregate 的 `reusableTools`。
- Knowledge Space inventory 必须来自真实 Web API。
- 如果真实 API 尚未提供某类资源，UI 显示明确 empty/unavailable state；不得伪造资源完成拖放。
- 自动测试可以使用 deterministic fixtures 测纯函数和 component boundary，但真实浏览器验收必须使用 Web API 数据。

### 2.3 Existing data compatibility

- 不迁移或重排既有 top-level Workflow。
- 不更改已冻结的 Workflow/Loop JSON shape。
- 不持久化 Vue Flow node/edge、DOM identity 或临时 drag state。
- M2.5 read-only Preview 不复用 M2.8 editable child session，也不得出现新的 mutation affordance。

## 3. Scope

### 3.1 In scope

- 真正的 Flow / Configure mode semantics；
- Focus Mode 与焦点恢复；
- Loop body nested Canvas；
- parent/child graph、layout、viewport、selection、panel 隔离；
- Loop child node create/move/connect/delete；
- child graph+layout 原子 application transactions；
- nested Loop 的 palette exclusion、payload preflight 和稳定错误；
- collapsible Resource Browser shell；
- Tool / Knowledge Space category、name search、真实可用 filter、compact pagination；
- typed resource card drag；
- Agent Action 内两个独立 drop zones；
- bind/remove/duplicate/type mismatch commands；
- node/resource/agent payload 中央仲裁；
- Esc cancel、invalid feedback、compact resource summary；
- 保存、刷新、revision CAS 回归；
- 1024px 与 1440×900 响应式和真实浏览器交互验收。

- autosave debounce、完整 save race/conflict recovery（M2.9）；
- Workflow execution、publish、versioning；
- 为完成演示写入 seed/mock resource。

## 4. Entry blockers and backend contract

### 4.1 Current API audit

当前 Web API 已支持：

- load/save Agent Workflow aggregate；
- aggregate 内的 `variables` 与 `reusableTools`；
- revision CAS 保存；
- Agent Template list/load。

当前 HTTP router 未暴露 Workflow Editor 可使用的 Knowledge Space summary list。数据库表存在不等于前端可以安全读取。

### 4.2 Required minimum backend addition

Implementation-ready backend contract: [`m2.8-knowledge-space-inventory-api-requirement.md`](../backend/m2.8-knowledge-space-inventory-api-requirement.md).

Resource DnD 编码前至少冻结并提供：

```http
GET /api/v1/knowledge-spaces?query=&page=&pageSize=
```

最小 response 只包含当前 Workspace 可见的 summary：

```ts
interface KnowledgeSpaceSummaryPage {
  items: Array<{
    id: UUID
    name: string
    description: string | null
    updatedAt: string
  }>
  page: number
  pageSize: number
  total: number
}
```

要求：

- Current Workspace 由服务端 dependency 决定；
- stable ordering；
- strict DTO 与 canonical camelCase response；
- name search；description search 仅在后端已有可靠字段时启用；
- 不因 M2.8 添加无产品用途的 create/update/delete endpoints；
- frontend repository 必须 runtime validate response。

如果该 endpoint 在 Loop/mode work 完成时仍不可用：

- Modes、Focus、Loop 和 Tool-from-aggregate DnD 可以继续实施；
- Knowledge Space tab 保持真实 unavailable state；
- M2.8 不得宣称 resource acceptance 完整通过。

### 4.3 Tool inventory decision

M2.8 的 `Tools` category 指当前 Agent aggregate 中的 `reusableTools`，因为 Agent Action 的 canonical field 是 `reusableToolIds`。

- 不把 Tool Definition ID 或 Tool Template ID 直接写入 `reusableToolIds`。
- 没有 `reusableTools` 时显示真实 empty state。
- 创建/配置 reusable Tool 的完整产品路径留在后续资源里程碑。

## 5. Frozen interaction semantics

### 5.1 Flow mode

Flow mode 负责 topology editing：

- Palette 可创建当前已满足前置条件的 Workflow node；
- Canvas node 可移动；
- 可连接、选择和删除 graph element；
- Node inspector 可显示 contextual information；
- Resource Browser 默认折叠；
- resource binding target 不作为主要交互强调。

### 5.2 Configure mode

Configure mode 负责配置已有节点，不负责改变 topology：

- node/edge 保持同一 graph/layout projection；
- node 可选择，但不可移动、连接、删除或由 Palette 新建；
- 选中 Agent Action 时展示 resource zones 与配置 side panel；
- Resource Browser 可展开；
- resource bind/remove 通过 domain command 修改同一 Agent Action config；
- pan/zoom 继续可用；
- 切换模式保留 selection、viewport 和 panel；
- mode 本身不 mark dirty。

模式切换不得复制 graph/layout，也不得通过重建 document 丢失 object identity 或未保存修改。

### 5.3 Focus Mode

Focus Mode 是同一路由内的 layout state：

- 隐藏 primary navigation、全局 header/breadcrumb 和非必要外围说明；
- 保留 Canvas toolbar、mode control 和明确的 `Exit focus`；
- Palette/Resource Browser 根据进入前状态折叠，不能覆盖 Canvas；
- 已打开的 contextual panel 可以保留为可折叠 overlay/drawer；
- 进入前记录 focus return target；退出后恢复键盘焦点；
- viewport、selection、panel、active Canvas context 不改变；
- focus state 不进入 save payload。

### 5.4 Entering Loop body

进入 Loop 使用明确动作，不依赖难以发现的双击：

```text
select Loop
→ Inspector: Open Loop body
→ activeCanvasContext = loop-body(loopNodeId)
```

子画布顶部显示：

```text
Agent Workflow / {Loop name}
[Back to parent workflow]
```

返回父画布时恢复进入前的 parent viewport、selection 和 panel。再次进入同一个 Loop 时恢复该 Loop child 最近的 viewport/selection；这些 session values 不持久化，持久化 viewport 仍来自 `Loop.config.body.layout.viewport`。

### 5.5 Nested Loop rejection

- Loop 不出现在 child Palette；
- keyboard/click/native payload 均不能绕过；
- resource payload 不会被误解析为 Loop node；
- domain command 继续作为最终 authority；
- rejection 使用稳定 `NESTED_LOOP_FORBIDDEN` 或既有等价 code；
- rejected operation 不改变 parent Loop config、child graph 或 child layout。

## 6. State and adapter design

### 6.1 Session model

将现有 Workflow session 收敛为明确结构：

```ts
type CanvasContext =
  | { kind: 'root' }
  | { kind: 'loop-body'; loopNodeId: UUID }

interface CanvasSession {
  selectedNodeId: UUID | null
  selectedEdgeId: UUID | null
  panel: WorkflowPanel
}

interface WorkflowEditorSession {
  mode: 'flow' | 'configure'
  focusMode: boolean
  activeContext: CanvasContext
  root: CanvasSession
  loopBodies: Record<UUID, CanvasSession>
  interaction: WorkflowInteractionState
  resourceBrowser: ResourceBrowserSession
}
```

不得使用一个全局 `selectedNodeId` 同时解释 parent 和 child identity。

### 6.2 Namespaced Canvas adapter

建立显式 context input：

```ts
interface WorkflowCanvasContextInput {
  namespace: `agent:${UUID}` | `loop:${UUID}`
  graph: WorkflowGraph | LoopBodyGraph
  layout: CanvasLayout
  mode: WorkflowMode
}
```

要求：

- Vue Flow DOM/view IDs namespaced；
- root 与每个 child 使用独立 Vue Flow store ID；
- adapter 不缓存第二份 canonical graph/layout；
- child event 必须携带 `loopNodeId`，通过 parent Loop command boundary 提交；
- parent event 不扫描 selection 猜测 child context。

### 6.3 Loop child application transactions

新增纯 application helpers：

```text
createLoopBodyNodeAt
moveLoopBodyNodePlacement
removeLoopBodyNodeAndPlacement
connectLoopBodyNodes
removeLoopBodyEdge
updateLoopBodyViewport
```

每个操作：

1. 读取目标 Loop 的 child graph/layout；
2. 在候选副本上执行 M2.6 Loop child command；
3. 同时验证 child layout references；
4. 成功后通过一个 parent command 替换该 Loop body；
5. 失败时 parent document 完全不变；
6. 成功只增加一次 mutation sequence。

现有 graph-only `updateWorkflowLoopBody` 不扩展为接受任意完整 body；增加窄而明确的 transaction action。

## 7. Resource Browser and DnD design

### 7.1 Resource inventory port

新增 frontend port，不允许 component 直接 fetch：

```ts
interface WorkflowResourceRepository {
  listKnowledgeSpaces(input, options): Promise<RepositoryResult<KnowledgeSpaceSummaryPage>>
}
```

Tool cards 从已验证的 `document.reusableTools` 派生，不发额外请求。

Resource Browser session 保存：

- active category；
- query；
- supported filter；
- page；
- collapsed；
- loading/error state。

这些字段均不进入 Workflow save payload。

### 7.2 Supported search/filter/pagination

- Tool：当前 Agent 内按 name/key 搜索；本地 compact pagination；不展示 unsupported filter。
- Knowledge Space：使用 API query/page/pageSize；filter 只展示 API 实际支持项。
- category/query/filter 变化时 page 回到 1。
- request 使用 abort/request sequence，旧响应不得覆盖新 query。

### 7.3 Unified drag payload

沿用 canonical `OdysseyDragPayload`：

```ts
{ version: 1; kind: 'workflow-node-template'; nodeType: ... }
{ version: 1; kind: 'resource'; resourceType: 'tool' | 'knowledge-space'; resourceId: UUID }
{ version: 1; kind: 'agent-template'; templateId: UUID }
```

Workflow Palette 不再维护与中央 payload 语义冲突的第二套 drag state。序列化输入必须 runtime validate。

### 7.4 Interaction state

扩展互斥 union：

```ts
type WorkflowInteractionState =
  | { type: 'idle' }
  | { type: 'dragging-workflow-node'; nodeType: WorkflowPaletteNodeType }
  | { type: 'dragging-resource'; resourceType: ResourceType; resourceId: UUID }
  | { type: 'moving-canvas-node'; context: CanvasContext; nodeId: UUID }
  | { type: 'connecting'; context: CanvasContext; source: HandleRef }
```

- Esc 一律 transition 到 idle；
- 新 interaction 开始前结束旧 interaction；
- browser dragover 只更新 session feedback，不修改 domain；
- drop success/failure 后都清理 active state。

### 7.5 Drop target and preflight

定义明确 target：

```ts
type WorkflowDropTarget =
  | { kind: 'canvas-pane'; context: CanvasContext }
  | { kind: 'agent-action-tools'; context: CanvasContext; nodeId: UUID }
  | { kind: 'agent-action-knowledge-spaces'; context: CanvasContext; nodeId: UUID }
```

纯函数 `evaluateWorkflowDrop(payload, target, context)` 返回：

```ts
type WorkflowDropEvaluation =
  | { status: 'valid'; action: WorkflowDropAction }
  | { status: 'invalid' | 'duplicate' | 'unavailable'; reason: WorkflowDropErrorCode }
```

矩阵：

| Payload | Canvas pane | Tool zone | Knowledge zone |
| --- | --- | --- | --- |
| workflow node | create node（Flow only） | reject | reject |
| Tool resource | reject | bind | reject |
| Knowledge Space resource | reject | reject | bind |
| Agent/Pattern payload | reject | reject | reject |

Valid nested zone 必须 `preventDefault + stopPropagation`，确保 Canvas pane 不二次创建 node。Invalid zone 不修改 graph，并显示 blocked cursor/短暂稳定提示。

### 7.6 Resource domain commands

新增纯 command：

```text
bindAgentActionReusableTool
unbindAgentActionReusableTool
bindAgentActionKnowledgeSpace
unbindAgentActionKnowledgeSpace
```

Preconditions：

- node 存在且 type 为 `agent_action`；
- resource type 与 zone 匹配；
- Tool ID 存在于当前 Agent `reusableTools`；
- Knowledge Space ID 存在于当前已验证 inventory；
- ID 尚未绑定；
- parent/child context 明确；
- candidate graph/Loop body 通过 validation。

Duplicate 返回稳定 code，并保持数组顺序和 state 不变。

### 7.7 Compact Agent Action renderer

Agent Action node 显示：

- title/goal summary；
- Knowledge Spaces zone；
- Tools zone；
- configured chips 前若干项；
- 超出部分显示 `+N more`；
- valid drag 高亮；
- invalid drag 使用 cursor/icon，不使用大面积红框；
- 点击 chip 只选择/打开 panel，不触发 Canvas node drag。

Node 与 side panel 只从 canonical node config 和 inventory projection 读取 label；label 不写回 resource ID field。

## 8. Node creation prerequisites

### 8.1 Agent Action

不得为启用 Palette 写入假 model、goal 或 resource ID。

M2.8 可实现最小 create draft：

- name；
- non-empty model string；
- literal goal；
- empty `knowledgeSpaceIds`；
- empty `reusableToolIds`。

用户确认后一次性创建合法 node + placement。若本阶段不实现该 draft，Agent Action Palette 继续 disabled，但已有真实 Agent Action 的 resource DnD 仍可验收。

### 8.2 Loop

Loop schema 要求真实 `exitCondition.variableId`。Loop create draft 只能使用当前 Agent 已存在且兼容的 Variable：

- variable；
- operator/value；
- positive `maxTurns`；
- deterministic minimal Loop body；
- child layout containing Loop Start/End placements and viewport。

没有可用 Variable 时显示明确 prerequisite，不创建假 UUID。Nested Loop child Palette 永远不显示 Loop。

## 9. Implementation sequence

### Step 0 — Freeze API and current-state evidence

- 记录 OpenAPI 中现有 resource endpoints；
- 冻结 Knowledge Space summary endpoint 或记录 blocker；
- 确认真实 Agent aggregate 可返回 `reusableTools`；
- 为四类 API state 准备真实验收数据：empty、non-empty、network failure、response invalid；
- 不写 mock fallback。

Gate：Resource DnD 使用的数据来源和 unavailable 行为可被独立解释。

### Step 1 — Refactor session into Canvas contexts

- 引入 `CanvasContext` 与 per-context selection/panel；
- mode/focus 保持 UI-only；
- save projection regression test；
- 切换 Agent/route/dispose 清理所有 child session 和 request。

Gate：session 不进入 payload；root/child ID 即使相同也不串 selection。

### Step 2 — Implement Flow / Configure

- 启用 Configure button；
- 将 Canvas capabilities 作为 adapter input；
- Flow 与 Configure 共享 projection；
- Configure 禁止 topology mutations，允许 pan/zoom/select/config command；
- mode switch 保留 session。

Gate：切换前后 graph/layout deep-equal，mutationSeq 不变。

### Step 3 — Implement Focus Mode

- 增加 Focus/Exit control；
- AppShell 使用 page-scoped layout state，不创建新 route；
- resize 后更新 Vue Flow dimensions，不重置 viewport；
- restore selection/panel/focus target；
- Esc 优先取消 active drag/menu，其次按产品冻结规则退出 Focus。

Gate：进入/退出后 viewport、selection、panel 等价恢复。

### Step 4 — Build Loop child adapter context

- Loop inspector 增加 `Open Loop body`；
- namespaced Vue Flow store；
- child Palette 排除 Loop；
- child renderers 支持 Loop Start/End；
- child viewport/selection/panel 独立；
- Back 恢复 parent session。

Gate：parent 与两个不同 Loop child 的 viewport/selection 互不覆盖。

### Step 5 — Add Loop child transactions

- graph+layout create/remove/move/connect/update viewport；
- nested Loop preflight + domain rejection；
- one success = one parent document replacement + one mutationSeq；
- save/reload round-trip。

Gate：任何 rejected child operation 后整个 parent Agent document deep-equal。

### Step 6 — Add Resource Browser repository and UI

- collapsible browser；
- category/search/pagination；
- Tool inventory from aggregate；
- Knowledge Space API adapter；
- loading/empty/error/unavailable；
- stale request/abort protection。

Gate：页面刷新后资源来自 Web API/aggregate，不来自 component constant。

### Step 7 — Centralize DnD arbitration

- unified payload；
- interaction transition；
- pure target preflight matrix；
- valid/invalid/duplicate visuals；
- Esc cleanup；
- nested zone consumption。

Gate：resource drop 不创建 node；node drop 不绑定 resource；invalid state 不变。

### Step 8 — Bind resources through commands

- four bind/unbind commands；
- root and child Agent Action support；
- compact renderer summary；
- side panel synchronization；
- save/reload and revision conflict regression。

Gate：node/side panel/reload 三处 resource IDs 一致。

### Step 9 — Responsive, accessibility and hardening

- 1024px internal scrolling；
- 1440×900 visual hierarchy；
- Focus resize；
- keyboard mode/focus/Loop navigation；
- visible focus ring；
- screen-reader labels for drop zones and resource remove；
- console warning/error check。

### Step 10 — Completion report and acceptance handoff

- 记录 API/commit/environment；
- 生成 M2.8 acceptance checklist；
- 列出真实创建的 Journey/Agent/resource IDs；
- destructive cleanup 继续由用户确认；
- 明确 M2.9 handoff：autosave race/conflict/E2E hardening。

## 10. Test strategy

### 10.1 Pure domain tests

- bind/unbind Tool and Knowledge Space success；
- invalid node type；
- missing resource；
- type mismatch；
- duplicate；
- root and Loop child application；
- input immutability；
- candidate validation failure atomicity；
- nested Loop rejection；
- child graph+layout reference integrity。

### 10.2 State/session tests

- Flow/Configure preserves graph/layout and mutationSeq；
- Focus preserves/restores viewport/selection/panel；
- root/Loop A/Loop B session isolation；
- removed Loop prunes orphan child session；
- route change/dispose aborts inventory load and clears context；
- resource browser query race ignores stale response；
- UI-only state excluded from `toSaveInput()`。

### 10.3 Adapter/component tests

- root/child namespace uniqueness；
- Configure adapter disables topology mutations；
- child Palette excludes Loop；
- Tool/Knowledge drop-zone states；
- compact `+N more`；
- node and side panel reflect one config；
- valid child zone prevents pane double-consumption；
- Esc returns interaction to idle；
- unavailable API never renders fake cards。

### 10.4 DnD cross matrix

必须覆盖：

```text
workflow node × root pane
workflow node × child pane
workflow node × both resource zones
Tool × root/child pane
Tool × Tool/Knowledge zones
Knowledge Space × root/child pane
Knowledge Space × Tool/Knowledge zones
Agent/Pattern payload × all Workflow targets
duplicate × root/child Agent Action
```

### 10.5 Persistence and HTTP tests

- Knowledge Space list runtime validation；
- search/page query mapping；
- abort and stale response；
- save root resource references；
- save child resource references；
- save Loop child graph/layout/viewport；
- reload equivalence；
- revision conflict preserves local nested edits；
- no session/Vue Flow fields in request。

### 10.6 Real-browser acceptance

使用真实 Web API，不使用 mock：

1. Flow → Configure → Flow，拓扑和 viewport 不跳动；
2. selected node + open panel 进入/退出 Focus，状态恢复；
3. 打开 Loop child、创建 Task、移动、连接、保存、刷新；
4. 返回 parent 后 parent viewport/selection 恢复；
5. child 尝试 Loop payload被拒绝且文档不变；
6. Tool card 拖入 Tool zone，刷新后恢复；
7. Knowledge Space card拖入 Knowledge zone，刷新后恢复；
8. cross-type 与 duplicate drop 被拒绝；
9. resource drop 到 pane 不创建 node；
10. workflow node drop 到 resource zone 不绑定 resource；
11. valid nested resource drop 不穿透 parent/pane；
12. 1024px、1440×900 下 Resource Browser、Canvas、panel 可访问；
13. keyboard/Esc/focus restoration 可用；
14. console 无新增 warning/error。

## 11. Acceptance gate

M2.8 只有在以下条件全部满足时才可 PASS：

- lint、typecheck、tests、build 全绿；
- Flow/Configure 不复制或隐式修改 graph/layout；
- Focus Mode session 恢复通过；
- parent/Loop child adapter/session 完全隔离；
- child mutation graph+layout 原子提交；
- nested Loop 从 UI preflight 到 domain hard gate 均被拒绝；
- Tool/Knowledge Space 均来自真实 aggregate/API；
- node/resource/agent DnD cross matrix 全部通过；
- duplicate/invalid drop 后 canonical document 不变；
- root/child resource references save/reload 等价；
- M2.5 Preview 仍为真正 read-only；
- 1024px 和 1440×900 真实浏览器验收通过；
- 无 P0/P1 defect 和 console error。

如果 Knowledge Space API 未完成，则整个 M2.8 只能标记为 partial/blocked，不能以 Tool-only 或 fixture path 宣称完成。

## 12. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| parent/child 共用 Vue Flow store 导致 selection/viewport 串扰 | stable namespaced store ID；per-context session tests |
| Configure 只是换按钮颜色 | capability matrix 禁用 topology mutation；component/browser assertions |
| Focus resize 触发 fitView 丢 viewport | resize only；保存/恢复同一 viewport；禁止无条件 fitView |
| child graph 改了但 layout 部分失败 | graph+layout candidate transaction；一次 parent replacement |
| resource zone drop 穿透 pane | target preflight + valid zone stop propagation + cross-matrix test |
| duplicate 先写入再回滚 | pure preflight before command；immutable candidate |
| Tool Definition/Template ID 写入 reusableToolIds | Tool inventory only from `document.reusableTools` |
| API 缺失时偷偷使用 fixture | explicit unavailable state；browser acceptance inspects real responses |
| Resource Browser request race | AbortController + request sequence |
| Node 内资源过多破坏 Canvas | bounded chips + `+N more` + full list in panel |
| M2.8 意外扩大成完整资源 CRUD | enforce out-of-scope list and backend minimum endpoint only |

## 13. M2.9 handoff

M2.8 完成后，M2.9 复用以下稳定边界：

- root/child canonical application transaction；
- namespaced Canvas context；
- centralized InteractionState；
- resource repository and request sequencing；
- explicit mutation sequence；
- current manual save/revision CAS。

M2.9 再实现 debounce autosave、edit-during-save、out-of-order response、route disposal、retry 和完整 revision-conflict resolution，不在 M2.8 中提前写半套 autosave。
