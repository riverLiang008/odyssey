# Odyssey 开发进度：已完成与待办

> 本文保留 2026-10-23 的历史评估。当前进度请看 [2026-10-26 重新评估](./odyssey-progress-reassessment-2026-10-26.md)：原画布问题已整改，对象存储与知识库主链已补验，只读知识图谱已具备。

更新日期：2026-10-23

本轮已补做浏览器和数据库验收，结果见 [验收记录](./odyssey-acceptance-2026-10-23.md)。主要保存流程、自动测试与最终构建已通过，仍有 Flow 切换后节点移出视野、Loop 内 Branch 越界两个问题；真实上传和知识库绑定受 MinIO 环境限制，尚未完成。验收期间还新增了知识图谱实现，此文正文保留初次评估时的范围，新功能的完整浏览器验收需另行补充。

## 目前做到哪了？

Odyssey 的核心编辑功能已经搭起来了。现在可以创建 Journey、选择 Pattern、配置 Agent，再进入 Workflow 画布编排节点、设置变量和工具。修改能够自动保存，刷新后可以继续编辑。Knowledge Space 也已经支持创建、上传文件、查看和编辑 Markdown。

距离 V1 完成，还差三块主要工作：**工作流版本管理、知识图谱界面，以及最近几轮改动的实际操作验收。** 接下来应该先把这些补齐。

目前的产品重点是“把工作流配置好、保存好”。工作流实际运行、工具调用和知识检索还没有实现，原来的 V1 计划也没有包含执行引擎。

这次评估覆盖了仓库中的代码、测试和开发文档。这批开发成果随后已提交并推送到 `main`，提交号为 `b4ddb2f`。

## 已完成

### Journey 和 Agent 配置

- 可以创建、查看、修改和删除 Journey。
- 可以选择内建 Pattern，配置 Slot 和 Agent，复用或保存 Agent 模板。
- Pattern 的路由会同步到 Agent Workflow 的出口。Hub 关系支持调整方向；涉及删除已连接出口时，会先提示影响并要求确认。
- Journey 列表的搜索、筛选和排序还没有开放。

### Workflow 编辑器

- 已有 Start、End、Task、Agent Action、Branch 和 Loop 节点。
- 可以创建节点、连接和删除连线、移动节点、编辑配置。
- 已有连线和图结构校验，也支持 Flow / Configure 切换及 Focus Mode。
- Loop 容器、Branch 配置和 Workflow Preview 最近都有更新，代码和自动测试已有，但还需要在浏览器里逐项检查拖放、缩放、布局和显示效果。

### 保存、导入导出和 DSL

- 自动保存、失败重试、版本冲突处理和离开页面前的未保存提醒已经实现。
- Workflow 可以导出为 JSON，也可以校验并导入 JSON。
- DSL Edit 已能把画布转成文本，也能将文本修改应用回画布；支持格式化、错误定位和保留未应用的草稿。
- DSL 的浏览器测试目前使用内存数据。通过真实后端保存、刷新恢复和处理冲突的流程，还需要补验收。

### 变量和工具

- 可以管理 Agent 变量，配置五类内建工具，以及创建、编辑和复用工具。
- 已有引用检查，避免删除仍被使用的变量或工具。
- Task 中的工具步骤可以排序，Agent Action 可以绑定工具和 Knowledge Space。
- 这些功能目前用于保存配置，尚不能执行工具。模型列表和系统变量列表也还没有正式接口。

### Knowledge Space

- 可以创建、查看、修改、归档、恢复和删除 Knowledge Space。
- 已有文件树、文件上传、预览、Markdown 正文编辑，以及文件移动和删除。
- 可以导入图谱 Manifest，检查内容、预览变更，再保存文档摘要、标签、关系等数据。
- **知识图谱的可视化界面还没做完。** 当前页面只显示文档和关系数量，还不能浏览图谱、点击节点查看详情。

## 接下来要做什么？

### 第一批：把现有功能验收完

这些功能已经有代码，优先确认它们能在实际使用中稳定工作。

| 工作 | 做完的标准 |
| --- | --- |
| Loop 容器 | 拖入节点、移动、调整大小和连线都正常；保存或导入导出后，内部位置和尺寸不丢失 |
| Branch | 创建、修改条件和连接分支正常；浏览器中的外观与设计一致 |
| Workflow Preview | 保留实际画布的布局；大小合适，节点和连线不被裁切；只能查看，不能误操作 |
| DSL 接真实后端 | 修改并应用后能够保存，刷新后保留；发生保存冲突或离开页面时，草稿得到正确处理 |
| Knowledge 绑定 | 从真实 Knowledge Space 中选择资源，绑定到节点或工具；保存、刷新后引用正确 |
| 后端检查 | 跑完数据库测试，修复两处格式问题；让 CI 有可用的 PostgreSQL 环境和建表步骤 |

### 第二批：补齐 V1 缺少的功能

**1. 工作流版本管理**

现在的自动保存和 `Save now` 都是在更新当前草稿。还需要支持主动保存一个版本、查看历史版本，以及恢复到某个版本。JSON 备份已经可用，但版本历史仍需单独实现。

**2. 知识图谱界面**

把已有的图谱数据展示出来，支持平移、缩放、选中节点和查看文档详情。还要补上摘要、标签等信息的编辑，以及返回图谱后保留原来的浏览位置。

**3. 文件管理的剩余操作**

补文件夹重命名、移动和删除，文档重命名，以及上传进度、重试和取消。还要处理上传中断、数据库保存失败等情况，避免留下无法使用的文件或存储垃圾。子文件夹创建的后端已支持父目录参数，需要再确认页面操作是否完整。

**4. 准备可重复演示的案例**

通过正常页面操作创建完整案例，准备可以重新导入的数据和说明。完成一次从创建 Journey、配置 Workflow、绑定知识库，到保存和刷新恢复的完整演示，并检查键盘操作、不同窗口宽度和部署流程。

### 后续再完善

- Journey 搜索、筛选、排序，以及知识库分类管理。
- 正式的模型列表和系统变量列表。
- 更多 DSL 错误提示、独立 `.ody` 文件支持和大文档测试。
- 大图性能与浏览器自动化测试。
- 更新旧计划中的进度描述。目前有些文档仍写着早期状态，也有些待办实际上已经部分完成。

最初评估时，前端的 `pnpm check` 全部通过，包括代码检查、类型检查、93 项共享数据格式测试、544 项 Web 测试和生产构建。补验收后的 Web 回归为 546 项，另跑新增知识图谱的 6 项测试，均通过；最终生产构建也通过。真实浏览器发现的问题单独保留在验收记录中，没有用自动测试代替交互验收。

补验收时已修复 `tools/router.py`、`tests/test_workflow_domain.py` 的格式问题；后端 Ruff 代码检查和格式检查现已全部通过。

后端测试现已重新确认：沙箱外运行并使用本机实际数据库端口 55432 后，145 项测试通过。随后又从空库运行迁移，找出并修复一项测试对已有工具定义的依赖，空库上的 145 项测试也全部通过。CI 已补数据库和迁移配置，远端运行结果尚未验证。

## 如果下一步想让它真正跑起来

这需要另开执行功能的开发范围。当前的 Knowledge Q&A 只是案例设计，还不能实际完成检索和回答。

最小可运行案例需要补上：文档索引与检索、模型调用、运行时变量读写、问题输入和答案展示，以及失败处理。之后再考虑跨 Agent 调度、重试和运行记录。多人权限、Community 和发布功能也不在当前 V1 范围内。
