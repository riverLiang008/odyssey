## 结论

本轮已完成实际操作检查，但**不能判定全部通过**。DSL 保存、冲突恢复、JSON 备份恢复、Preview 和主要后端测试已经验证；仍有两个画布问题需要修复，真实文件上传和知识库绑定也没有验收完。自动测试与最终生产构建已通过，具体范围见“自动检查”。

检查过程中修复了三个界面问题：DSL 新建 Loop 时子节点跑到容器外、Preview 的 Loop 子节点尺寸与编辑器不一致，以及 Focus 模式隐藏保存状态。另修复了后端测试对开发数据的依赖和两处格式问题，并为 CI 补上 PostgreSQL 与迁移步骤。

## 已修复的问题

### 1. DSL 新建 Loop 时，子节点可能在容器外

原来所有新节点都沿横向排列，第三个 Loop 子节点就可能超过默认宽度。现在新建 Loop 的内部节点按两列放置，避开顶部标题，并按内容增加新容器的初始高度。已有节点位置仍保留。

补了新建、边界、输入不被修改和重新编译后布局保持的测试，并在浏览器重新创建 Loop 检查。

这项修复针对 DSL 的初始布局，不代表 Loop 内所有动态卡片的边界问题都已解决。

### 2. Preview 把 Loop 子节点展开成大卡片

编辑器中的 Loop 子节点是紧凑卡片，Preview 却全部展开，导致预览尺寸与实际画布不一致。现在 Preview 使用与编辑器相同的展开规则，并补了 Loop 预览测试。

### 3. Focus 模式看不到保存状态

Focus 样式隐藏了整组保存控件。现在这组控件固定显示在右下角，保留 Saved、Save now 和冲突处理入口。已补样式回归检查，并在浏览器确认显示和 Esc 退出正常。

### 4. 一项后端测试依赖已有开发数据

145 项测试在开发库通过，但在新建空库迁移后，有一项并发保存测试失败：它默认数据库里已有工具定义。现在测试自行准备所需定义，只清理本次创建的数据。修复后，空库上的 145 项测试全部通过。

### 5. 格式与 CI 环境

- 修复了 `tools/router.py`、`tests/test_workflow_domain.py` 的格式问题。
- CI 的 API job 增加 PostgreSQL 17 服务、数据库连接配置和 `alembic upgrade head`。
- 本机已验证空库迁移及完整测试；尚未推送本轮修改，因此没有新的 GitHub CI 运行结果。

## 仍未通过的问题

### A. 切到 Flow 后，节点可能移出当前视野

复现：在 Configure 模式平移到 Loop 所在区域，再点击 Flow。节点位置随显示模式改变，但视野没有相应调整，画布会看起来像空白。切回 Configure 能重新看到节点，数据没有丢失。

这会影响正常浏览，不能把 Flow / Configure 切换整项勾为通过。

![切到 Flow 后看不到当前节点](../../temp/acceptance-2026-10-23/flow-viewport-failure.png)

### B. Loop 内新建 Branch，卡片可能伸出容器

复现：选中 Loop 内节点，通过 Add Branch 创建一个包含布尔条件的 Branch。配置可以保存，但展开的 Branch 卡片下半部分超出 Loop 外框。

已有紧凑节点的拖动限制通过，不代表新建节点或动态变高后的卡片也一定在边界内。需要结合卡片实际尺寸处理创建、内容变化和容器缩小这些情况，再补浏览器回归。

![Loop 内 Branch 超出容器](../../temp/acceptance-2026-10-23/loop-branch-overflow.png)

## 受环境限制、没有完成的部分

真实文件上传，以及“上传文档 → 导入 Manifest → 在 Workflow 绑定可用知识库 → 保存刷新”没有完成。

本机只有 PostgreSQL，没有运行中的 MinIO，也没有缓存的 MinIO 镜像。通过项目配置的 Quay 地址下载时返回 unauthorized；尝试官方 Docker Hub 的同版本镜像也被拒绝。没有改账号、凭据或现有服务配置。

因此，本轮只确认知识库能创建、刷新，以及未索引时不能绑定。后端对象存储端口测试通过，不能替代真实 MinIO 上传验收。恢复可用的对象存储后，需要继续完成这条流程。
